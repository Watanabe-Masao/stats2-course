# 関係図の設計書

定義書（docs/relation-map.md）の決まりを、どの型・データ・画面で持つかを書く。教材は今、二項分布を中心に作っていて、全部の分類を一度に移すことはできない。そこで次の形にする。

- **分類ごとに移す。** 移し終えた分類から関係図に出す。
- **型は足すだけにする。** 移していない分類のデータは、今のまま読める（v1 の改訂）。
- **最初の見本は確率分布の分類（13個）。** この文書の 4 に、見本を概念ごとに書いた。ほかの分類を移すときは、4 と同じ形で表を作ってから原本を直す。

## 1. 型（knowledge-net の schema。v1 の改訂）

| 所 | 今（rev35） | 変えた後 |
| --- | --- | --- |
| 関係の種類 | 8種類 | 「種類」「材料」を足す |
| 対比の関係 | 違いは `description` | 比べる軸 `axis` を足す（任意。移した分類では build が必須にする） |
| 前提の関係 | premise が learning か mathematical | 今のまま。移した分類では learning だけ（学ぶ順） |
| まとまり | `course.groups`・`concept.group`（任意） | 今のまま（移した分類では build が必須にする） |

- 種類が増えると、今の画面は知らない種類のデータを読めない（型の enum で止まる）。そのため、**画面を先に**新しい種類が読めるようにし、公開してから、教材が新しい種類を書く。
- `x-revision` を1つ上げ、CHANGELOG に書く。relation-types.yaml に「種類」「材料」の定義・読み方・該当する例・該当しない例を、定義書の 3 から写す（S1 のときの記録。今の定義書 3 は書き方だけで、例の正本は製本 ⑤）。
- 種類・材料の `trace`（前提をさかのぼる）は true にする。学ぶ順の見方（今の経路）は、M4 で作り直すまで、前提と材料・種類をあわせてたどる。
- 特殊化・統合（0本）は型に残す。外すのは、全部の分類を移し終えて v2 にするときにまとめて行う。
- **v2 にするとき：** 製本への移行の計画書（docs/rulebook-migration-plan.md）の M2（設計）・M7（古いものを閉じる）に置き換えた（2026-11-08）。下は S1 のときの見込みの記録。
  - まとまりを必須にする。
  - 前提を学ぶ順だけにし、premise の欄を外す。
  - 特殊化・統合を外す。

## 2. 教材の原本（stats2-course）

### 移した印

shared.yaml に、移し終えた分類の一覧を置く。

```yaml
relation_map_ready: [確率分布]   # 関係図の決まりで書き終えた分類（docs/relation-map.md）
```

build は、この一覧に入った分類にだけ、次を**止める**（入っていない分類は今のまま）。

| 止めること | 理由 |
| --- | --- |
| まとまりのない概念 | 何の仲間かに答えられない |
| その分類の概念を to にした、premise が mathematical の前提 | 材料か学ぶ順に分け終えていない |
| 種類の親が2つ以上の概念 | 木が1つに決まらない |
| axis のない対比 | 何が違うかの軸が書かれていない |

**警告**にするのは、材料の輪だけ（どの分類も）。

### 関係をどの分類で移すか

型 v2 への移し方は #265（M5）で決める（2026-11-08）。下は v1 の relation_map_ready で移したときの決まり。

- 種類・材料：to（定義される側）の概念の分類で移す。
- 対比・変換・一般化・導出・応用：どちらかの概念の分類を先に移すときに、いっしょに見直す。
- 学ぶ順（前提 learning）：to の分類で移す。中身は変えない。

### ID と版

- 関係の ID は変えない・消さない。
  - 種類を変えるときは、`version` を1つ上げ、`description` を新しい意味に直す。
  - 向きが逆だったときは、from と to を入れ替えてよい（ID はそのまま）。
- 概念を分けるときは、元の ID を、今の定義の意味の側に残す。新しい意味の側に新しい ID を付ける。

## 3. 画面（knowledge-net）

### 関係図の決定の記録（#247）

画面の原則（knowledge-net の CLAUDE.md）は「なぜ」だけを書く。関係図でその原則をどの形にしたかは、ここに決定として書く（ほかの画面の決定は knowledge-net の docs/decisions.md）。前提が変われば見直してよいのは、こちら。下の「関係図（M3）」は形の細かい所で、ここの決定と食い違うときはここが先。

決定ごとに、決定・原則（番号）・前提・根拠・日付・見直す条件を書く。

#### 空いた所の1回のタップは1段戻す
- **決定**：帯が全部引っ込んでいれば戻す → 下の面が段2なら段1へ → 選んでいれば外す（上の帯も戻る）→ 帯を引っ込める。ダブルタップを待ってから
- **原則**：1・10
- **前提**：関係図のキャンバス。下の面（詳しくの面）と上の帯・下のタブがある
- **根拠**：渡辺さん 2026-11-07（iPhone）
- **見直す条件**：帯か面の段が増えたとき

#### 地図を指で動かすと帯を引っ込め、概念を選ぶと上の帯を引っ込める
- **決定**：地図を指で動かすと帯を全部引っ込める（Safari でページを送ると帯が引っ込むのと同じ）。概念を選ぶと上の帯だけ引っ込める。時間で自動には消さない。中身は画面の同じ所に残す
- **原則**：1・16
- **前提**：iPhone の Safari の高さで地図を広く取る
- **根拠**：渡辺さん 2026-11-07（A/B）
- **見直す条件**：広い画面（タブレット・PC）で使うとき

#### 浮かせた説明・一覧は、地図を動かすと消す
- **決定**：線の説明・印だけの所の一覧・概念の概要は、地図を指で動かす・2本指で触る・分類を替える・全画面に切り替えると消す
- **原則**：1（消えるのは指で動かしたとき）・11
- **前提**：浮かせた物は地図の上の場所を指している
- **根拠**：渡辺さん 2026-11-07「画面移動等で消えるように」
- **見直す条件**：浮かせた物を地図から離した所（面の中など）に出すようにしたとき

#### 線を押すと矢印の向きに引き直す。長押しは下見とメニュー
- **決定**：
  - 線（線の上の印）を押しても別の画面へ移らない。待たずに、その線を矢印の向きに引き直す：元の線を薄くして矢じりを隠し、ペン先の光る点が始まりから同じ速さで引く（破線は破線のまま）。引き終わると矢じりが矢の向きへ少し進みながら現れ、少し置いて元へ戻る。引いている間は両端の概念のカードを線の色の枠で囲む。押した瞬間に線を太くする。動きを減らす設定では引かず、着いた先の縁を灯すだけ。
  - 続けてもう一度押したらダブルタップとして引き直しを止め、まとまり（または分類の全体）へ寄る。
  - 長押しで、後ろをぼかして関係の下見（両端と「つまり」）とメニュー（2つの概念のページを開く・閉じる）を出す。離しても残し、後ろか「閉じる」で閉じる。
  - となり合う概念の間は、開いたときの倍率で 44px 以上にする（間の線も 44px で押せる）。
  - 解説・操作は全画面のページで開くので、前に選んだ形を覚えていても自動では開かない（押したときだけ）。
- **原則**：1・6・10・11・13
- **前提**：線を押す目的は向きを確かめること。押しただけで全画面のページへ移ると来た道を見失う
- **根拠**：渡辺さん 2026-11-07（見本 https://claude.ai/artifact/AWcf31bVKBy1viJxScKdrf：押す所は A「間を広げる」、押したときは「3+ 引き直す（改）」＋「概念カードに枠」、長押しは下見とメニュー）
- **見直す条件**：線から2つの概念のページを開く人が多く、長押しまで遠いと分かったとき

#### 全体の見え方は引いたときだけ。離れた矢印は印だけ。まとまりの説明は名前を押したとき
- **決定**：
  - 開いた直後は、概念の名前が読める倍率（幅に合わせる）。全体の見え方は、指で引いて名前が画面の上で 11px を割ったときだけ（前の「最初の画面は全体の見え方」をやめた）。
  - 全体の見え方では、語を薄くし、まとまりの名前と概念の数を大きく出す。まとまりの間は組ごとに1本の矢印。となりのまとまりへは動詞の言葉、離れたまとまりへ（枠の右の外を通る矢印）は種類の印だけにし、言葉は押したときに出す。
  - 矢印を押すと、後ろをぼかして組・操作・条件の文（note）を先に出し、メニューから2つの概念のページを開く。
  - まとまりの1文（説明）は枠に出しておかず、まとまりの名前を押したときに出す（どの倍率でも同じ）。
- **原則**：6・13・15・19
- **前提**：iPhone の幅。全体を収める倍率（0.5 ほど）では概念の名前が読めず、離れた矢印の言葉の入る幅もない
- **根拠**：渡辺さん 2026-11-08（見本 https://claude.ai/artifact/JiCFRFsjD4Yv3eWSKW2s8a で B・b、「先程の説明は項目名をタップするとモーダルで表示」）
- **見直す条件**：広い画面（タブレット・PC）で使うとき、まとまりの数が増えて全体をつかみにくいと分かったとき

#### 見てきた道は置かず、← の長押しでたどった道
- **決定**：
  - 「二項分布 › ポアソン分布 › 指数分布」のような見てきた道の帯は、画面に置かない（c）。
  - ← を押すと1つ前の概念へ戻る。← を長押しすると、後ろをぼかして「たどった道」のメニュー（新しい順に5つまで）を出し、選んだ概念へ戻る（iPhone の戻るボタンの長押しと同じ）。
  - 長押し中は、ほかの長押しと同じ手触り（沈んで光る。knowledge-net の docs/decisions.md「長押しの手触り」）。
- **原則**：10・13・15・19
- **前提**：たどった道を見たいのは、戻りたいときだけ。いつも出すと、面の高さか上の帯を使う（上の帯は語を選ぶと引っ込む）
- **根拠**：渡辺さん 2026-11-07（見本 https://claude.ai/artifact/8bSBMs2AaEpdqyWs1aW7yQ で c、「長押しでどこを辿ったかわかるモーダルを置けば解決」、長押し中の見せ方は見本 https://claude.ai/artifact/N4NgvkERR9KnRSJ5E9K5M4 で「3 沈んで光る」）
- **見直す条件**：戻る先を探して ← を何度も押す使い方が多いと分かったとき

#### 隠したら、数と出し方をその場に出す（前の原則 5）
- **決定**：
  - 量で畳んだ所は「+N」「ほかに N 種類」「このまとまりで使う概念 N ›」のように、隠した数と開き方を同じ所に出す。
  - ただし、寄ったときに面の下に隠れた相手には、縁の「↓ 名前」の札を置かない。隠れた相手は線の長押しで両端を浮かせて見る。
- **原則**：15・9・13
- **前提**：今の関係図（まとまりの枠と束ねた線）。原則から外したのは、この形を前提にした決まりだったため（渡辺さん 2026-11-07）
- **根拠**：#239 の UX レビュー。縁の札は渡辺さん 2026-11-07「隠れているチップは必要ない」
- **見直す条件**：関係図の形（まとまり・線の束ね方）を変えたとき

#### 詳しくの面は3つの段
- **決定**：段1＝名前の1行と右に概要・式・関係の札（長い名前は「…」）→ 段2＝つまりと選んだ札の中身 → フル＝全画面のふだんの形。つまみは1段上げ、空いた所は1段下げる。フルの ← と上のつまみは来た段へ戻す。上のつまみを下へ引くとページが指に付いて下がり、離すと面がその高さから段へ動く（少し引いただけなら上へ戻る）。別の概念を選んでも段2は保つ

#### 2つの概念を見るのは2つの概念のページだけ
- **決定**：関係のページと比較を1つにする。関係があれば関係の説明が先で、下に「並べて見る」。関係のない組も同じページ
- **原則**：4・8
- **前提**：関係の説明と比較が同じ2つの概念を扱う
- **根拠**：渡辺さん 2026-11-07（「まとめましょう」）
- **見直す条件**：3つ以上の概念を比べる必要が出たとき

### 関係図（M3）

2026-11-06 に試作 A（v1〜v61）を iPhone で触って決めた形（#235）に、同じ日の UX レビュー（#239。別のエージェントが実際に動かして確かめた）を取り込んだ。取り込み方は渡辺さんの方針（2026-11-06）：指摘を点で直すのではなく、指摘の裏の考え方を「画面の原則」（knowledge-net の CLAUDE.md）にし、その当て方としてここに書く。前の試作とモックからは、今の土台（束ねた線のキャンバス）の機能を良くする部品だけを持ってくる（土台は置き換えない）。試作で試してやめた形（自動配置の ELK、まとまりのタイルの段、歪めて見せる、円・3列の概念の地図、線を全部出す一覧）は、ここに書かない。

- **出す範囲：** 移した分類（`relation_map_ready` を公開の JSON に出す）だけを関係図で開く。移していない分類は、同じ形で概念を1つの枠に並べ、横の関係の線だけを出す。
- **段は3つ：**
  1. **遠く＝ライブラリ。** 柱ごとに分類の札を2×2で並べる（概念の印3つ＋「ほかの概念」の数、名前と「準備中」は札の下）。キャンバスの遠くの見え方とライブラリを同じものにし、2つ持たない。島の間に関係の札は置かない。札を押すと分類へ寄り、札の中の概念を押すとその概念を選んで寄る（ライブラリの札から関係図へ直に入る。見方の切り替えの奥に置かない）。分類を引いて離すと、ライブラリのその札が見える所へ戻り、札の形へ縮む動きで行き先を示す。引いている間（全体が入る倍率の 0.8 倍と 0.45 の小さい方より下）は、枠の角を丸めて薄くする予告を出す。
  2. **近く＝分類の関係図。** 1枚のキャンバスに分類の島を並べ、島の中にまとまりを学ぶ順に縦に積み、概念を3列に置く。分類を開くとまとまりまで一度に開く（まとまりは6個まで。1段ずつ開く段は置かない）。**全体の見え方：** 概念の名前が実寸 11px を割る所まで引くと、概念のカードを薄くし、各まとまりの枠に名前・1文・概念の数を大きく出す（地図アプリの、縮めると地名だけになる見え方。並びは動かさない）。まとまりの間の束ねた幹は、まとまりの組ごとに1本の矢印と動詞（「確率を保って回数を増やす」「平均を保って回数を増やす」「問いを入れ替える」。#240）にまとめる。矢印の言葉は教材の原本の「まとまりの間の関係」（#240）から出し、その矢印は裏付けの概念の関係（REL-…）を少なくとも1本指す（種類は指した関係から決め、原本には書かない）。矢印は「どう移るか」だけにし、1本の矢印に1つの意味（所属・材料・変換・対比を混ぜない。材料はまとまりの見出しの共通の印で示す）。矢印を開いた直後に、実際の分布の組（例：ポアソン分布 → 指数分布）・操作・成り立つ条件を最初に出し、まとまり全体が別のまとまりへ変わるようには見せない。言葉の「確率」は「1回の成功確率」、「平均」は「成功回数の平均」と開いた文で書く（渡辺さん 2026-11-07。#240）。この見え方になるのは指で引いたときだけで、ライブラリへ戻る境目は、この見え方よりさらに引いた所に置く（上の決定。2026-11-08）。
  3. **概念のページ**（全画面で読む）。
- **線：**
  - 直線と直角の曲がりだけ。入れ子なので、段を飛ばす線はできない。見せ方は A/B で B に決めた（2026-11-07）：幹の中の線の間 6px・角を丸める・十字にまたぐ所に切れ目。
  - まとまりの間を通る線は、隙間の中の1本の幹に束ね、遠くのまとまりへは右の1本の幹を通る。幹の中では線を少しずつ寄せて並べ、下に灰色の帯を敷く。
  - 線の上に種類の印（⇄ 変換・↗ 一般化・⇒ 導出・≠ 対比）を置く。画面でいつも同じ大きさ（直径 22px 以上。字ではなく SVG の線の印で描く）にし、ほかの印・概念・見出しと間をあけられる所だけに置く（取れない線には置かない。概念を選べば、相手の枠の色で分かる）。
  - 線はまとまりの見出しの帯をよけて通す（見出しの字を切らない）。
  - 色だけに頼らない：種類は色と形の印で示す。点線の枠は「定義がまだの概念」だけの意味にし、関係の種類には使わない。
- **概念を押したとき（4つの問いへの答え方）：**
  - **何とどう違い、どう移るか：** 押した概念の線だけを濃くし、ほかは薄くする。相手は枠を種類の色にし、関係のない概念は灰色にして少し小さく（0.93倍）、押した概念は少し大きく（1.08倍）する。並びと線は動かさない（歪めて見せることはしない）。
  - **寄り方：** 押した概念と相手と線のまとまりを、見える所（上の端から下の面の上まで）の真ん中に置き、全部入る倍率に寄せる（押した概念だけを真ん中にすると、相手が片側にあるとき反対側が空く。2026-11-07）。字が読める倍率より引かない。読めるとは、概念の名前が画面の上で 11px 以上のこと（カードの名前を 14px にし、下限を 0.8 倍にする）。入らないときは、まとまりの上の端を見える所の上の端にそろえ、押した概念から近い相手を見せる（それで押した概念が出るときだけ、押した概念を真ん中に）。面の段が替わったら、相手が面の下に隠れたときだけ寄り直す（面の動きと同じときに）。縁の「↓ 名前」の札は置かない（渡辺さん 2026-11-07「隠れているチップは必要ない」）。隠れた相手は、線の長押しで両端を浮かせて見る。
  - 横のつながりのない概念（確率変数など）は、寄らずにその場で選ぶだけにする。面には「この概念を材料にする概念 N ›」を出し、押すとその概念たちを強める（「何もない」に見せない）。
  - **何でできているか：** 概念を選んだときだけ、カードのすぐ下に材料の名前付きの札を1段出す（字は実寸 11px 以上。ほかのカードの上に重ねて出し、並びを押し下げない）。札を押すと、その材料を選んで寄る（掘り下げ）。ふだんのカードには材料の印を出さない（小さすぎて見分けられない）。まとまりの見出しの共通の材料と「このまとまりの中で使われる概念」も、同じ名前付きの札にする。種類の木の子が多い分類では、親のカードの下に「+6 種類」の行（44px）を置き、押すとまとまりの中で開く（開くときは下へだけ伸ばす）。
  - **何の仲間か：** まとまりの枠が答える。種類の親がある概念は、押したときにカードの上に親の札を出す。
  - **いつ成り立つか：** 地図には条件に名前の出る概念の点線の輪の印だけを置き、文は長押しの「のぞき見」と概念のページで読む。
  - 下の面（詳しくの面。島の地図・一覧と同じ面。渡辺さん 2026-11-07 に A/B で決めた）：
    - **段は3つ**：段1＝名前の1行と、右に概要・式・関係の札（名前が長いと「…」。地図が約 700px 残る）→ 段2＝つまり（3行）と、選んだ札の中身 → フル＝全画面のふだんの形（切り替えの帯・問い・つまり・図・定義…、下に「実験室で検証」）。段ごとに1つ増やす。しまう段は置かない。
    - つまみは1段上げる。引っ張ると近い段に止まる。段1で札を押すとその中身で段2、段2で別の札は中身を替え、選んでいる札をもう一度押すとフル。中身（つまり・図）を押すとフル。
    - フルの「←」と上のつまみ（押す・下へ引く）は、来た段へ戻す。別の概念を選んでも段2は保つ（「2段目を維持」）。
    - 種類ごとの数の札と「〇〇のページ」は置かない（選んだ＝説明をそのまま出す。渡辺さん 2026-11-07）。種類で絞るのは地図の下の札（下）。
    - 上へ引いた一覧は、種類ごとの行に「A → B」の小さな流れを並べる（選んだ概念は小さな「この概念」の札、相手はカード。向きは → ←）。相手を押すと地図でその概念を選んで寄る（地図のカードと同じ働き）。行は多い種類から3行まで、残りは「ほかに N 種類」で開く。概念のページの「関係」・関係のページの見出しも、同じ行の部品にする。
    - 上の段に、ほかの分類の札（種類の印＋分類の名前＋数＋›）。押すと、まずその分類の相手を面の中で見せ、「〇〇へ ›」でその分類を、相手を選んだ状態で開く。
    - 凡例は地図の下の1行の札にし、押すとその種類の線だけに絞る（いくつでも。概念を選んでも続く。右上の印の横の「絞り込み中」から外す）。
    - 見てきた道は面に置かない。← の長押しでたどった道（上の決定）。
    - 「前提を見る」の札：押すと、同じ分類の前提の概念へ薄い灰色の線を一時的に引いてその概念を強め、もう一度押すと消す（ふだんは前提の線を出さない）。ほかの分類の前提は線にせず、面の札にする。
    - ≠ で絞ったときは、比べる相手を面の中に横一列に並べ、押すとその2個を交互に強める。
    - 一覧から相手へ移るときは、面を低い段に戻してから寄る（寄る計算は、そのときの面の高さで）。
- **ほかの分類とのつながり：** 地図に線を出さない（島の外へ線を伸ばさない）。概念を選んだときは下の面の上の段の札（上）、何も選んでいないときは、まとまりの枠の下に「ほかの分類 N ›」を出す。概念のページ・実験室にも同じ札を置く。

- **操作：**
  - タップ：概念のカードなら選ぶ（指が 8px 動くまでは動かさない。押すと少し沈み、選んだカードは薄く主の色で塗る）。概念を選ぶと上の帯を引っ込める。地図の空いた所の1回は1段戻す：帯が全部引っ込んでいれば戻す → 下の面が段2なら段1へ → 選んでいれば外す（上の帯も戻る）→ 帯を引っ込める。地図を指で動かすと帯を全部引っ込める（Safari と同じ）。時間で自動に消すことはしない。帯が消えた状態でも、概念のカードは1回の押しで選ぶ。中身は画面の同じ所に残す（渡辺さん 2026-11-07）。
  - 帯（上の帯・下のタブ・下の面）の出入りの動きは1つ：その縁の方へ滑りながら薄く・濃くする（画面の原則 16）。
  - 線（や線の上の印）を押すと、待たずに矢印の向きに引き直す。長押しは後ろをぼかした下見とメニューで、メニューから2つの概念のページ（下）を開く（上の決定）。指の下のいちばん近い線を取る。
  - ダブルタップ：概念なら概念のページ（全部の段）、まとまりの中（概念の外）ならそのまとまりへ（1.3 倍以上寄る。どのまとまりかは押した位置で決める）、まとまりの外なら分類の全体へ寄る。待つ間は 0.2 秒（--dur）。1回目はすぐ沈んで選んだ見た目にし、面と寄る動きは待つ間のあと。線の上は待たずに引き直し、2回目で止めて寄る。
  - 長押し：概念なら選ばずに概要（名前・分類と状態・定義1文とページへ）。印だけの所（このまとまりで使う概念・見出しの共通の印）は押すと名前を出す。
  - 右上のボタン：概念を選んでいればその概念へ寄せ、選んでいなければ分類の全体を収める（全画面でも右上に同じ働き）。
  - パン：遊び（8px）を越えたら、地図を指の真下に付ける（越えるまでの分も捨てない）。離すと慣性で少し流れて止まる。速さは1本指の直近 50〜100ms の動きから求める。
  - ピンチ：指の真ん中を軸に拡大・縮小。離しても流さない（2本指の間は速さを取らない）。
  - 縁：越えると引くほど重くなり（越えた分を 0.55 倍などで縮める）、離すと縁ぴったりへ戻る（空きを残さない）。自動で寄っている途中に触ると止まる。
  - 「全体に戻す」（枠に収める形の印。全画面の印 ⤢ にしない）とダブルタップ（まとまりの外）は、分類の全体を見える所に収める。
  - 上の検索で概念を選ぶと、ページへ移らず、地図の上でその概念を選んで寄る。
  - 初めて開いたときだけ、「概念を押すと、つながる概念が色で光る」と1行の案内を出す。1回押したら二度と出さない（その端末のブラウザに覚える）。
  - 戻るは上の「‹ 前のページの名前」。積んだページを1つ戻り、戻った先は離れたときの状態（選んでいた概念・倍率・位置）のまま（URL に残す）。長押しでたどった道（上の決定）。相手へ移るときは、面を低い段に戻してから寄る。
  - 関係図から開く概念のページは、はじめから全画面の概念のページ（旧版の島の地図とシートの画面を経ない）。
  - 動きは、何が変わったかを伝えるフェード・寄せる動き・押すと沈む動き・札へ縮む動きだけ。1つの操作に動きは1つ。動きを減らす設定では止める。
- **上の帯：** 地図の上の見出し・検索・切り替えは1段に縮め、地図を広く取る。まとまりの間の空きは、線の上の印が入る広さまでつめる。
- **埋め込み（360×320）：** 地図はページの中に置かず、全画面のページとして開き、上に「‹ 分類の名前」を置く（ページに戻れなくならない）。下の面は低い段（1行）から始める。
- **一覧（読み上げと文で読む道）：** キャンバスは読み上げ（VoiceOver）で読みにくいので、同じ情報を文で読む一覧を残す。分類のページで「並び／つながり」を切り替える。行は印・名前・定義1文・›（ライブラリ・検索の結果・概念のページの一覧と同じ部品）。並びはキャンバスと同じ「まとまり → 学ぶ順」、行の右に種類の印でつながりの数。長押しはキャンバスと同じ「のぞき見」。行から「地図で見る」で、その概念を選んだキャンバスを開く。
  - 並び：まとまりごとの概念のカード。押すと、その行のすぐ下に「つながりの帯」（種類ごとの1行。左に種類、右に相手。向きは名前の前の → ←）が開く。長押しで「のぞき見」（定義・材料・成り立つ条件・つながりの数）。
  - つながり：種類ごとに1枚の小さな地図（向きのある関係は流れの深さで左から右、対比は相手の多い概念を左）。名前を押すとその概念を強める。
- **2つの概念のページ**（関係のページと比較を1つにした。渡辺さん 2026-11-07）：2つの概念を見るのはこのページだけ。関係があれば、関係の説明（つまり → 同じ所・違う所・だから → 解説・ラボ）が先で、その下に「並べて見る」（定義・原理・条件・反例を A と B の1行ずつ・共通の前提）を閉じて置く。関係のない組は「まだ関係が書かれていない」と、開いた「並べて見る」。入口は線の長押しのメニュー・関係の行・「…」の「ほかの概念と比べる」（探して選ぶだけ）。3つの比較は外した。前の `?cmp=A,B` の URL はこのページで開く。
- **概念のページ：**
  - 定義
  - 中の材料（掘り下げ。道筋を上に残す）
  - これを材料にする概念（一覧。その先を開ける）
  - 種類
  - 横のつながり：種類ごとの1行の流れ（超幾何分布 → 二項分布 → ポアソン分布）。相手を押すと、その1枚が「つまり」と比べる軸に替わる
  - 成り立つ条件・例と反例・よくある誤解
  - 下の帯は「実験してみる」を主に、「地図で見る」は文字だけのボタン
  - 見本は #228 のモック（分散の概念のページ）と、試作 A の二項分布のページ。

## 4. 見本：確率分布の分類（13個）

S3・S5b で原本に入れた決定の記録。判断の基準の正本は製本（① 概念・③ 成立条件・⑤ 関係）。ここの決定を製本に照らして v2 に移すのは #265（M5）の確率分布の見本で行う。ほかの分類の判断に、ここの例を基準として使わない。

定義書の規則で、確率分布の分類の13個を書いた。今の関係（REL-…）の行き先も並べる。この表が、ほかの分類を移すときの形になる。

### 対比（比べる軸と違いの1文）

| 組 | 比べる軸 | 違い |
| --- | --- | --- |
| 二項分布 ⇄ ポアソン分布 | 回数の上限と、分散と平均の関係 | 二項は上限 n があり分散が平均より小さい。ポアソンは上限がなく分散と平均が等しい |
| 二項分布 ⇄ 幾何分布 | 何を決めて、何を数えるか | 二項は回数を決めて成功を数える。幾何は成功1回を決めて回数を数える |
| 二項分布 ⇄ 超幾何分布 | 取り出し方 | 二項は戻す（確率が一定）。超幾何は戻さない（確率が変わる） |

### 成立条件の区分（S5b。#249 ①③。2026-11-08）

分布は確率関数・確率密度の式を基準の定義にし（`basis_formula`）、定義1文（生まれ方）は学習者向けの導入として残す（渡辺さん 2026-11-08）。要件は母数の範囲、仮定は「その分布に従う」ことを保証する条件。外れたときの説明は、要件が「この定義の分布として扱えない」、仮定が「使えるとは保証できない（偶然に一致することはある）」。

| 概念 | 要件 | 仮定（保証すること） |
| --- | --- | --- |
| 二項分布 | n は1以上の整数（n＝0 は扱わない）・0≦p≦1 | 回数が決まっている・2値・同じ p・独立（成功回数が B(n, p) に従う） |
| ポアソン分布 | λ＞0 | 独立に起きる・同時に2つ起きない・割合が一定（件数が Po(λ) に従う） |
| 幾何分布 | 0＜p≦1 | 独立・同じ p（初めて成功するまでの回数が従う） |
| 負の二項分布 | r は1以上の整数・0＜p≦1 | 独立・同じ p |
| 超幾何分布 | N・M・n は整数、0≦M≦N・1≦n≦N | 戻さずに取る・どの n 個の組も同じ確率 |
| 指数分布 | λ＞0 | 一定の割合で独立に起きる（待ち時間が従う） |
| 一様分布 | a＜b・区間の外の密度は0 | なし |
| 正規分布 | σ＞0 | なし |
| 確率分布・確率密度関数 | 確率が0以上・合計（面積）が1 | なし |
| 確率変数 | 試行の結果ごとに値が1つ決まる | なし |
| 共分散 | なし | 分散が有限（共分散が有限の値に定まる） |

関係の行（行き先が確率分布の概念）：

| 関係 | 区分 |
| --- | --- |
| 二項分布 → 正規分布（近似） | 目安：np≧5 かつ n(1−p)≧5（出典は shared.yaml の sources） |
| 二項分布 → ポアソン分布・超幾何分布 → 二項分布・t 分布 → 正規分布（極限） | 仮定（近づくことを保証する条件） |
| 標準化 → 正規分布・中心極限定理 → 正規分布・独立 → 共分散・ポアソン分布 → 指数分布 | 仮定 |

直したこと：

- 定義そのもの（正規分布の「確率密度が f(x) の式で表される」）は成立条件から外し、要件 σ＞0 にした。
- 確率変数の「各値の確率が0以上で、合計が1」は確率分布の要件と同じなので、確率変数からは外した（同じことを2か所に書かない）。「値の範囲が決まっている」は「試行の結果ごとに値が1つ決まる」に直した。
- 共分散の「分散が有限」は、共分散が存在するための十分条件なので要件でなく仮定にした。
- 二項分布 → 正規分布 の「境目を0.5ずらす（連続修正）」は手順なので成立条件から外した（REL-binom-cc の説明にある）。
- REL-binom-sampleprop の条件が、YAML の書き方で「B(n, p)」の読点のところで2行に割れていたのを直した。
- 実験室の反例（`breaks`）が照合する文（各回が独立・各回の成功確率 p が同じ）は変えていない。

残したこと（判断を待つもの）：

- 負の二項分布の式の記号 p の範囲は 0 を含む（0≦p≦1）。p＝0 では確率の合計が1にならないので、要件は 0＜p≦1 と書いた。式の記号の範囲を直すと式のレビューのやり直しになるので、別に直す。
- 中心極限定理の条件に「同じ分布に従う」がない（2級の範囲は独立同分布）。分類「標本分布・極限」を移すときに足す。
- 主張に使う概念（#249 ②）は、確率分布の分類にはない。
