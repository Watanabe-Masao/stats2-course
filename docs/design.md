# 全体設計：目的と要件（v0・2026-10-29）

「どう作るか・どう見せるか」の前に、**何のために、どんな設計が要るか**を決める。作り方（ラボの技術・画面・Notion の形）はこの要件から決め、ここと食い違ったらここを先に直す。計画（いつ作るか）は course-plan.md と #55。

## 1. 目的（渡辺さん、2026-10-29）

- **合格は前提**。そして合格は、理解する力（発展）と切り分ける力（創造）へ向かわせる**きっかけ**
- **自分の学習が中心**。ただし教材として**共有できる**形にする
- 知識ネットワークは、いずれ**別の科目**（小売の計数管理などのノート）とつなげて広げる
- **「分かった」＝合格レベル＝応用まで**（初学・復習・応用）。それより先（転用・発展・創造）は**好奇心を満たすコンテンツ**で、到達の基準を置かない

## 2. 2つの区域

| 区域 | 段階 | 何を約束するか |
| --- | --- | --- |
| 合格の区域 | 初学・復習・応用 | 範囲を漏れなく、分かったと言える証拠まで |
| 好奇心の区域 | 転用・発展・創造（と研究するラボ・ネットワークの散策） | 入口がいつでもあり、自由に深く行ける。正解・完了・点数で縛らない |

この2つは**同じ骨格（単元・概念）の上**にあり、行き来できる。

## 3. 要件

### R1 合格に必要な学習機会と理解確認を提供する（合格の区域）
目的は「統計検定2級の合格を目指す」。試験の結果はシステムが保証できないので、**保証するのは範囲の網羅と理解確認の仕組み**。
- 2級の範囲表のどの項目も、概念・教材・問題（初学〜応用）につながっている。漏れを build が数える
- 単元の「分かった」の運用上の判定：応用の問題が解けた＋復習の3回（翌日・1週間・1か月）で思い出せた。これは理解の証拠として扱い、合格や長期の定着を確約するものではない
- 本番の形式・時間で解く練習がある
- 間違えたとき、戻る先（前提の概念・よくある誤解・関係する教材）が出る

### R2 きっかけを置く（合格の区域 → 好奇心の区域）
- 合格の区域のどこにでも、好奇心の区域への入口がある。型は例えば：
  - **なぜ？**：この式はなぜこの形か（発展へ）
  - **本当に？**：いつでも成り立つか。反例・誤解をラボで崩す（発展へ）
  - **ほかでは？**：仕事・別の単元・別の科目では（転用・ネットワークへ）
  - **自分なら？**：自分のデータで問いを立てる（創造へ）
- 入口は押しつけない。開かなくても合格の区域は完結する

### R3 好奇心を満たす（好奇心の区域）
- 答えの決まらない問いを、答えの決まらないまま扱える（予想→照合にしない。「1つの考え方の例」を置く）
- ラボは**研究の道具**：条件を変える・反例を探す・つながりを確かめる。理論値・近似値・シミュレーション値を区別し、条件を再現できる
- ネットワークは**散策の地図**：概念から前提・つながり・別の科目へたどれる
- 記録は任意（研究ノートとして残したいときだけ）。到達や点数にしない

### R4 自分の学習と、共有を分ける
- 教材（原本・公開物）に個人のデータを入れない。個人の記録は ID だけを指す
- 個人の記録を外しても、教材として使える（配布先の設定：personal_root が空）
- 記録が教材の書き直しで壊れない（ID を変えない）

### R5 科目をまたいで広げる（知識ネットワーク）
- ネットワークは教材に依らない（knowledge-net）。教材だけでなく**ノート**（単元・段階のない知識のまとまり）も載せられる
- 科目をまたぐ線を引ける（例：小売の発注量 →「応用」← 期待値・分散）
- 別の科目の概念がまだなくても、線は「未接続」として残る（今ある決まり）

### R6 正しさを確かめられる
- 数は検算式で確かめる（今ある）。反例は「何を、どの数で否定するか」まで確かめる
- 観察（シミュレーション）と証明、近似と厳密を混ぜない

## 4. 要件から決まる役割

| 部品 | 合格の区域での役割 | 好奇心の区域での役割 |
| --- | --- | --- |
| 問題 | 分かった証拠を作る（照合） | 問いを立てるきっかけ（評価しない） |
| ラボ | 予想→照合で意味をつかむ・問題を確かめる | 研究の道具（反例・条件・つながり） |
| 知識ネットワーク | 戻る先（前提・誤解）を示す | 散策の地図・別の科目への橋 |
| 個人記録 | 到達と復習の期日を決める | 研究ノート（任意） |

## 5. 決まったこと（渡辺さん、2026-10-29）

- **D1 創造の観点**：「切り分け」「解釈」「前提の吟味」「別の可能性の探索」などの観点は、学習者が任意に使う**自分で振り返るための補助**として残す。到達の基準・点数・完了の条件には使わない。すべての探究で振り返りを求めない
- **D2 好奇心の区域の記録**（形は保留）：**研究ノート**を設ける。記録・保存・振り返りは任意。未完成の問い・結論のない記録・途中で考えが変わった記録も有効。項目は内容（保存するときだけ必須）と、任意のタイトル・関連する概念・仮説・実験の条件（ラボ・場面・値・乱数のシード）・観察と発見・まだ分からない問い・関連する資料。ラボの今の状態をそのまま添付できる
- **D3 別の科目**（形は保留）：教材と**知識ノート**は別の型にする。教材は単元・段階に属し、知識ノートはそれを求めない。両者は共通の概念 ID と参照の仕組みで知識ネットワークにつながる。公開の範囲と個人の情報は教材から分ける
- **D4 好奇心への入口**：「なぜ？」（仕組み・導出・理由）「本当に？」（前提・反例・限界）「ほかでは？」（別の分野・実務・概念）「自分なら？」（自分の問い・実験）の4つを採用する。型は足せるタグとして扱い、1つの入口に複数付けてよい。入口を開くことは合格の区域の進み具合・完了の条件に含めない

### 補足の原則
- 好奇心の区域では、到達・完了・点数を学習者に求めない
- 2つの区域は、知識の基盤（概念・ネットワーク・数理エンジン）を共有し、学習の評価を分ける
- 実験の結果を残すときは、再現に要る条件を一緒に残す

### 区域ごとの約束

| 合格の区域 | 好奇心の区域 |
| --- | --- |
| 正答・理解・再現を確かめる | 問い・考え・発見を振り返る |
| 到達の条件がある | 到達の条件を置かない |
| 復習の期日を管理する | 自分から何度でも戻れる |
| 進み具合を出す | 探究の跡を出せる |

### 2つの「ノート」を混ぜない（保留：ノートの話はいったん離れる。2026-10-29）
| | 研究ノート（D2） | 知識ノート（D3） |
| --- | --- | --- |
| 何か | 自分の探究の記録 | 別の科目などの知識のまとまり（小売の計数管理など） |
| 置き場所 | 個人の記録（公開しない） | 公開できる知識（ネットワークに載る） |
| 型 | 個人の記録の型 | knowledge-net の型（教材と並ぶ別の型） |

研究ノートで育った考えを知識ノートに書き起こすことはできるが、自動ではつなげない（個人の記録を公開物に入れない）。

## 7. 単元の骨格を固める（タブと節）

単元ページの6つのタブと節を、先に固める。問題・ラボ・ネットワーク・記録は、この節に「何を置くか」として決める。

### 7.1 タブと区域・きっかけ

| タブ | 区域 | きっかけの型 |
| --- | --- | --- |
| 🌱 初学・🔁 復習・🎯 応用 | 合格 | （入口を置く側） |
| 🔀 転用 | 好奇心 | ほかでは？ |
| 🔭 発展 | 好奇心 | なぜ？・本当に？ |
| 💡 創造 | 好奇心 | 自分なら？ |

好奇心の区域は、新しく作るものではなく**転用・発展・創造のタブそのもの**。合格の区域の節に置く入口が、そこへつながる。

### 7.2 初学（知る・理解する）

| 節 | 役割 | 置くもの・つながり |
| --- | --- | --- |
| 入口の問い | できるようになることを問いで見せる（答えない） | 仕事の場面の問い。創造の課題で回収（自分なら？） |
| 前提チェック | 足りない前提を見つける | 3問。戻る先は**概念の前提関係から生成**（今は手書き） |
| 意味をつかむ | 概念を場面の言葉で | 概念の定義を参照＋概念図。場面の例は単元に書く |
| 式の構造 | 記号と役割 | **分解の木（7.7）から生成**。単元は「場面での意味」の列だけ書く。入口：なぜ？（→発展） |
| 例題 | 補助を減らして手順を身に付ける | 図かラボ（今の決まり） |
| 実験 | 予想して確かめる | 場面（照合する） |
| 自力で確かめる | 初学の証拠 | 問題（初学・確かめる対象付き） |
| 振り返り | 自分の言葉で言う | 到達の記録（セルの証拠） |

### 7.3 復習（定着させる）

| 節 | 役割 | 置くもの・つながり |
| --- | --- | --- |
| 翌日・約1週間後・約1か月後 | 間をあけて思い出す | 問題（復習）。期日は個人の記録から。1か月後は**概念で選んだ他の単元の問題**と混ぜる |
| 言葉にする練習 | 説明の型で言う | 問題（🗣️） |
| 図を再現する | 概念図を手本に描く | 概念図 |
| 式の早見 | 式の一覧 | **概念の式から生成** |
| さらに解く | 量をこなす | 問題集の並べ方（旧版の問題集の置き換え） |

### 7.4 応用（条件に合わせて使う）＝単元の「分かった」

| 節 | 役割 | 置くもの・つながり |
| --- | --- | --- |
| 判断の手順 | どれを使うかを決める手順 | 本文 |
| 問題 | **単元の「分かった」の証拠** | 問題（応用）。誤答 → 誤解 |
| 使えない例と比べる | 成立条件と反例 | **概念の条件・反例・誤解から**＋場面（崩す・照合）。入口：本当に？（→発展） |
| この先で使う | 先の単元へ | **概念の関係から生成**（used_by）。入口：ほかでは？（→転用・ネットワーク） |

### 7.5 転用・発展・創造（好奇心）

| タブ | 節 | 置くもの |
| --- | --- | --- |
| 転用 | 同じ構造の場面 → 構造を見る → 転用の問題 → 仕事の場面 → 転用チェック | 関係「応用」。場面（比べる） |
| 発展 | 使うラボ → 発展1〜4 | 導出・前提が崩れると。場面（崩す・比べる・調べる。予想なし） |
| 創造 | 課題 → 検証に使う → 振り返りの観点（D1）→ ChatGPT に批評を頼む | 場面（調べる）。観点は任意 |

### 7.6 骨格から分かること
1. **節の半分は知識のデータの「見え方」**：前提チェックの戻る先・式の構造・式の早見・使えない例・この先で使う。概念と関係に1回書き、単元の節は生成する（同じことを2か所に書かない）。単元に書くのは場面の例と問い
2. **「分かった」の証拠は3つの節**：初学「自力で確かめる」・復習の3回・応用「問題」
3. **きっかけの入口は合格の区域の4つの節**：入口の問い（自分なら？）・式の構造（なぜ？）・使えない例と比べる（本当に？）・この先で使う（ほかでは？）
4. **単元の外の骨格も要る**：本番形式・他の単元と混ぜた問題・領域のまとめは1つの単元に収まらない。単元の上に「領域（9）」と「全体」の段を置く

### 7.7 式の構造＝分解の木（2026-10-29）

小売の「売上＝客数×客単価、客単価＝一品単価×買上点数」と同じく、統計の式も**記号が別の式に開く木**になっている。

| 段 | 式 | 教える単元 |
| --- | --- | --- |
| t 値 | （標本平均−仮の平均）÷ 標準誤差 | U25 |
| 標準誤差 | 標準偏差 ÷ √n | U20 |
| 標準偏差 | √（偏差の2乗の和 ÷（n−1）） | U07 |
| 平均 | 合計 ÷ n | U06 |

- **式は木の形のデータで持ち、TeX はそこから作る**。記号は概念の ID を指す（記号の字面ではなく概念で区別する。σ と s など）
- 単元の「式の構造」・式の早見・ネットワーク・ラボが**同じ木を読む**。記号を押すと一段ずつ開く（#64 の数式の逐次展開）
- 木の「使われている先」が「この先で使う」とネットワークの線になる。記号 → 概念は関係「前提（数学的）」として出す（新しい種類は要らない）
- いちばん下の記号は「出どころ」を持つ（データはどう生まれたか）
- ラボの問いの型に「分解する」：下の段を動かし、上の値がどう動くか・どの要素が効いたかを見る（小売の要因分解と同じ）
- 参考：粗利管理の FormulaNode 計算ツリー（記号の辞書・式の木・その場で展開・使われている先・構成図との連動・逆算のスライダー）。統計には Σ・√・累乗・関数（Φ など）と、データの集まりを葉に持つ形を足す
- 小売の計数管理の式も同じ型で書ける（R5）
- 置き場所（#71 で決定）：式のデータ＝教材の原本、式の木の型＝knowledge-net、計算・展開・表示（React＋TypeScript＋KaTeX）＝math-lab の最初の部品。データベースのサーバーは置かない（YAML → build が検査 → JSON）。TeX と記号の表を作る処理は math-lab に1つだけ置き、教材の build はそのコマンドを呼ぶ

## 8. 構造（合格の区域を軸に、1つのコンテンツにする）

### 8.1 5つの層

| 層 | 中身 | 今 |
| --- | --- | --- |
| 範囲 | 公式2級範囲表の項目（何が出題されるか） | **データになっていない**（本文に「範囲表No.1」と書いてあるだけ） |
| 骨格 | 単元×段階のセル（33×6） | ある（ゴールの文・できた証拠） |
| 知識 | 概念・関係・導出。命題・誤解・反例は概念の中 | 概念 8/114 |
| 活動 | 本文の設問・問題・ラボの場面・図 | 問題 537・場面 737 |
| 道筋と記録 | 判定・戻る先・復習の期日・記録 | 個人の記録の DB 3つ |

### 8.2 層をつなぐ線（これが「1つのコンテンツ」の正体）

| 線 | 意味 | 今 |
| --- | --- | --- |
| 範囲 → 概念 | 出題される | なし |
| 単元 → 概念 | 教える | unit.yaml の terms（189 か所） |
| 問題 → 概念・関係・誤解 | 確かめる | 0/537 |
| 場面 → 概念・関係・命題・誤解 | 確かめる・調べる | 概念・関係からの参照（#62）だけ |
| 概念 → 概念 | 関係（8種類） | 10 |
| 単元 → 単元 | 前提 | 手書きだけ（概念の関係から導いて照らし合わせる） |
| 記録 → 問題・場面・セル | ID で指す | 問題 ID・単元×段階 |

**活動（問題・場面）は「確かめる対象（知識）」に属し、骨格のセルに「置かれる」**。置かれる場所が変わっても、何を確かめるかは変わらない。

### 8.3 設問・問題の在り方
- 合格の区域の問題は照合できる（答え・checks）。形式（選ぶ・埋める・書く）と、誤答が当たる誤解を持つ
- 問題集は並べ方：置き場所（単元ページ）・確かめる対象（概念別）・誤解別・本番形式・混ぜた問題・自分の復習
- 判定は2つの単位で出す：**セル**（その単元の応用が解け、復習3回で思い出せた）と**概念**（その概念を確かめる問題の結果。単元をまたいで集まる）
- 戻る先は線をたどって出す：問題 → 確かめる概念 → その前提の概念 → それを教える単元の初学、と誤答の誤解

### 8.4 ラボの在り方：場面は「問いの型 × 確かめる対象」で決まり、開く文脈には属さない

| 問いの型 | 何をするか | 区域 |
| --- | --- | --- |
| 照合する | 予想 → 結果 | 合格 |
| 法則を見つける | 条件を変えて予想を重ね、式で説明 | 合格（応用） |
| 崩す | 命題の反例・誤解を数で崩す | 合格（照合）・好奇心（反例を探す） |
| 比べる | 2つの概念・近似と厳密・A/B | 好奇心（応用でも可） |
| 調べる | 予想なし。条件・結果・説明を自分で残す | 好奇心 |
| 解説する（2026-10-30・#90） | 解説付き再生。説明に沿って変化を見て、そのあと自分で触る。答えを見せる | 合格・好奇心（定義の説明・つながり） |

**「ラボで解説」と「ラボで確かめる」を分ける**（渡辺さん 2026-10-30）：解説は答えを見せ、確かめるは自分で出して照らし合わせる。ボタンは「▶ ラボで解説」「🧪 ラボで確かめる」。解説を先、確かめるを後に並べる。原本には区別を書かず、版に tour があれば解説と build が判定する。
- 使い所は**定義の説明**（概念がどう組み立てられているか）と**つながり**（関係の変換・対比・導出）。単元では初学「式の構造を読む」（定義）と発展「ほかでは？」（つながり）
- 同じページで予想させる数を、解説で先に見せない（解説は組み立て方を見せ、予想の版とは別の数・場面にする）
- 問題の答えの中・創造には置かない。1つの概念・関係に解説は1つ。作るときは段ごとの静止図も作る（Notion・印刷の代わり）

**つながりは「つまりどういうこと？」に手が届くようにする**（渡辺さん 2026-10-30・#95）：関係は文だけで終わらせない。種類ごとに付けるもの：

| 種類 | つまり（gist） | 図 | ラボ |
| --- | --- | --- | --- |
| 変換・対比・導出 | 必須 | 必須（段ごとの静止図） | 解説（tour）＋確かめる |
| 一般化 | 必須 | 必須（特別な場合を重ねる） | 確かめる |
| 応用 | 任意 | 任意 | 確かめる（問題の版） |
| 前提 | 任意 | なし | なし（前提をさかのぼるでたどる） |

「つまり」は説明・図・ラボより先に出し、関係から開く解説の最後の段にもなる。

開く文脈：単元の節・問題の答え・概念・関係・誤解・きっかけ（なぜ？本当に？…）・自分の復習。
**「問題にリンクしたラボ」は「照合する × 問題の答えという文脈」の1つのます目にすぎない**。場面は1か所に書き、どの文脈からも同じ起動で開く。

### 8.5 知識ネットワークの在り方：単元をつなぐのは概念
- 1つの概念は複数の単元に出る（例：期待値は U06・U13・U14・U15・U27 の terms にある）
- 単元の前後は、概念の前提関係から導ける。手書きの prereq と照らし合わせ、違いを build が出す
- ネットワークは「すべての活動への索引」：どの概念からも、教える単元・確かめる問題・場面・誤解へたどれる

### 8.6 体系的に学ぶ流れ
範囲 → 道順（セル）→ 問題・場面 → 判定（セル・概念）→ 戻る先・復習の期日 → きっかけ（好奇心の区域へ、任意）

### 8.7 例：期待値（TERM-expect）
- 範囲：範囲表の「確率変数・期待値・分散」の項目（データ化してから ID を付ける）
- 教える：U13 の初学（意味・式の構造・例題）。U14・U15 で二項・ポアソンの期待値として再び出る
- 確かめる：Q-U13-001〜（初学）、Q-U13-020〜（応用）→ 対象に TERM-expect を付ける
- 場面：LAB-expect（照合する：期待値が重心）、反例・誤解の場面（崩す：期待値＝いちばん出やすい値ではない）
- 線：期待値 → 分散（前提）、導出 DER-binom-moments の前提
- 記録：Q-U13-020 の正誤と誤解 → 概念「期待値」の判定 → 戻る先は U13 の初学「意味をつかむ」

### 8.8 足りないもの（合格の区域の土台）
1. **範囲表のデータ化**（項目と ID。R1 の起点）
2. 問題 → 確かめる対象（0/537）
3. 誤答 → 誤解（選ぶ形式の 33 問から）
4. 場面 → 確かめる対象と問いの型（737 場面）
5. 単元の前提を概念から導く検査
