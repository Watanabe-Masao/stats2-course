# 全体設計：目的と要件（v0・2026-10-29）

「どう作るか・どう見せるか」の前に、**何のために、どんな設計が要るか**を決める。作り方（ラボの技術・画面・Notion の形）はこの要件から決め、ここと食い違ったらここを先に直す。計画（いつ作るか）は course-plan.md と #55。

## 1. 目的（渡辺さん、2026-10-29）

- **合格は前提**。そして合格は、理解する力（発展）と切り分ける力（創造）へ向かわせる**きっかけ**
- **自分の学習が中心**。ただし教材として**共有できる**形にする
- 知識ネットワークは、いずれ**別の科目**（小売の計数管理などのノート）とつなげて広げる
- **「分かった」＝合格レベル＝応用まで**（初学・復習・応用）。それより先（転用・発展・創造）は**好奇心を満たすコンテンツ**で、到達の基準を置かない

## 2. 2つの区域

| 区域 | 段階 | 何を約束するか |
| --- | --- | --- |
| 合格の区域 | 初学・復習・応用 | 範囲を漏れなく、分かったと言える証拠まで |
| 好奇心の区域 | 転用・発展・創造（と研究するラボ・ネットワークの散策） | 入口がいつでもあり、自由に深く行ける。正解・完了・点数で縛らない |

この2つは**同じ骨格（単元・概念）の上**にあり、行き来できる。

## 3. 要件

### R1 合格に必要な学習機会と理解確認を提供する（合格の区域）
目的は「統計検定2級の合格を目指す」。試験の結果はシステムが保証できないので、**保証するのは範囲の網羅と理解確認の仕組み**。
- 2級の範囲表のどの項目も、概念・教材・問題（初学〜応用）につながっている。漏れを build が数える
- 単元の「分かった」の運用上の判定：応用の問題が解けた＋復習の3回（翌日・1週間・1か月）で思い出せた。これは理解の証拠として扱い、合格や長期の定着を確約するものではない
- 本番の形式・時間で解く練習がある
- 間違えたとき、戻る先（前提の概念・よくある誤解・関係する教材）が出る

### R2 きっかけを置く（合格の区域 → 好奇心の区域）
- 合格の区域のどこにでも、好奇心の区域への入口がある。型は例えば：
  - **なぜ？**：この式はなぜこの形か（発展へ）
  - **本当に？**：いつでも成り立つか。反例・誤解をラボで崩す（発展へ）
  - **ほかでは？**：仕事・別の単元・別の科目では（転用・ネットワークへ）
  - **自分なら？**：自分のデータで問いを立てる（創造へ）
- 入口は押しつけない。開かなくても合格の区域は完結する

### R3 好奇心を満たす（好奇心の区域）
- 答えの決まらない問いを、答えの決まらないまま扱える（予想→照合にしない。「1つの考え方の例」を置く）
- ラボは**研究の道具**：条件を変える・反例を探す・つながりを確かめる。理論値・近似値・シミュレーション値を区別し、条件を再現できる
- ネットワークは**散策の地図**：概念から前提・つながり・別の科目へたどれる
- 記録は任意（研究ノートとして残したいときだけ）。到達や点数にしない

### R4 自分の学習と、共有を分ける
- 教材（原本・公開物）に個人のデータを入れない。個人の記録は ID だけを指す
- 個人の記録を外しても、教材として使える（配布先の設定：personal_root が空）
- 記録が教材の書き直しで壊れない（ID を変えない）

### R5 科目をまたいで広げる（知識ネットワーク）
- ネットワークは教材に依らない（knowledge-net）。教材だけでなく**ノート**（単元・段階のない知識のまとまり）も載せられる
- 科目をまたぐ線を引ける（例：小売の発注量 →「応用」← 期待値・分散）
- 別の科目の概念がまだなくても、線は「未接続」として残る（今ある決まり）

### R6 正しさを確かめられる
- 数は検算式で確かめる（今ある）。反例は「何を、どの数で否定するか」まで確かめる
- 観察（シミュレーション）と証明、近似と厳密を混ぜない

## 4. 要件から決まる役割

| 部品 | 合格の区域での役割 | 好奇心の区域での役割 |
| --- | --- | --- |
| 問題 | 分かった証拠を作る（照合） | 問いを立てるきっかけ（評価しない） |
| ラボ | 予想→照合で意味をつかむ・問題を確かめる | 研究の道具（反例・条件・つながり） |
| 知識ネットワーク | 戻る先（前提・誤解）を示す | 散策の地図・別の科目への橋 |
| 個人記録 | 到達と復習の期日を決める | 研究ノート（任意） |

## 5. 決まったこと（渡辺さん、2026-10-29）

- **D1 創造の観点**：「切り分け」「解釈」「前提の吟味」「別の可能性の探索」などの観点は、学習者が任意に使う**自分で振り返るための補助**として残す。到達の基準・点数・完了の条件には使わない。すべての探究で振り返りを求めない
- **D2 好奇心の区域の記録**（形は保留）：**研究ノート**を設ける。記録・保存・振り返りは任意。未完成の問い・結論のない記録・途中で考えが変わった記録も有効。項目は内容（保存するときだけ必須）と、任意のタイトル・関連する概念・仮説・実験の条件（ラボ・場面・値・乱数のシード）・観察と発見・まだ分からない問い・関連する資料。ラボの今の状態をそのまま添付できる
- **D3 別の科目**（形は保留）：教材と**知識ノート**は別の型にする。教材は単元・段階に属し、知識ノートはそれを求めない。両者は共通の概念 ID と参照の仕組みで知識ネットワークにつながる。公開の範囲と個人の情報は教材から分ける
- **D4 好奇心への入口**：「なぜ？」（仕組み・導出・理由）「本当に？」（前提・反例・限界）「ほかでは？」（別の分野・実務・概念）「自分なら？」（自分の問い・実験）の4つを採用する。型は足せるタグとして扱い、1つの入口に複数付けてよい。入口を開くことは合格の区域の進み具合・完了の条件に含めない

### 補足の原則
- 好奇心の区域では、到達・完了・点数を学習者に求めない
- 2つの区域は、知識の基盤（概念・ネットワーク・数理エンジン）を共有し、学習の評価を分ける
- 実験の結果を残すときは、再現に要る条件を一緒に残す

### 区域ごとの約束

| 合格の区域 | 好奇心の区域 |
| --- | --- |
| 正答・理解・再現を確かめる | 問い・考え・発見を振り返る |
| 到達の条件がある | 到達の条件を置かない |
| 復習の期日を管理する | 自分から何度でも戻れる |
| 進み具合を出す | 探究の跡を出せる |

### 2つの「ノート」を混ぜない（保留：ノートの話はいったん離れる。2026-10-29）
| | 研究ノート（D2） | 知識ノート（D3） |
| --- | --- | --- |
| 何か | 自分の探究の記録 | 別の科目などの知識のまとまり（小売の計数管理など） |
| 置き場所 | 個人の記録（公開しない） | 公開できる知識（ネットワークに載る） |
| 型 | 個人の記録の型 | knowledge-net の型（教材と並ぶ別の型） |

研究ノートで育った考えを知識ノートに書き起こすことはできるが、自動ではつなげない（個人の記録を公開物に入れない）。

## 6. 今の決まりとの照合

| 今の決まり | 要件との関係 |
| --- | --- |
| stages.yaml の exam（初学〜応用が true） | R1 と一致 |
| 発展・創造に予想→照合を置かない | R3 と一致 |
| 創造の「評価の観点」 | D1：自分で振り返る観点として残す。CLAUDE.md の「評価の観点」の書き方を合わせる |
| 型 v1 の `course.units` が必須 | D3：知識ノート用の型を knowledge-net に足す（v1 の改訂か v2 かは型の決まりで判断） |

## 7. 次にすること
R1〜R6 と D1〜D4 を、要件ごとに次の4つに分ける（機能に直接割り当てない）：
1. 何を実現するか
2. どのデータが要るか
3. どの仕組み（教材の build・math-lab・knowledge-net・個人の記録）が責任を持つか
4. 何をもって実装済みとするか（数えられる条件）
