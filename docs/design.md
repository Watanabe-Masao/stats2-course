# 全体設計（下書き・保留：目的から考え直す。2026-10-29）

教材の骨格（単元×段階）を土台に、問題・ラボ・知識ネットワーク・学ぶ仕組み・個人記録を**1つのコンテンツ**として設計する。計画（いつ・どの順で作るか）は course-plan.md と #55、ここは「何をどういう形にするか」の元。

## 0. 原則

1. **確かめる対象は1つの言葉で書く**。問題・ラボ・図・本文はどれも「何を確かめるか」を、概念・関係・命題・誤解の ID で指す。単元はその入れ物。
2. **部品は1か所、入口は多数**。問題もラボの場面も1か所に書き、単元・概念・誤解・復習・研究のどこからでも同じものを開く。問題集やラボの一覧は「並べ方」で、別の中身を作らない。
3. **答えの決まる問いと、決まらない問いを分ける**。初学〜転用は照合できる問い。発展・創造は説明・切り分けと評価の観点。
4. **記録は ID だけを指す**。個人の記録は教材の ID（単元・段階・問題・概念・場面）を参照し、教材の原本には入れない。
5. **生成物は原本から作る**。Notion のページ・公開サイト・ネットワークの JSON・問題集の並べ方は build が作り、build が型と数を検査する。

## 1. 骨格：単元×段階（今あるもの）

- 9領域・33単元。各単元は前提（prereq）と後で使う単元（used_by）を持つ
- 各単元に6段階のタブ。段階ごとに「ゴールの文」と「できた証拠」がある（33×6＝198 のセル）
- タブの中の節は全単元で同じ型（初学：入口の問い→前提チェック→意味→式の構造→例題→実験→自力で確かめる→振り返り など）

**セル（単元×段階）が、学ぶ順と到達の記録の単位**。概念が、理解の単位。この2つの軸を部品がつなぐ。

## 2. 問題・設問

### 2.1 何を持つか

| 項目 | 意味 |
| --- | --- |
| 置き場所 | 単元・段階・節（今ある） |
| 確かめる対象 | 概念・関係・命題・誤解の ID（**今 0/537 問**。W0c から） |
| 形式 | 選ぶ・埋める・書く（今ある）＋説明する・切り分ける（発展・創造） |
| 誤りの診断 | 選択肢や典型的な誤答が、どの誤解に当たるか（誤解の ID） |
| 確かめ方 | ラボの場面か図（今ある。493 問にラボ、44 問に図） |
| 評価 | 照合（答え・checks）か、観点（発展・創造：切り分け・解釈） |

### 2.2 本文の設問と、問題の違い
- 本文の設問（入口の問い・前提チェック・例題）は読む流れの一部。記録しない
- 問題は ID を持ち、記録・復習・診断の対象になる。**記録したいものは問題にする**（発展・創造の課題も、ID と観点を持つ問題にする。今は発展 8・創造 0）

### 2.3 問題集＝並べ方
中身は1か所（content/problems）。問題集はその並べ方として生成する。

| 並べ方 | 何で選ぶか |
| --- | --- |
| 単元・段階順 | 置き場所（今の単元ページ） |
| 概念別・関係別 | 確かめる対象 |
| 誤解別 | 誤りの診断（この誤解を崩す問題だけ） |
| 本番形式 | タグ（旧版の15問を取り込んだ後） |
| 混ぜた問題 | 複数単元の概念（復習の約1か月後） |
| 自分の復習 | 個人記録（間違えた問題・弱い概念・期日）。ここだけは個人の側で作る |

## 3. ラボ

### 3.1 装置と場面を分ける
- **装置（ラボ）**：数理エンジン・モード・画面。数学の性質でテストする（math-lab、#66）
- **場面**：装置の使い方。最初のモード・値・課題・予想・照合の答え。教材の側に置く（予想の答えは公開しない）

### 3.2 場面の種類（用途）

| 種類 | 段階 | 形 |
| --- | --- | --- |
| 確かめる | 初学・復習 | 1つの場面で予想→照合 |
| 問題を確かめる | 全段階 | 問題の数値を入れた場面（今の answers の lab） |
| 法則を見つける | 応用・転用 | 条件を変えて予想を重ね、式で説明（steps・law） |
| 反例・誤解を崩す | 応用（照合）・発展（探す） | 命題・条件・反例・何をどの数で否定するか（#70） |
| 関係を見る | 応用・発展 | 2つの概念を並べる（変換の近似誤差・対比・A/B） |
| 図とつながりを触る | 初学・復習 | 点を動かすと図と数が一緒に動く（LAB-graph） |
| 研究する | 発展・創造 | 予想なし。自由に動かし、問い・条件・結果・説明を記録する |

**どの入口からも同じ場面を開く**：単元の節・問題の答え・概念・関係・誤解・反例・研究の問い・自分の復習。起動は1つ（起動契約、#66）。

### 3.3 結果の扱い
- 理論値・近似値・シミュレーション値を分けて出す。乱数はシードで再現できる
- 予想・条件・結果・説明は、個人記録へ渡せる形で返す（記録先は教材ではない）

## 4. 知識ネットワーク

### 4.1 点と線

| 種類 | 中身 |
| --- | --- |
| 概念 | 114 語（今 8 概念）。定義・原理・式・条件（数学／データ）・例・反例・誤解 |
| 命題（案） | 「平均±2σ に95.45%」のような主張。成立条件と反例を持つ。まず概念の属性として扱う（#70） |
| 関係 | 8種類（前提・導出・一般化・特殊化・変換・対比・統合・応用） |
| 導出 | 前提（2つ以上）→ 結論 |

### 4.2 単元をつなぐ
- 単元の前提（prereq）は今は手で書いている。**概念の前提関係から単元の前提を導き、手書きとの食い違いを build が出す**（どちらかの直し漏れを見つける）
- 単元をまたぐ線（例：二項→正規＝U14→U16、正規→中心極限定理＝U16→U19）が、ネットワークで見える「教材の背骨」になる
- ネットワークから単元・問題・ラボの場面へ、単元・問題・ラボからネットワークへ、の往復

### 4.3 見え方
概念の詳細・前提をさかのぼる・2〜3概念を比べる（済）、クラスターマップ（W2）、自分の理解の地図（#54 のあと）、再構築演習（#63）。

## 5. 体系的に学ぶ仕組み

1. **地図**：ネットワークで、今どこにいて何が前提かを見る
2. **道順**：単元×段階のセルを順に進む（前提チェックで戻る先は概念の前提から）
3. **練習**：問題とラボの場面。誤答は誤解の ID で診断する
4. **記録**：問題の結果・セルの到達・ラボの予想と説明
5. **次の一手**：復習の期日（翌日・1週間・1か月）、弱い概念、残っている誤解から、次に開く問題・場面を選ぶ（個人の側で。ChatGPT と組む）

## 6. 個人記録（KSLP・#54）

| 記録 | 指す ID |
| --- | --- |
| 解答記録 | 問題・（誤答なら）誤解 |
| 到達記録 | 単元×段階のセル（できた証拠） |
| 学習ログ | 単元・ページ・時間 |
| ラボの記録（案） | 場面・予想・条件・説明 |
| 理解の地図（案） | 概念ごとの状態（解答記録から計算） |

教材の原本・公開物には入れない。ID は変えない（`retired`）。

## 7. 1つのコンテンツにするための約束

| 約束 | 中身 |
| --- | --- |
| ID の体系 | U（単元）・S（段階）・Q（問題）・TERM（概念）・REL・DER・LAB と場面・FIG・（案）PROP・MIS・CE |
| 1か所に書く | 原本：stats2-course／型：knowledge-net／装置：math-lab／記録：Notion の個人用 |
| 生成する | Notion の単元ページ・ガイド・進み具合、公開サイト、net の JSON、問題集の並べ方 |
| 検査する | 型・checks・孤立した概念・反例が本当に否定するか・単元の前提の食い違い・埋め込みの大きさ |

## 9. 決めること
1. 命題（PROP）・誤解（MIS）・反例（CE）を独立した ID にするか、概念の属性のままにするか
2. 発展・創造を「観点付きの問題」として ID を振るか（記録・評価につなぐなら必要）
3. 問題集の並べ方をどこに出すか（Notion のページ／ネットワークの画面／両方）
4. 単元の前提を概念から導く検査を、いつ入れるか
