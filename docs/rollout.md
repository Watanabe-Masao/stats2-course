# 横展開の手順書（R3。#172）

新しい概念を「発見の環境」に載せる順番と、各段を閉じる確かめ方。2つの実例から書いた：二項分布（式で決まる分布。R1・#171）と期待値（表で決まる分布。R2・#119）。

この文書は**順番と完了の確かめ方**だけを書く。意味の判断は製本（docs/rules/）、決まりは CLAUDE.md、書き方（記法・YAML の形）は docs/authoring.md にある。ここに中身を写さない。

## 0. 始める前

- 作業の issue を作り、読む製本（CLAUDE.md の製本の表）と、つながり（前提の issue・親）を書く。
- 対象の概念と、その単元の今の数を `python3 build/progress.py` で見る（人の記憶で決めない）。
- 新しい形（型の項目・画面の部品）を足すのは、下の段で要ると分かったときだけ（roadmap 9 の「止めること」）。

## 1. 概念：骨格 → 説明あり

製本 ①（同一性・姿）、③（成立条件）、式があれば ②。書き方は authoring「概念データの書き方」「製本の形で書く」「成立条件の区分」。

1. 1つの概念にするかを ① の 2 で決める（別の語に分けるか・同じ名前で呼ぶ別の形か）。
2. 姿（`forms`）を ① の 3 で決める。記述の道具はデータを固定して見る（#342）。2つの姿は、偶然の側の姿が ⑤ の線の端になるときだけ。
3. 確率分布は確率関数・確率密度の式を基準の定義にする（`basis_formula`）。定義1文（`short`）は学ぶ人向けの導入のまま。
4. 説明あり：`principle`・`conditions`（math と data。行ごとに区分）・`example`・`counterexample`・`misconceptions`・`sources`・`version`。数があれば `checks`。
5. 概念のページの元（R1c。#188）：`question`（問い）・`gist`（つまり）・`chart`（その場で描く図）・`figures`・`labs`。ページの見せ方は画面の側で直すので、ここでは原本の項目だけをそろえる。

閉じる確かめ：build が通る（必須の項目・区分・孤立）。① の確かめ方で、check-pairs.md の組を振り分け直したか。

**実例から（W1 の U10・U11。2026-11-15・16）**：独立な監査役で毎回直した型。書く前に当てる。
- 命題の概念（加法定理・乗法定理など）の条件は「仮定」にして claim（④）を書く。対象の要件（P(A)＞0 など）はその対象の概念の側に書き、命題に重ねない
- 反例は、その条件を外したときに、定義が決まらない・式が誤る場面を示す（条件を満たしたまま「別の誤り」をする例は誤解へ）
- 概念の基準の定義が式なら `basis_formula`。式が「定義」でなく公理などから導く等式なら、述語の概念の側に置く（余事象の確率は確率の式）
- 誤解は1つの概念にだけ置く（同じ誤解が関係の文にもあれば、概念の側は別の誤解にする）

**実例から（W3 の U17。2026-11-16）**：
- 要件を書いたら、その概念の基準の定義（basis）が許すもの（重複・復元抽出・集落）と、一種の関係の子（集落抽出など）が、その要件を満たすかを当てる。狭すぎる要件は、自分の定義と子の概念を外してしまう
- 主張の主語の概念が許すもの（枠の重複・戻す選び方）を、主張の条件に書いたかを当てる（CLM-40 の包含確率 n/N は、重複がなく戻さないときだけ）
- 製本で決めた扱い（① 6-6：確率が分からない取り方でも標本分布・偏りは「ある」が求められない）と、要件の outside（「定まらない」）を食い違わせない
- 定義1文・例・原理は basis より強く言わない（basis が「変わりうる」「〜のとき」なら、そのまま残す。U18 の統計量・標準誤差）。確率変数の分散・ばらつきを言う所は大文字（X̄）で書く（② 4）
- 仮定の行の outside には、前の単元で学んだ取り方でのずれも書く（独立が崩れる向きは1つではない。戻さずに取ると X̄ の分散は小さい）
- 一致の理由を「偏りが0に近づく」だけで書かない。偏りとばらつきの両方が縮むこと（正規母集団など、ばらつきが縮む条件も）を書く（U21 の v の一致）
- 比べ方の注意（同じ母数の値で比べる）を要件の行にしない。要件は定義が成り立つための条件だけで、比べ方は principle か data に書く。要件と仮定で、一方が他方を含んで outside が起きない組を作らない（U21 の MSE）
- 近似の作り方（割合の p̂±z×SE など）について、「信頼係数が 1−α に近づく」と書かない。近づくのは母数の値を1つに固定したときの被覆確率だけで、信頼係数（下限）は別（④-19。U22 の区間推定・信頼係数）
- 信頼区間の図で、x̄ を中心にした分布の曲線に区間を塗らない（「μ が95%の確率でこの区間にある」という図になる）。区間は横の棒と点推定の点で描く（U22 の解説の図・場面 mean）
- 「〜のときだけ有利」と条件を言い切る前に、境目を計算する（対応ありがウェルチより狭くなるのは、10店なら相関が約0.14を超えるときで、「強く連動するときだけ」ではない。U23）

**実例から（W5 の U28。2026-11-16）**：
- 定義に因果の見立て（直接の因果がない）を含む概念は、それを要件の行にして「データの外の見立てで決める」と添える。仮定の行にして claim を書くと、claim が定義の言い換えになる（④ の 1 に当たらない）
- 偏相関・層別で取り除けるのは「z と直線的に一緒に動く分」まで。「見かけの相関が消える」「z を通した分」は因果の見立てを含むので、統計で言える分と見立てを分けて書く（z が x と y の間に入る量なら「見かけ」ではない）
- 同じ注意を、誤解・data の行・仮定の outside の3か所に書かない。誤解は1か所にし、data は確かめ方の手掛かりに絞る
- 回帰の係数は「x を1増やすと y が b 増える」と書かず、「x が1大きいところでは y が平均して b 大きい」と書く（増やす・広げるは介入の言い方。short・本文の表・key もそろえる）。重回帰の係数も「ほかを固定したとき」でなく「ほかと直線的に一緒に動く分を除いたあと」（U29）
- 仮定の claim は、記号で書けて示せる1文にする（「見込みになる」では何を指すか決まらない。「x ごとの y の平均が1本の直線に乗るなら、回帰直線はその直線と一致する」）。反例は、その仮定だけを外した場面にする（範囲の外で曲がる例は、範囲の中では直線にぴったり乗るデータで作る）（U29）

**実例から（#53 の標準正規分布・無相関。2026-11-17）**：
- checks は文の数を写さず、分布（値と確率の表）から作り直す。E(XY) を「1/2×1/2」と書くと E(X)E(Y) しか確かめていない（確かめるの3 独立性）
- 確率変数の概念の定義・例に「値」「相関係数」と書かない。データの概念（TERM-corr はデータの r）へ行ってしまう。確率変数・確率変数の相関係数 ρ と書くか、書かない
- 仮定の行の text は条件だけを書き、結論は claim に持たせる（「Z が N(0, 1) に従うのは X が…のとき」でなく「X が N(μ, σ²) に従う」）
- 誤解の訂正が反例の言い換えになっていないかを当てる。なっていたら、誤解は別のよくある誤り（σ² と σ の取り違え）にする

**実例から**：期待値の B-01 で、大数の法則（TERM-lln）の説明を問いの前に書いた。問いの考察の文（条件「分散が有限なら」）と概念の `conditions` を同じ主張（④ の CLM-）から写すと、言い方がずれない。

## 2. 関係・主張・学ぶ順

製本 ⑤（関係）、④（主張・導出）、⑥（学ぶ順）。書き方は authoring「関係図に移す」「学ぶ順」。

1. ⑤ の判定の順（定める → 一種・特別な場合 → 移る → 比べる → 線にしない）を全部当てる（#336）。線にしない判定も check-pairs.md に残す。
2. 移る・比べる・導ける・特別な場合に `gist` と図（`figures`）。移る・比べる・導けるに解説（tour）と確かめるラボ。
3. 前提知識は関係に書かず、learning.yaml の足すに理由の1文と書く。

閉じる確かめ：build（関係の種類・区分・学ぶ順の輪）。関係図の警告（図のない関係）がその分類で0。

## 3. 式

製本 ②。書き方は authoring「式の分解の木」、CLAUDE.md「問題・式の決まり」。

1. 式は木で書く（`tex` を書かない）。記号に `of`・`domain`。1式＝1つの等式の連なり。
2. 全部の式に契約（content/formula-contracts.yaml）。
3. 代表の式は、書いた側でない独立なレビューの記録（content/formula-reviews.yaml。指紋つき）。

閉じる確かめ：build と `python3 build/formulas.py --publish-check`。直したら authoring「直したら一緒に直すもの」の式の行。

## 4. 作業台

決まりは math-lab の CLAUDE.md「作業台の型」。

- 式で決まる分布 → 概念の `workspace`（二項分布）。表で決まる分布 → `table_workspace`（期待値）。
- どちらにも合わなければ、先に型にパターンを足す（例：連続分布は3つ目のパターン）。概念の好みで欄を変えない。

閉じる確かめ：knowledge-net の作業台のテスト（欄ごとに同じ確かめ方を両方のパターンに当てる）に、その概念が入る。

## 5. 問い

製本 ⑦。仕組みは CLAUDE.md「実験室」。

1. テーマ体系（まとまり：分布の形と仕組み・事象と確率計算・理論と実験・期待値と分散・前提条件と反例・応用など）を先に作り、どの画面に並べるかはあとで決める。
2. 問いは発見させたい性質の数だけ。主は発見させる性質で、関連は理解に実際に使う概念だけ。似た問いがあれば重複の判断（⑦ の 1）。重なるなら統合し、片方を `retired: true`（期待値の B-02 を B-01 にまとめた）。
3. 問いごとに：予測（画面に見えている物か具体の数で。答えは書かない）・操作・観察（見る所だけ）・考察（理由と、題の問いへの答え）・応用（別の考え方）・`judge`（理解判定。性質の文を先頭に）。
4. 頻度と目安の文は ⑦ の 2 の型（今の回数・0% に丸めない・範囲を下限と読ませない）。量の名前・単位・数える語はテーマごとに1か所で決める（⑦ の 4）。
5. 応用は、見当で選べる選び肢をなくす。反証の二択は答えを偏らせない（⑦ の 3）。

閉じる確かめ：⑦ の 5 を全部当てる。

## 6. 実験の仕組みと画面

- 既存の問いの形（`open` の部品）で足りるかを先に見る。足りなければ型（kn-experiment）に任意の項目を足し、改訂を上げる（knowledge-net の CLAUDE.md の 2）。
- 反例は「成り立つ条件を外す実験」だけを反例の欄に置く（#369）。5つの条件をそろえ、崩す条件は1つ。
- 新しい画面（実験室）が要るかは、5 と ここのあとで決める。
- 画面の部品を足したら、knowledge-net の docs/decisions.md に決定（どの原則から・前提・根拠・見直す条件）を書く。

閉じる確かめ：engine の性質のテスト（同じ種なら同じ・理論に近づく・境目）と、画面のテスト（問いの流れ・テーマで答えの位置が変わる）。大事なテストは、わざと入れた誤りで落ちることを確かめ、テストのコメントに書く。

## 7. 独立に読み直す

書いた側が自分で確かめるだけで閉じない（2026-11-14・11-15 の実例では、毎回ここで直す所が出た）。

1. ⑦ の監査役（問いの設計：重複・粒度・応用の考え方・照らしの頻度）。数の言い分は、監査役が別の道（独立な計算）で検算する。
2. 概念・関係を変えたら ①③④／⑤ の監査役。
3. 学習者役（画面を上から順に読み、「分からなくて止まる」「引っかかる」を挙げる）。
4. 指摘は点で直さず、ほかの問いでも起きる型か、一度だけかに分ける。型は製本か authoring に入れ（変更の入口）、一度だけはその場で直す。直したら、同じ言い方が出る所を grep してから閉じる。

## 8. 公開

1. 型・画面を変えたら、knowledge-net を先にマージ・公開する（CLAUDE.md「データの意味が変わる公開は、画面を先に公開する」）。
2. 教材を main から公開する（authoring「公開」）。
3. knowledge-net の見本を取り込む（`node scripts/sync-sample.mjs --update <labs の sha>` と `cd math-lab && node scripts/sync-stats2.mjs --from <教材>`）。見本の数や中身に頼るテストを直し、`npm run check` を通す。

## 9. 単元へ戻す

roadmap 10 の共通の完了条件を、その単元に当てる。

- 問題に `concepts:`（解く・解説を理解するのに要る概念・関係・主張だけ）と `concepts_linked: true`。
- 問題に付けたラボの予測・課題の文を ⑦ の 2「単元の問題のラボ」（型 A〜E）に合わせる（#373 の表のその単元の分）。
- 初学に概念図、復習の「図を再現する」はその手本で。
- 発展・創造は ⑧ の形（予測の照合を置かない。「1つの考え方の例」）。

**実例から（W3 の U17）**：
- 創造の「統計で言えること」は、どの範囲について言えるかを段に分ける（送った人・抽出枠・母集団）。1つの範囲の結論を、広い範囲の結論として書かない
- 解釈の向き（高め・低め）は、「誰が抜けたか → 抜けた人の値は大きい側か小さい側か → だから手元の値は」と1段ずつ書いて確かめる（U17 の未回答で、向きを逆に書いた。独立な読み直しでも見落とされた）
- 発展の課題文が、使うラボのモードが実際に出す値で見られるかを、ラボの値の一覧（tool.yaml の values）と照らす。式の値とラボの値がいつも同じなら、比べさせても発見にならないので、学ぶ側が自分で計算する量を残す
- 問題の concepts は、答えの解説を1行ずつ読んで、使っている概念を全部拾う（標準化・独立・差の分散など、単元の主役でない概念も。U18 で 4問の漏れ）
- 初学のラボの予測の数は、同じ節の問い・例題・概念図に出ていない数にする（U18 の s1-se は、予測の前に答えの 2g が3回出ていた）
- 種が固定のラボ（押すたびに同じ結果）で「何度押しても」「回数を増やすと」と書かない
- 解釈の向きは、仕組みの1段も抜かずに書く（「まとめて応募 → 当たり外れがまとまる」では足りない。1口ずつ独立に抽選するなら、まとめて応募しても独立は崩れない。U19）。解釈には、データの生まれ方の一番素直な読み方（数が回ごとに違う・確率そのものが変わった）を入れたかを当てる
- 要件の行の outside は「〜に従うとは限らない」「この作り方では作れない」で書き、「従わない」「定義されない」と言い切らない（たまたま同じ分布になる組み方・ほかの所で使う一般の形〔ウェルチの整数でない自由度〕がある。U20）
- 移るの段で、1つの点（5%の点）がそろったことから分布がそろうことを言わない。分布がそろう理由（定義の形）を先に書き、点の一致はその帰結として書く（U20 の t→F）
- 版の set・解説の段の値が、ラボのつまみの刻み（step）に乗るかを当てる。乗らないと値が丸まり、文と画面の数がずれる（U20 の F で s₁²＝5.117 が 5.0 に丸まった。探究の s＝3.93 は入れられない）
- 数表で出せない確率（t・カイ二乗の p 値など）は、数でなく「0.05 より小さい／大きい」の選び肢で予測させる（⑦ の 2 の B）
- 発展・創造の主張にも前提を添える（「返品率 1% なら」だけでなく「独立に起きるなら」。モデルで出した値を「本当の値」と呼ばない。U19。母数やシミュレーションで決めた値（母集団の平均・設定した効果 τ）を「本当の」と呼ぶのは対象外。#429 で全体を見て、該当はなかった）
- 発展と創造で同じ中心（例：答えた人と答えなかった人の違い）を扱わない。発展はその単元の「なぜ・何が消えるか・前提が崩れると」、創造は混ざったデータの切り分け
- 発展の「説明してみる」は、手前の段（初学・応用・転用・ラボの初期値）と同じ場面・同じ数・同じ結論にしない。同じ性質を、新しい見方（その推定量は何に一致しているのか）で問う（U21 の集め方の偏り → 滞在時間の長さで選ばれる偏り）
- 創造の課題で「必要な n は？」のように答えが1つに決まる計算を置かない（応用に置く）。創造に残すなら、計算に入れる数（どの日から s を取るか）を選ぶことと、その選び方が何で決まるかを切り分ける形にする（U21 の課題B）
- 発展の「1つの数で何が消えるか」と創造の探究で、同じ結論（使い道で推定量が変わる）に落ち着かせない。発展は数の内訳の性質（平均すると縮む分と縮まない分）に絞り、使い道の判断は創造に任せる
- 発展の節に、次の単元が2級の範囲として扱う中身（U23 の差の区間）や、別の単元の発展と同じ場面・数（U24 の多重比較の k＝20）を置かない。つながりとして「ほかでは？」で指すだけにする（U22）
- 創造の設計の課題（人数と集め方を決める）にも、選び肢を2つ以上と判断の材料、1つの考え方の例を置く。報告に添える項目は「統計で言えること」の見出しに入れない（U22）
- 初学のラボの選び肢の予測（約95%が含む）の答えを、同じ節の問い・概念図で先に言わない。信頼係数を変える（90%）など、見せていない設定にする。予測のあとに動かす選択欄は unlock に書く（U22 の s1-cover）
- 創造の探究の中心を、ほかの単元の創造と同じ型（2つの集団の比率 → 差の区間 → 解釈3つ）や同じ交絡（曜日とキャンペーン。U32）にしない。その単元の方法でしか出ない問い（U23 なら、どれと比べるかで差の区間が変わる）を中心にする（U23）
- 解説（tour）の段でモードを切り替えるときは、最初の段にもモードを書く（版の mode だけでは、ラボが前の段のモードのまま始まることがある）。段の文と「つまり」は、埋め込み（320px）に収まる長さにする（U23 の対応ありとウェルチ）
- 創造の探究で、比べる相手のない前後の差（基準より上がった）を「効果」と呼ばない。手前の単元で教えた比べ方（U23 の差どうし）と食い違わせない（U24）
- 発展の「本当に？」は、別の単元の発展と同じ仕組み（値どうしが独立でない）にしない。その単元の手順に固有の前提（U24 なら σ を分かっているとして z を使うこと）を崩す（U24）
- 発展の「1つの数で何が消えるか」は、平均の推測で1つずつの散らばりが消える話（U23 の発展）を繰り返さない。その単元の数の内訳（t＝差÷s×√(n÷2) で、差の大きさと日数が1つの t に混ざる）に絞る。「本当に？」も選び方の偏り（平均への回帰。U29）でなく、その単元の手順の前提（正規性。歪んだ分布で少ない群に t を使う）を崩す（U25）
- 概念図で重ねる2本の曲線がほぼ重なるとき（t(15) と正規）は、違いの出る範囲（右の裾）を拡大して描く。並ぶ縦線（1.96・2.0・2.131）は拡大で離す。目盛りの数も本文にある数だけにする（build が止める）。復習の「図を再現する」の文は、手本の範囲と線にそろえる（U25）
- 創造で「何を1個と数えたか」を問うときは、日を1個と数えた t をそのまま次の段の根拠に使わない（研修の前の差を、同じ数え方の t で「前からの違い」と読まない）。同じ数え方で、研修のない期間にも t が出ることを見せる（U25）
- 発展・創造のラボで、つまみで正確に合わせにくい値（平均 0〜5000 の 1200、日数の 200）を学ぶ側に入れさせない。値は版の set で渡し、版ごとに動かすものを1つにする（U25 の s5-ratio・s6-before）
- 版の set は最初のモードにだけ当たる。2つのモードで別の値を見せたいときは、版を分ける（U26 の s5-pt1・s5-pt20）
- 発展・創造を書く前に、手前の単元の発展・創造で同じ前提を崩していないか（U20 の分散の検定と正規性）、同じ型の創造（U19 の「二項分布の前提よりばらつく」）がないかを grep で当たる。重なったら、その単元の方法でしか出ない問い（U26 なら、基準の p₀ がどう生まれた値か・F が比べている揺れの中身）に移す（U26）
- 「なぜ？」で2つの方法の食い違いを見せるときは、食い違いのもと（区間の SE に p̂ を入れる）まで書く。「離れているほど」のような傾向は、反例（p̂＝0.4・p₀＝0.6 で SE が等しい）を当ててから書く（U26）
- 発展・創造の課題文で手前の段の例を指すときは、その例が実際にあるかを grep で確かめる。「本当に？」で「倍率 → 誤って棄却する割合」を出す型は U24 で使った。ほかの単元では、その単元の手順を選ぶ判断（基準が何人分の積み重ねか）を中心にする（U26）
- 版を足す・直すときは、予測が数表で出せない値（χ²・t の p 値）になっていないかを、その単元の全部の版と問題のラボに当てる（U27 の s1-gof・Q-U27-030 は p 値を数で予測させていた）
- 交絡の例（2つの店を合わせた表のシンプソン型）は U01・U11 の発展で使っている。検定の単元の「本当に？」には、その検定の近似の前提（期待度数が小さいと χ² 分布から離れる）を使う。合わせた表の関連は統計としては本当にあり、崩れるのは「効果」という解釈の方だと書き分ける（U27）
- 「分散はおよそ E」のような近似の言い方は、その単元の例題に当てて確かめる（例題A の E＝25 では O−E の分散は約6.3）。近似の差が自由度と同じ話になるなら、そこまで書く（U27）
- 創造の探究の設定の文（「出入りのたびに数える」「同じ人を1回」）と、答えの例の計算が使う前提（1人1回なら20%のまま）を1行ずつ照らす。設定から起こらない数を答えに書かない。分子と分母の単位（レシートか人か）がそろっているかも当てる（U01）
- 名指しの見出しは「統計で言えること（前提）」にそろえる。計算だけの段でも「計算で言えること」と別の名前にしない（U01）
- 「なぜ？」は、初学〜応用で済んだ結論（増減は掛ける）を繰り返さず、その結論の新しい見方（足し算とのずれは率の2乗）にする。次の単元が2級として教える計算（幾何平均）は「ほかでは？」で指すだけにする（U01）
- 概念図を新しい図の型で作るときは、同じ物を描くラボの色（`--acc` と中立の色）と呼び名にそろえる。色の名前（灰色・白い）で呼ばず、物の名前（対角以外の長方形）で呼ぶ。後の単元が2級として教える計算（分散の近道・桁落ち）を発展に置かない（U02）
- 創造の設定に数を並べたら、数どうしを掛けて照らす（1日10個×2週間と月9,000件は両立しない）。設定の数が答えの読み方（3%は低く出た）を支えているかも、その掛け算で確かめる。ラボの版も、探究の中身（全数を調べても届かない）を起こせる値にする（U03）
- 「〜ほど」の傾向は、両端の2つの組の平均だけでは言えない。真ん中の組を設定に置くか、2つの組の差までにする。尺度の言い方では、差で読むのに要るのは間隔がそろうこと（間隔尺度）、何倍に要るのが 0（比例尺度）で、この2つを1つの理由にまとめない。発展の結論を、ラボを動かす前の本文や版の課題文で言わない（トグルの中に置く）（U04）
- 版で値を動かした後の状態から始めると、学ぶ側は動かす前の値を見られない。動かす前と後を比べさせる版は、元の値で始め、動かすのは学ぶ側にする。「なぜ？」で手前の段の結論（幅をそろえる÷幅）を広げるときは、手前で扱わない違い（個数の違う2つのデータ）を中心にする。順位で決まる数（中央値・四分位数）の動きは、「値の間が広い」でなく「どの位置をまたいだか」で説明する（U05）
- ラボが画面に出さない値（柵・途中の値）を、版の課題や本文で「読む」と書かない。出さない値は「自分で計算する」と書く。版が答えの状態で始まらないかも、U05 の行と合わせて全部の版に当てる（U05 で決めたのに U05T の s6-cal で再発した）。創造の「統計で言えること」の前提に、結論で残る分を消してしまう仮定（「1日あたりの売上は前年と同じ」なのに残る伸びを言う）を書かない（U05T）
- 創造・発展で使う計算の決め方（分位点の補間など）を、その単元の初学〜応用で教えているかを確かめる。教えていない決め方を使うなら、その場で決め方を書き、ラボの決め方（四分位数）との違いも書く。発展の節と、発展に置いた問題とで、同じデータ・同じ結論を繰り返さない。予測のない版には「くわしく」のボタンが出ない（表・式はそのまま見える）ので、版の課題で「くわしく」と書かず、「式で計算」の欄・表の欄と書く（U06。U09・U17・U26・U29 の同じ書き方もこのとき直した）
- 創造の設定の数どうしが両立するかを、内訳まで計算して照らす（「土日が平日の2倍」と標準偏差25は両立しなかった）。目安の式（√平均）の前提は、式が成り立つための1段まで書く（1人1個買う）。発展の3つの節と説明してみる・創造で、同じ結論（前もって分かる分がまとまる）を繰り返さない。前の単元の発展（U06 の「何を最小にするか」・U21 の独立）と同じ仕組みを繰り返さず、つなぐ1文にする。ラボのデータの名前は短くする（選択欄が埋め込みで横にはみ出す。U06）（U07）
- ラボで太字に出る値と本文の計算の定義が合っているかを確かめる（ラボの標準偏差は n−1 で割った s、本文は n で割った値だった）。発見させたい式・決まりを問いの文に先に書かず、トグルの中に置き、問いには具体の数を置く。指標を比べる創造で「A と B のどちらか」の二択にせず、自然な3つ目の指標（伸び率）を消さない。解釈の例は、1つ目を前提にした言い換えではなく、データの生まれ方（記録の側）を含めて互いに別の読み方にする。課題の判断の材料は、答えの例で全部使う（U08）
- 課題文の操作（真ん中の点を消す・店1 だけを残す）が、ラボの操作でできるかを確かめる（相関ラボの「点を消す」は最後の点からしか消せない）。見せたい点の組ごとに版を分け、data で渡す。静止図とラボで同じ物の色が逆にならないかを当て、本文では色の名前でなく位置（右上・左下）で呼ぶ。発展の「本当に？」を応用で見た性質の裏返し（範囲を絞ると下がる → 両端を選ぶと上がる）にしない。創造の課題を、ほかの単元の創造と同じ枠（本部の画面×ア・イ・ウ）にせず、その単元の方法でしか出ない選び方（式で結ばれた量の揺れの出どころを、r と変動係数のどちらで示すか）にする（U28）
- 概念図を例題より前に置くときは、図の中に例題の答えの数（SST・SSE）を出さない（図の型の設定で数を消す）。創造の聞き取りで答えの要因（駅前・改装）を先に渡さず、自分の問いを書いてから開くトグルに入れる。1店だけにある要因（駅前は1店）を説明変数に足すと、その店の残差は必ず0 になり、要因の分と店の働きの分は分けられない。創造の場面は、ほかの単元の創造（表彰・評価）や解釈の例（駅前・改装）と同じにしない。2本の回帰直線（y を x で・x を y で）を図で比べるときは、見た目の傾きでなく係数で言う（x を y で回帰した直線は、図では立って見える）。閉じた店のように別の時期・別の物差しの値を足すときは、同じ物差しで比べられるとみた前提を書く（U29）
- 単元の本文（初学〜転用）の決まり文句も、概念と同じ言い方にそろえる（重回帰の「ほかの変数を一定にしたとき」→「ほかの変数が同じ値どうしで比べたとき」。試験の言い方は1か所で添える）。ラボの数を本文に書くときは、ラボが表に出す丸め方（差は丸める前の平均どうしの差）で書く。特別な日が絞った群に入るなら、その影響を添える。発展・創造の中心を、あとの単元（U32 の無作為化・交互作用）と同じにしない。手前で置くなら、その単元の方法に固有の判断（重回帰に何を並べるか：交絡・通り道・精度を上げる変数）に絞る（U30）
- 創造の「統計で言えること」で、係数の確かさを言う前に t を計算し、係数ごとに書く（「どれも標準誤差が大きい」とまとめない）。ダミーを並べた係数は、群ごとの差をならした値で、相手が1日しかない比べに頼ることがあるので、群ごとの差を添える。説明変数の値が群でほとんど重ならないなら「同じ値どうし」と言わず、直線の当てはめに頼ると書く。課題の選び肢に探究で読ませる数を書かず、判断の材料にトグルの中身を出さない（トグルを指す）。ラボの表示の文も本文と同じ言い方にし（「一定にしたとき」「1あたりの変化」を使わない）、set の値がつまみの範囲に入るように単位を選ぶ（客数を百人に）（U30 の2回目）
- ラボの固定のデータの癖を、一般の決まりとして本文・概念に書かない（地域の差0 で集落が単純無作為の0.63倍になったのは、固定の並びの偶然）。固定の並びを選ぶときは、条件を外した所（差0）で方法どうしがそろうことを先に確かめる。手で出せない小数の倍率は予測させず、「大きい・ほぼ同じ・小さい」の選び肢にする。偏りを決めるのは回答率の差ではなく比。重みの大きい例では、なぜその人の選ばれる確率が低いかを1文書く。発展と創造で同じ中心（回答率の違い）を重ねず、創造はその単元の方法に固有の問い（何を1つと数えたか・選んだ単位の数・届く集まりの段）にする（U31）
- 創造の場面を決める前に、手前の単元の発展・創造の場面と仕組み（U01 の数える単位、U17 の名簿と両端、U21 の選ばれやすさの逆数の重み）を一覧で当て、同じ仕組みを中心にしない。重みの例では、段ごとの選び方（店は売上に比例、店の中は同じ割合）を書いて、客1人の確率が違う理由を閉じる。ネイマン配分など「最もよい」と言う主張には、費用が層で同じなどの前提を添える。前提の行（「全員が答えたとみて」）の下に、その前提を外した話を混ぜない（U31 の2回目）
- ラボの結果欄に決まりを言う注（「2倍にすると4倍」「ブロック化でばらつきも小さく」）を置かない。予測・法則を見つける版で、次の段の答えを先に見せる。「同じになるか」を確かめさせる値は、ラボの中で別々に計算する（全体の平方和を群間＋群内と書くと、いつも同じで発見にならない）。1つのつまみに2つの意味を持たせない（「くり返し」が、別の店を足すことと同じ店を何日も数えることの両方に読める）。創造の課題の枠（報告に1つ載せる×ア・イ・ウ）を、続く単元で同じにしない。その単元の方法でしか出ない判断（次の実験の設計）にする。交絡のような定義の要件に「処理の前に値が決まる」を落とさない（処理の結果で変わる量は通り道）（U32）
- 発展の問いを、ほかの単元の発展を統計量だけ替えた形にしない（U25 の「同じ t でも中身が違う」→ U32 で「同じ F でも」）。その統計量に固有の内訳（F なら、どの群がずれたかが消える）を問う。ある仮定だけを外す反例に、別の崩れ（処理と時期の交絡）を混ぜない（U32 の3回目）
