# 横展開の手順書（R3。#172）

新しい概念を「発見の環境」に載せる順番と、各段を閉じる確かめ方。2つの実例から書いた：二項分布（式で決まる分布。R1・#171）と期待値（表で決まる分布。R2・#119）。

この文書は**順番と完了の確かめ方**だけを書く。意味の判断は製本（docs/rules/）、決まりは CLAUDE.md、書き方（記法・YAML の形）は docs/authoring.md にある。ここに中身を写さない。

## 0. 始める前

- 作業の issue を作り、読む製本（CLAUDE.md の製本の表）と、つながり（前提の issue・親）を書く。
- 対象の概念と、その単元の今の数を `python3 build/progress.py` で見る（人の記憶で決めない）。
- 新しい形（型の項目・画面の部品）を足すのは、下の段で要ると分かったときだけ（roadmap 9 の「止めること」）。

## 1. 概念：骨格 → 説明あり

製本 ①（同一性・姿）、③（成立条件）、式があれば ②。書き方は authoring「概念データの書き方」「製本の形で書く」「成立条件の区分」。

1. 1つの概念にするかを ① の 2 で決める（別の語に分けるか・同じ名前で呼ぶ別の形か）。
2. 姿（`forms`）を ① の 3 で決める。記述の道具はデータを固定して見る（#342）。2つの姿は、偶然の側の姿が ⑤ の線の端になるときだけ。
3. 確率分布は確率関数・確率密度の式を基準の定義にする（`basis_formula`）。定義1文（`short`）は学ぶ人向けの導入のまま。
4. 説明あり：`principle`・`conditions`（math と data。行ごとに区分）・`example`・`counterexample`・`misconceptions`・`sources`・`version`。数があれば `checks`。
5. 概念のページの元（R1c。#188）：`question`（問い）・`gist`（つまり）・`chart`（その場で描く図）・`figures`・`labs`。ページの見せ方は画面の側で直すので、ここでは原本の項目だけをそろえる。

閉じる確かめ：build が通る（必須の項目・区分・孤立）。① の確かめ方で、check-pairs.md の組を振り分け直したか。

**実例から（W1 の U10・U11。2026-11-15・16）**：独立な監査役で毎回直した型。書く前に当てる。
- 命題の概念（加法定理・乗法定理など）の条件は「仮定」にして claim（④）を書く。対象の要件（P(A)＞0 など）はその対象の概念の側に書き、命題に重ねない
- 反例は、その条件を外したときに、定義が決まらない・式が誤る場面を示す（条件を満たしたまま「別の誤り」をする例は誤解へ）
- 概念の基準の定義が式なら `basis_formula`。式が「定義」でなく公理などから導く等式なら、述語の概念の側に置く（余事象の確率は確率の式）
- 誤解は1つの概念にだけ置く（同じ誤解が関係の文にもあれば、概念の側は別の誤解にする）

**実例から（W3 の U17。2026-11-16）**：
- 要件を書いたら、その概念の基準の定義（basis）が許すもの（重複・復元抽出・集落）と、一種の関係の子（集落抽出など）が、その要件を満たすかを当てる。狭すぎる要件は、自分の定義と子の概念を外してしまう
- 主張の主語の概念が許すもの（枠の重複・戻す選び方）を、主張の条件に書いたかを当てる（CLM-40 の包含確率 n/N は、重複がなく戻さないときだけ）
- 製本で決めた扱い（① 6-6：確率が分からない取り方でも標本分布・偏りは「ある」が求められない）と、要件の outside（「定まらない」）を食い違わせない
- 定義1文・例・原理は basis より強く言わない（basis が「変わりうる」「〜のとき」なら、そのまま残す。U18 の統計量・標準誤差）。確率変数の分散・ばらつきを言う所は大文字（X̄）で書く（② 4）
- 仮定の行の outside には、前の単元で学んだ取り方でのずれも書く（独立が崩れる向きは1つではない。戻さずに取ると X̄ の分散は小さい）
- 一致の理由を「偏りが0に近づく」だけで書かない。偏りとばらつきの両方が縮むこと（正規母集団など、ばらつきが縮む条件も）を書く（U21 の v の一致）
- 比べ方の注意（同じ母数の値で比べる）を要件の行にしない。要件は定義が成り立つための条件だけで、比べ方は principle か data に書く。要件と仮定で、一方が他方を含んで outside が起きない組を作らない（U21 の MSE）
- 近似の作り方（割合の p̂±z×SE など）について、「信頼係数が 1−α に近づく」と書かない。近づくのは母数の値を1つに固定したときの被覆確率だけで、信頼係数（下限）は別（④-19。U22 の区間推定・信頼係数）
- 信頼区間の図で、x̄ を中心にした分布の曲線に区間を塗らない（「μ が95%の確率でこの区間にある」という図になる）。区間は横の棒と点推定の点で描く（U22 の解説の図・場面 mean）
- 「〜のときだけ有利」と条件を言い切る前に、境目を計算する（対応ありがウェルチより狭くなるのは、10店なら相関が約0.14を超えるときで、「強く連動するときだけ」ではない。U23）

**実例から**：期待値の B-01 で、大数の法則（TERM-lln）の説明を問いの前に書いた。問いの考察の文（条件「分散が有限なら」）と概念の `conditions` を同じ主張（④ の CLM-）から写すと、言い方がずれない。

## 2. 関係・主張・学ぶ順

製本 ⑤（関係）、④（主張・導出）、⑥（学ぶ順）。書き方は authoring「関係図に移す」「学ぶ順」。

1. ⑤ の判定の順（定める → 一種・特別な場合 → 移る → 比べる → 線にしない）を全部当てる（#336）。線にしない判定も check-pairs.md に残す。
2. 移る・比べる・導ける・特別な場合に `gist` と図（`figures`）。移る・比べる・導けるに解説（tour）と確かめるラボ。
3. 前提知識は関係に書かず、learning.yaml の足すに理由の1文と書く。

閉じる確かめ：build（関係の種類・区分・学ぶ順の輪）。関係図の警告（図のない関係）がその分類で0。

## 3. 式

製本 ②。書き方は authoring「式の分解の木」、CLAUDE.md「問題・式の決まり」。

1. 式は木で書く（`tex` を書かない）。記号に `of`・`domain`。1式＝1つの等式の連なり。
2. 全部の式に契約（content/formula-contracts.yaml）。
3. 代表の式は、書いた側でない独立なレビューの記録（content/formula-reviews.yaml。指紋つき）。

閉じる確かめ：build と `python3 build/formulas.py --publish-check`。直したら authoring「直したら一緒に直すもの」の式の行。

## 4. 作業台

決まりは math-lab の CLAUDE.md「作業台の型」。

- 式で決まる分布 → 概念の `workspace`（二項分布）。表で決まる分布 → `table_workspace`（期待値）。
- どちらにも合わなければ、先に型にパターンを足す（例：連続分布は3つ目のパターン）。概念の好みで欄を変えない。

閉じる確かめ：knowledge-net の作業台のテスト（欄ごとに同じ確かめ方を両方のパターンに当てる）に、その概念が入る。

## 5. 問い

製本 ⑦。仕組みは CLAUDE.md「実験室」。

1. テーマ体系（まとまり：分布の形と仕組み・事象と確率計算・理論と実験・期待値と分散・前提条件と反例・応用など）を先に作り、どの画面に並べるかはあとで決める。
2. 問いは発見させたい性質の数だけ。主は発見させる性質で、関連は理解に実際に使う概念だけ。似た問いがあれば重複の判断（⑦ の 1）。重なるなら統合し、片方を `retired: true`（期待値の B-02 を B-01 にまとめた）。
3. 問いごとに：予測（画面に見えている物か具体の数で。答えは書かない）・操作・観察（見る所だけ）・考察（理由と、題の問いへの答え）・応用（別の考え方）・`judge`（理解判定。性質の文を先頭に）。
4. 頻度と目安の文は ⑦ の 2 の型（今の回数・0% に丸めない・範囲を下限と読ませない）。量の名前・単位・数える語はテーマごとに1か所で決める（⑦ の 4）。
5. 応用は、見当で選べる選び肢をなくす。反証の二択は答えを偏らせない（⑦ の 3）。

閉じる確かめ：⑦ の 5 を全部当てる。

## 6. 実験の仕組みと画面

- 既存の問いの形（`open` の部品）で足りるかを先に見る。足りなければ型（kn-experiment）に任意の項目を足し、改訂を上げる（knowledge-net の CLAUDE.md の 2）。
- 反例は「成り立つ条件を外す実験」だけを反例の欄に置く（#369）。5つの条件をそろえ、崩す条件は1つ。
- 新しい画面（実験室）が要るかは、5 と ここのあとで決める。
- 画面の部品を足したら、knowledge-net の docs/decisions.md に決定（どの原則から・前提・根拠・見直す条件）を書く。

閉じる確かめ：engine の性質のテスト（同じ種なら同じ・理論に近づく・境目）と、画面のテスト（問いの流れ・テーマで答えの位置が変わる）。大事なテストは、わざと入れた誤りで落ちることを確かめ、テストのコメントに書く。

## 7. 独立に読み直す

書いた側が自分で確かめるだけで閉じない（2026-11-14・11-15 の実例では、毎回ここで直す所が出た）。

1. ⑦ の監査役（問いの設計：重複・粒度・応用の考え方・照らしの頻度）。数の言い分は、監査役が別の道（独立な計算）で検算する。
2. 概念・関係を変えたら ①③④／⑤ の監査役。
3. 学習者役（画面を上から順に読み、「分からなくて止まる」「引っかかる」を挙げる）。
4. 指摘は点で直さず、ほかの問いでも起きる型か、一度だけかに分ける。型は製本か authoring に入れ（変更の入口）、一度だけはその場で直す。直したら、同じ言い方が出る所を grep してから閉じる。

## 8. 公開

1. 型・画面を変えたら、knowledge-net を先にマージ・公開する（CLAUDE.md「データの意味が変わる公開は、画面を先に公開する」）。
2. 教材を main から公開する（authoring「公開」）。
3. knowledge-net の見本を取り込む（`node scripts/sync-sample.mjs --update <labs の sha>` と `cd math-lab && node scripts/sync-stats2.mjs --from <教材>`）。見本の数や中身に頼るテストを直し、`npm run check` を通す。

## 9. 単元へ戻す

roadmap 10 の共通の完了条件を、その単元に当てる。

- 問題に `concepts:`（解く・解説を理解するのに要る概念・関係・主張だけ）と `concepts_linked: true`。
- 問題に付けたラボの予測・課題の文を ⑦ の 2「単元の問題のラボ」（型 A〜E）に合わせる（#373 の表のその単元の分）。
- 初学に概念図、復習の「図を再現する」はその手本で。
- 発展・創造は ⑧ の形（予測の照合を置かない。「1つの考え方の例」）。

**実例から（W3 の U17）**：
- 創造の「統計で言えること」は、どの範囲について言えるかを段に分ける（送った人・抽出枠・母集団）。1つの範囲の結論を、広い範囲の結論として書かない
- 解釈の向き（高め・低め）は、「誰が抜けたか → 抜けた人の値は大きい側か小さい側か → だから手元の値は」と1段ずつ書いて確かめる（U17 の未回答で、向きを逆に書いた。独立な読み直しでも見落とされた）
- 発展の課題文が、使うラボのモードが実際に出す値で見られるかを、ラボの値の一覧（tool.yaml の values）と照らす。式の値とラボの値がいつも同じなら、比べさせても発見にならないので、学ぶ側が自分で計算する量を残す
- 問題の concepts は、答えの解説を1行ずつ読んで、使っている概念を全部拾う（標準化・独立・差の分散など、単元の主役でない概念も。U18 で 4問の漏れ）
- 初学のラボの予測の数は、同じ節の問い・例題・概念図に出ていない数にする（U18 の s1-se は、予測の前に答えの 2g が3回出ていた）
- 種が固定のラボ（押すたびに同じ結果）で「何度押しても」「回数を増やすと」と書かない
- 解釈の向きは、仕組みの1段も抜かずに書く（「まとめて応募 → 当たり外れがまとまる」では足りない。1口ずつ独立に抽選するなら、まとめて応募しても独立は崩れない。U19）。解釈には、データの生まれ方の一番素直な読み方（数が回ごとに違う・確率そのものが変わった）を入れたかを当てる
- 要件の行の outside は「〜に従うとは限らない」「この作り方では作れない」で書き、「従わない」「定義されない」と言い切らない（たまたま同じ分布になる組み方・ほかの所で使う一般の形〔ウェルチの整数でない自由度〕がある。U20）
- 移るの段で、1つの点（5%の点）がそろったことから分布がそろうことを言わない。分布がそろう理由（定義の形）を先に書き、点の一致はその帰結として書く（U20 の t→F）
- 版の set・解説の段の値が、ラボのつまみの刻み（step）に乗るかを当てる。乗らないと値が丸まり、文と画面の数がずれる（U20 の F で s₁²＝5.117 が 5.0 に丸まった。探究の s＝3.93 は入れられない）
- 数表で出せない確率（t・カイ二乗の p 値など）は、数でなく「0.05 より小さい／大きい」の選び肢で予測させる（⑦ の 2 の B）
- 発展・創造の主張にも前提を添える（「返品率 1% なら」だけでなく「独立に起きるなら」。モデルで出した値を「本当の値」と呼ばない。U19）
- 発展と創造で同じ中心（例：答えた人と答えなかった人の違い）を扱わない。発展はその単元の「なぜ・何が消えるか・前提が崩れると」、創造は混ざったデータの切り分け
- 発展の「説明してみる」は、手前の段（初学・応用・転用・ラボの初期値）と同じ場面・同じ数・同じ結論にしない。同じ性質を、新しい見方（その推定量は何に一致しているのか）で問う（U21 の集め方の偏り → 滞在時間の長さで選ばれる偏り）
- 創造の課題で「必要な n は？」のように答えが1つに決まる計算を置かない（応用に置く）。創造に残すなら、計算に入れる数（どの日から s を取るか）を選ぶことと、その選び方が何で決まるかを切り分ける形にする（U21 の課題B）
- 発展の「1つの数で何が消えるか」と創造の探究で、同じ結論（使い道で推定量が変わる）に落ち着かせない。発展は数の内訳の性質（平均すると縮む分と縮まない分）に絞り、使い道の判断は創造に任せる
- 発展の節に、次の単元が2級の範囲として扱う中身（U23 の差の区間）や、別の単元の発展と同じ場面・数（U24 の多重比較の k＝20）を置かない。つながりとして「ほかでは？」で指すだけにする（U22）
- 創造の設計の課題（人数と集め方を決める）にも、選び肢を2つ以上と判断の材料、1つの考え方の例を置く。報告に添える項目は「統計で言えること」の見出しに入れない（U22）
- 初学のラボの選び肢の予測（約95%が含む）の答えを、同じ節の問い・概念図で先に言わない。信頼係数を変える（90%）など、見せていない設定にする。予測のあとに動かす選択欄は unlock に書く（U22 の s1-cover）
- 創造の探究の中心を、ほかの単元の創造と同じ型（2つの集団の比率 → 差の区間 → 解釈3つ）や同じ交絡（曜日とキャンペーン。U32）にしない。その単元の方法でしか出ない問い（U23 なら、どれと比べるかで差の区間が変わる）を中心にする（U23）
- 解説（tour）の段でモードを切り替えるときは、最初の段にもモードを書く（版の mode だけでは、ラボが前の段のモードのまま始まることがある）。段の文と「つまり」は、埋め込み（320px）に収まる長さにする（U23 の対応ありとウェルチ）

閉じる確かめ：`python3 build/progress.py` でその単元が全部 ✓、全部の確認が通った main から公開し、公開サイトから概念・関係・実験室を開ける。
