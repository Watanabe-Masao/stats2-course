# 製本への移行の計画書

2026-11-08。製本（docs/rules/）を判断の基準として採った（PR #257）。この計画書は、教材の原本・型・build・画面をその基準に移し、古い決まりを閉じる順を書く。移った状態の記録は docs/rules/migration.md、進み具合は追跡の issue（#259）に置く。

関係図の計画書（docs/relation-map-plan.md）の S6（横に広げる）・S7（v2）は、この計画書の M4〜M7 に置き換える。S1〜S5b は済んだ段の記録として残す。

## 移行の完了の条件

- 原本（関係・概念・導出）の全部の行が、製本の意味で書かれ、型 v2 の形で持たれている（migration.md 2 の対応表の全行で「移行の完了の条件」を満たす）。
- 型 v1 だけの種類（前提・応用・統合・特殊化）と premise が、型・build・画面から消えている。
- 意味の判断を書いた古い文書（関係図の定義書の 3〜5 など）が、製本を指すだけになっているか、旧版として閉じている。
- 照らしていない範囲（migration.md 4）が空になっている。

この計画書が保証するのは、移す順と、各段で何が済めば次へ進めるかが分かること。各段の判断の正しさは製本と、各段の確かめが受け持つ。

## 順番の考え方

1. **先に、判断の置き場を1つにする**（M1）。古い文書に意味の判断が残ったまま原本を移すと、移す人がどちらに従うか迷い、移したあとでも古い判断が戻ってくる。
2. **型を先に決め、原本はそのあと**（M2〜M4）。原本を先に直すと、型 v2 で書けない形を作ってしまい、もう一度直すことになる。
3. **原本は分類ごとに、見本から**（M5）。確率分布は S3・S5b で一度通したので、見本にする。全部を一度に移さない（今の計画書の進め方を引き継ぐ）。
4. **学ぶ順は関係のあと**（M6）。⑥ の候補は関係から求めるので、関係が移ってからでないと作れない。
5. **古い形を消すのは最後**（M7）。全部の分類を移すまで、型 v1 の行を読む仕組みを残す。
6. 問い（⑦）と本文（⑧）の照合は、型に依らないので、M2 以後いつでも並べて進めてよい（M8）。
