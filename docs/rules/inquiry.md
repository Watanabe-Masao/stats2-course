## 0. この本の器

- **答える問い**：学ぶ人に何を発見させ、何を操作・観察させ、何ができれば理解したとするか。
- **決めること**：下の節（1 から）
- 保証すること：学習目標・体験・判定が対応し、何を確かめたかが分かる。
- 確かめ方：5 に書いた。

保証しないことと、その引き受け先：

| 保証しないこと | 引き受け先 |
| --- | --- |
| 正解だけで深い理解を証明すること、長期の定着 | 全体でも保証しない |
| 実験結果だけで定理を証明すること | ④ |

## 1. 問いの単位

- 問いは、学ぶ人に発見させたい性質の数だけ作る。概念の数だけ作らない（CLAUDE.md #163）。
- 問いの主は、発見させたい性質で決める。2つの概念のつながりそのものを発見させる問いは、関係（⑤）を主にする。関連は、その問いを理解するのに実際に使う概念だけ（#169）。
- 同じ現象・同じ図でも、注目するもの（平均・散らばり・分布全体）が違えば別の問い。
- 同じ実験をして、同じ発見をして、同じ問題で理解を判定できるなら、別の問いにしない。言葉を替えただけの問いは作らない。

## 2. 体験の形（予測 → 実験 → 観察 → 考察 → 応用 → 比較）

- 予測は、答えが理論から決まる問いにだけ置く。発展・創造の段には置かない（答えの決まらない「説明する・切り分ける」形にする）。
- 予測は、予測の段の画面に見えている物か、具体の数で聞く。観察で初めて出る量・図・名前（±2SE・平均の線・独立など）では聞かない。名前は観察の段で付ける（2026-11-12。#372）。
- 予測1つに照らし1つ。予測で答えさせたこと（値・向き・選び肢）と、照らす粒度をそろえる。照らさない入力は置かないか「任意」と書く（2026-11-12。#372）。
- 問いの題・照らし・考察は、その問いで見つけることだけを言う。予測の答えを題で言わない。ほかの問いで見つけてほしいことは先に言わず、「→ その問い（○-○）で確かめる」と案内する。観察は見る所を指し、答えと理由は考察で言う（2026-11-12。#372）。
- 実験は、前の条件と変えた条件の両方を、同じ回数ずつ起こして比べる。
- 反例は、次の5つをそろえる（#118 の反例の方針。元は CLAUDE.md）。種類は「成り立つ条件を外す実験」「誤解を正す例」「指標の限界を示す比較」。
  1. 何を確かめるかを先に書く
  2. 比べる条件をそろえる
  3. 成り立つ範囲と、差が出ない端を示す
  4. 理論の関係と、実験のゆれを分ける
  5. 観察のあとの理解（どの分布・概念で考えるか）までつなぐ
- 反例の文章・実験の仕組み・比べる理論・検証が、同じ主張（④）を指すこと。主張は反例の concept と本文で言い、型に主張の欄は置かない（2026-11-11。#352）。
- 反例で崩す条件は1つ（2つ目の「比べる条件をそろえる」から。2026-11-11。#352）。
- 問いを持たない反例にも、理解の判定を置く（その実験室のテーマ体系に問いを1つ足して置く。2026-11-11。#352）。
- 実験の結果は、主張（④）の確かめであって証明ではない。

## 3. 理解判定

- 問いを作るときに、何ができれば理解したと判定するかを最低限書く。実験の目的と理解判定がずれないようにするため。
- 応用の段は、予測〜理由で練習したのとは別の考え方を求める（逆算・評価・設計・変換・反証・モデル選択など）。場面の言葉や数を替えて同じ計算をさせるだけにしない（#169）。
- 段階（初学・応用・発展・創造）で、身に付ける力と判定の形を変える（CLAUDE.md の段階の定義）。発展・創造の答えは「1つの考え方の例」で、正解にしない。
- 実験室の問いは、応用までの段（予測を置ける）として扱う（2026-11-11。#352）。
- 応用の課題だけが2つの問いで重なるときは、問いを統合せず、片方の応用を別の考え方に直す（2026-11-11。#352）。
- 応用では、2級の範囲の式を使ってよい。学ぶ人がその問いで発見していない式は、解き方の段で示す（2026-11-11。#352）。

## 4. 何を学ぶ人に見せるか

- 関係図・概念のページで、どの比べるを載せるか。取り違えやすさ（学ぶ人がよく取り違える組か）を理由として持つ（⑤ から移した判断）。
- 使い道（その概念を何に使うか）は、問いの本文や単元の本文で見せる（外した「応用」の行き先）。
- 学ぶ順（⑥）とは往復して調整する。問いや説明が使っている概念が、学ぶ順の前提知識の根拠になる。

## 5. 確かめ方（器の「確かめ方」の中身）

- 問いごとに、目標（発見させたい性質）・操作・観察・判定の4つがそろっている。原本では、目標＝finds、操作＝operate、観察＝predict で予測した量と open の画面で見る結果、判定＝judge（観察の欄は置かない。2026-11-11。#352）。
- 判定が、目標の性質を確かめている（別の計算の練習になっていない）。finds は予測の前に出さない短い見出しなので、性質の文は judge の先頭に書き、judge が説明・判断でその性質を確かめるかを見る（2026-11-11。#352）。
- 反例は 2 の5つがそろい、同じ主張を指している。
- 予測の文に、予測の段で見えていない量・図・名前が出ていない。照らしが予測と同じ粒度。題・照らし・考察が、予測の答えやほかの問いの発見を先に言っていない（画面の上の順に、問いの文 → 表・図 → 予測 → 選び肢 → 照らし を読んで確かめる。2026-11-12。#372）。
