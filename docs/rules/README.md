# 製本（判断の基準と、その判断が保証する範囲）の一覧

製本するのは、教材を作るときの判断の基準と、その判断が保証する範囲。章や機能ではなく、**何を判断する責任を持つか**で分ける（渡辺さん 2026-11-08）。

ここでいう保証は、「この本に従ったというだけで正しさが確定する」という意味ではない。何を確かめられれば、その範囲を満たしたと認めるかまでを定めること。

画面の配置・データの項目・保存の形・build は設計書へ、移す順・担当・期限は計画書へ置く。読みやすさ・操作のしやすさと、実装が製本に従っていることは、実物を別に確かめて初めて分かる。

## 8冊の責任範囲

| 製本 | 何を製本するか | 保証すること |
| --- | --- | --- |
| ① 概念 | 語が指すもの、同一性、対象の姿、文脈による役割 | 同じ名前・別名・文脈の違いを区別し、何について述べているかを特定できる |
| ② 式と記号 | 記号の意味、変数の範囲、式の読み方、定義式・等式・近似式などの区別 | 式が何を表し、各記号が何を指すかを曖昧さなく読める |
| ③ 成立条件 | 定義の要件、主張の仮定、適用の目安、その掛かる先 | どの条件のもとで何を主張しており、外れると何が保証されなくなるかが分かる |
| ④ 主張・定理・導出 | 主張の正確な内容、根拠、導出、各段階で使う条件 | 結論が何に基づき、どの範囲で支えられるかを追い、確かめられる |
| ⑤ 関係 | 概念の間の関係の意味、両端、向き、操作、参照する主張 | 線が何を意味し、何と何を結んでいるかを正確に読める |
| ⑥ 学ぶ順 | 学習目標に対する前提知識、順序、段階、前提を省ける範囲 | 指定した説明や課題が、まだ導入していない知識を暗黙に求めていないことを確かめられる |
| ⑦ 問い・実験・理解判定 | 発見させたいこと、操作、観察、問い、理解したと判断する証拠 | 学習目標・体験・判定が対応し、何を確かめたかが分かる |
| ⑧ 適用・解釈 | 現実の問いとモデルの対応、結果から言えること、判断への接続 | 計算結果・統計的主張・現実の解釈・意思決定を区別できる |

## 保証しないことと、その引き受け先

ある本が保証しないことは、別の本が引き受けるか、全体でも保証しないと明記する。

| 製本 | 保証しないこと | 引き受け先 |
| --- | --- | --- |
| ① 概念 | その概念についての主張の正しさ | ④ |
| ① 概念 | 学ぶ必要性 | ⑥ |
| ② 式と記号 | 等式や近似が成り立つこと、導出の正しさ | ④（条件は ③） |
| ② 式と記号 | 画面での読みやすさ | 設計書と、実物の確かめ |
| ③ 成立条件 | 現実のデータが条件を満たしていること | ⑧ |
| ③ 成立条件 | 条件を満たせば主張が正しいこと自体 | ④ |
| ④ 主張・定理・導出 | 現実への当てはまり | ⑧ |
| ④ 主張・定理・導出 | 学ぶ順 | ⑥ |
| ④ 主張・定理・導出 | 理解しやすい説明 | ⑦・設計書 |
| ⑤ 関係 | 線をたどれば学習できること | ⑥・⑦ |
| ⑤ 関係 | 線だけで根拠が説明されること | ④（⑤は ④ の主張と ③ の条件を参照する） |
| ⑥ 学ぶ順 | 唯一・最短・最良の順であること | 全体でも保証しない |
| ⑥ 学ぶ順 | その順なら誰でも理解できること | 全体でも保証しない（⑦ で理解を確かめる） |
| ⑦ 問い・実験・理解判定 | 正解だけで深い理解を証明すること、長期の定着 | 全体でも保証しない |
| ⑦ 問い・実験・理解判定 | 実験結果だけで定理を証明すること | ④ |
| ⑧ 適用・解釈 | モデルが現実を完全に表すこと、因果や施策の成功を無条件に保証すること | 全体でも保証しない |

## つながり方

依存は一直線にしない。

- ①② で、何について何を述べているかを定める。
- ③④ で、その主張の条件と根拠を定める。
- ⑤ で、裏付けのある関係を整理する。⑤ は ③④ を参照し、数学的な根拠を自分では作らない。
- ⑥⑦ で、学習目標に合わせて順序・体験・判定を組み立てる。⑥ と ⑦ は往復して調整する。
- ⑧ で、現実への適用と解釈の範囲を確かめる。

例：二項分布

| 判断する内容 | 責任を持つ製本 |
| --- | --- |
| 二項分布・成功回数・成功確率は何か | ① |
| X・n・p と確率関数は何を表すか | ② |
| どんな試行を仮定しているか | ③ |
| その仮定から、成功回数が二項分布に従うと言える根拠 | ④ |
| 成功回数と二項分布を「従う」でどう結ぶか | ⑤ |
| その説明の前に独立や組合せを学ぶ必要があるか | ⑥ |
| 何を操作・観察し、何ができれば理解したとするか | ⑦ |
| 売場での購入件数に当てはめてよいか、結果をどう読むか | ⑧ |

## 各冊に置く5つの項目

1. 答える問い
2. 決めること
3. 保証することと、その確かめ方
4. 保証しないことと、その引き受け先
5. 判断の例・反例・未決のこと

## 運用の決まり（2026-11-08）

この決まりが保証するのは、変更の根拠と影響を追え、旧い方針へ黙って戻ったことを見つけられること。将来の変更や誤りそのものをなくすことは保証しない。

1. **正本**：各判断の正本は、上の表で担当する製本1冊。ほかの本・CLAUDE.md・設計書は参照する。製本の外に正本がある判断は、段階の定義と考え方の枠組み（CLAUDE.md）、画面の原則（knowledge-net の CLAUDE.md）、作業台の型（math-lab の CLAUDE.md）。
2. **確定と未決**：確定には、判断・理由・適用の範囲・日付を残す。未決には、決まるまで使ってよい方針を「暫定」として書く。暫定は確定に数えない。暫定のない未決は、その判断をしない（作業を止めて決める）。
3. **変更の入口**：意味を変えるときは、次の4つを一組にして issue（アイデア・方針の変更）に出し、決まってから正本を直す。実装や教材から見つかった問題も、この入口で受ける（正本を変えることは禁じない）。実装の都合や1つの例への対応だけで、正本を直さない。
   1. 何が破綻したかを示す例・反例
   2. 正本の修正案と、その理由
   3. 影響する主張・条件・関係・教材・実装
   4. 前に確かめたことのうち、確かめ直しが要る範囲
4. **旧形式との対応**：[migration.md](migration.md)。製本を採った版と、教材・実装が移った状態は、別に記録する。移行中の例外は、対象と終了の条件を付けてそこに書き、一般の決まりに混ぜない。
5. **識別子**：主張は ④ の 6 の番号（④-25、④-28b）、確かめの組は check-pairs.md の番号で指す。条件は、主張の番号と、その主張の成立条件の行で指す。番号は変えない・消さない（使わなくなったら「外した」と残す）。ほかの本・文書から指すときは番号を書く。
6. **確認と版**：確認は、何を・どの版（コミット）で・どの範囲まで、を残す。確認したあとに変えた所は確認済みに数えず、変えた所とその直接の参照先を確かめ直す。ただし、次の表の直しは、確かめ直しを待たずに記録してよい（渡辺さん 2026-11-08）。条件は、確認済みを増やさず、数学的な内容と参照の意味を変えないこと。

   | 変更 | 確かめ直しを待たずに記録できる範囲 |
   | --- | --- |
   | 結果の転記・表記の統一 | 確認元（どの確かめが、どの版で）が特定でき、主張・定義・条件・根拠・参照先を変えない |
   | 状態を「未」（④ の §9 の状態）に下げる | 本文を変えず、確認済みの扱いを取り下げる。依存する箇所への影響も記録する |

   - 主張の範囲・定義・条件を変える直しは、例外にしない。範囲を狭める場合も、変えた部分は確かめる。
   - 例外で入れた直しは、使った表の行と確認元を、コミットの説明に書く（あとで、例外として入れた直しを見つけられるように）。
   - 「未にする」（保証の取り下げ）と「主張を狭める」（数学的な内容の変更）は分ける。
   - 「範囲外」にするのは教材での扱いを変える判断なので、例外にしない。
   - この例外は、それを足した変更（PR #257）には使わない。その変更は例外なしで確かめる。確かめ直しは回数ではなく、具体的な指摘を閉じることで終える。主張ごとの根拠の確認の状況は ④ の 9。
