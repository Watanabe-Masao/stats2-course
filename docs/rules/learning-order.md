# 学ぶ順のルール（学ぶ順の製本）

何を先に知っておくと、次の概念が理解しやすいか、の決まり。概念どうしの数学的な関係（関係のルール）とは別に持つ（渡辺さん 2026-11-08：関係図は概念の関係性を表すもので、学ぶ順ではない。学ぶ順は別で作る）。

## 1. 何を扱うか

- 扱う：**学ぶ人にとっての順**。ある概念を理解するのに、先に知っておきたい概念（前提知識）。
- 扱わない：
  - 概念どうしの数学的な関係（定める・一種・移る など）→ 関係のルール（docs/rules/relations.md）
  - 単元の並び・段階（初学・応用・発展・創造）の中身 → 教材の計画（course-plan・CLAUDE.md の段階の定義）

## 2. 前提知識

- **意味：** B を理解するのに、先に A を知っておくとよい。B の定義や主張に A の名前が出るとは限らない。
- **書くもの：** なぜ先に知っておくとよいかの1文（例：独立 → 二項分布「並び1つの確率を掛け算で出せる理由」）。
- **直接の1段だけ：** A → B → C なら、C は B だけを持つ。A は B をたどって出す。たどれば着く前提知識は重ねて書かない。
- **輪にならない。**

## 3. 関係のルールとの違いと使い方

| 関係のルール | 学ぶ順のルール |
| --- | --- |
| いつでも成り立つ数学的な関係 | 学ぶ人が理解しやすい順 |
| 定める・一種・導ける などの種類を持つ | 種類は前提知識の1つ |
| 学ぶ人や教材によらない | 教材・学ぶ人によって変わってよい |

- 関係（定める・一種・特別な場合・導ける）をさかのぼった順は、学ぶ順の**候補**になる。ただし同じではない。
  - 定めるの元でも、学ぶ順では後でよいことがある（直観で先に使える場合）。
  - 関係がなくても、学ぶ順では先に要ることがある（確率変数を知ってからベルヌーイ分布）。
- だから学ぶ順は、関係をさかのぼった順を土台に、学ぶうえでの前提知識を足し、要らないものを外して作る。関係のデータを学ぶ順に書き換えない。
- 成立条件の文に出る概念（独立など）は、成立条件の札として関係の側に出る。学ぶ順で同じ概念を前提知識にしてもよい（別の問いに答えるので、同じことを2か所に書くことにはならない）。

## 4. 単元・段階との関係

- 単元の並び（U01…）は、学ぶ順を大きくまとめたもの。単元の中の概念の順は前提知識と食い違わないようにする（食い違いは build が知らせる。止めるかは決める）。
- 段階（初学・応用・発展・創造）は、同じ概念の深さの順で、概念どうしの順ではない。

## 5. 画面

- 学ぶ順は、関係図・概念のページの関係のタブには出さない。
- 出し方（学習の道筋の画面・概念のページの「先に知っておくとよい概念」など）は、この製本のあとで決める。

## 6. 決めること

1. 学ぶ順を、教材に1つ持つか、学ぶ人の目的（検定まで最短・確率を丁寧に など）ごとに持つか。
2. 単元の中の順と前提知識の食い違いを、build で止めるか、知らせるだけにするか。
3. 画面の出し方。
