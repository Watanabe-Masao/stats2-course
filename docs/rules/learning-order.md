# ⑥ 学ぶ順（学ぶ順の製本）

何を先に知っておくと、次の概念が理解しやすいか、の決まり。概念どうしの数学的な関係（⑤）とは別に持つ（渡辺さん 2026-11-08：関係図は概念の関係性を表すもので、学ぶ順ではない。学ぶ順は別で作る）。①の上に立ち、⑤の関係を土台に使う。データ・build・画面での持ち方は、設計書と計画書で決める。

## 0. この本の器

| 項目 | 中身 |
| --- | --- |
| 答える問い | 学習目標に対して、何を先に知っておくと理解しやすいか。どの前提を省けるか |
| 決めること | 下の節（1 から） |
| 保証すること | 指定した説明や課題が、まだ導入していない知識を暗黙に求めていないことを確かめられる |
| 確かめ方 | 説明・ラボ・問いが使う概念が、学ぶ順でその前に来ているか（⑦ と往復する） |
| 例・反例・未決 | 5 の決めること |

保証しないことと、その引き受け先：

| 保証しないこと | 引き受け先 |
| --- | --- |
| 唯一・最短・最良の順であること | 全体でも保証しない |
| その順なら誰でも理解できること | 全体でも保証しない（理解は ⑦ で確かめる） |
| 学ぶ順の画面 | 設計書 |

## 1. 何を扱うか

- 扱う：**学ぶ人にとっての順**。ある概念を理解するのに、先に知っておきたい概念。
- 扱わない：
  - 概念どうしの数学的な関係 → ⑤
  - 単元の並びと、段階（初学・応用・発展・創造）の中身 → 教材の計画

## 2. 学ぶ順の作り方

学ぶ順は、次の3つを合わせたもの。

> 学ぶ順 ＝ 関係から求める候補 ＋ 前提知識（足す） − 外す

- **候補**：関係をさかのぼって求める（3 の表の向き）。学ぶ順の側には書かない。
- **前提知識（足す）**：関係にはないが、学ぶうえで先に知っておきたいもの。理由の1文を書く。
  - 例：独立 → 二項分布「並び1つの確率を掛け算で出せる理由」。独立は二項分布になる仮定で、確率関数の構成要素ではない。
  - 例：ヒストグラム → 確率密度関数「面積で確率を読む見方の土台」。
- **外す**：候補のうち、学ぶ順では先に要らないもの。組と理由を書く。
  - 例：直観で先に使える構成要素は、外してよい。
- 関係のデータを、学ぶ順のために書き換えない。
- **直接の1段だけ**：A → B → C なら、C は B だけを持つ。たどれば着く前提知識は重ねない。重ねと輪は、合わせた学ぶ順で調べる。
- 成立条件の文に出る概念（独立など）は、成立条件の札として関係の側に出る。学ぶ順で同じ概念を前提知識にしてもよい。答える問いが違うので、同じことを2か所に書くことにはならない。

## 3. 関係の種類ごとの候補の向き

| 関係（from → to） | 先に学ぶ候補 | 理由 |
| --- | --- | --- |
| 定める | from（構成要素） | 構成要素を知らないと定義が読めない |
| 一種 | to（親） | 親の定義を満たすものとして区別するので |
| 特別な場合 | 候補にしない | 教え方で向きが変わる（ベルヌーイ分布は二項分布より先、標準正規分布は正規分布の後が多い）。教材で決めて前提知識に書く |
| 移る | from と、通す操作の概念 | 元の形と操作を知ってから行き先を読む |
| 従う | to（分布） | 分布を知ってから、何が従うかを読む |
| 推定する | to（母集団の数・関数） | 何を知りたいかが先 |
| 導ける | from | 前の主張から読む |
| 根拠 | from（定理） | 定理を知ってから手続きの根拠として読む |
| 同値・比べる | 候補にしない | 向きがない |
| 定理の点 | 前提の概念 | 前提を知ってから定理を読む |

## 4. 単元・段階との関係

- 単元の並び（U01…）は、学ぶ順を大きくまとめたもの。単元の中の概念の順は、学ぶ順と食い違わないようにする。
- 段階（初学・応用・発展・創造）は、同じ概念の深さの順で、概念どうしの順ではない。ただし、段階によって要る前提知識が違うことはある（二項分布の初学は独立だけ、発展は期待値の線形性も要る）。

## 5. 決めること

未決。暫定は、決まるまで使ってよい方針（README の運用の決まり 2）。⑥ の作り方（候補＋足す−外す）は M6（#266。2026-11-10）で build に入れた（build/learning.py。足す・外すの原本は content/learning.yaml）。


1. 学ぶ順を教材に1つ持つか、学ぶ人の目的ごとに持つか。暫定：教材に1つ。目的別（検定まで最短など）はその中の道筋として選び出す（レビューの意見）。
2. 前提知識の強さ（必ず要る／あるとよい）を分けるか。暫定：分けない（必ず要るものだけ書く）。
3. 段階ごとに前提知識を持てるようにするか。暫定：持たない。
4. 何を根拠に前提知識とするか。暫定：その概念の説明・ラボ・問いが実際に使っていること。
5. 別の教材の概念を前提知識にできるか。暫定：しない。
6. 単元の中の順との食い違いを止めるか、知らせるだけにするか。暫定：判断しない。M6 でも止めも知らせもしない（原本の概念の単元は、その概念が初めて出る単元で、学ぶ単元とは限らないので、食い違いを機械で数えると誤りが多い。学ぶ単元を概念に持たせるかと一緒に決める）。
7. （決めた。渡辺さん 2026-11-10、#266・#327）合わせた学ぶ順に輪を作る候補は、⑥ の 3 の向きはそのままにして、組ごとに外す（理由の1文）。要るなら代わりの前提知識を足す。判断：推定する（ヒストグラム → 確率密度関数）の候補を外し、ヒストグラム → 確率密度関数 を足す（面積で確率を読む見方を先に持つ）。移る（順列 → 階乗。k＝n）の候補を外し、階乗 → 順列 を足す（U09 は階乗から入る）。M6 で同じ形の輪がほかに2組あり、同じく外した：移る（t 分布 → 標準正規分布。極限）は標準正規分布が t 分布の定義に使われるので、従う（不偏分散 → カイ二乗分布）は不偏分散がカイ二乗分布なしに標本平均から定まるので。理由：⑥ の 3 の向きは、関係を読む順の一般の形で、1つの組の教え方で表を変えない。範囲：合わせた学ぶ順の輪だけ（build が止め、外すを書くまで通らない）。

8. 命題の姿の概念（大数の法則・中心極限定理・加法定理・乗法定理・ベイズの定理など。① の 3）の基準の定義に出る概念を、候補にするか（3 の表の「定理の点：前提の概念」は導出の点だけを指していて、命題の概念は候補を持たない）。暫定：候補にせず、要るものを足すで書く（理由に「基準の定義が使う」）。候補にするなら、画面の型の via に概念の id を許す改訂が要る（#345）。
