## 最終ゴール（完成の条件）

どれも build・テストで確かめられる形にする。

1. 用語114語すべてに概念データ（定義・成立条件・具体例・反例）がある。
2. どの概念も関係でつながり、孤立した概念がない。
3. 全問題に、確かめる概念か関係が書いてある。
4. 教材の用語のリンクがすべて知識ネットワークを指し、ネットワークから全単元・全問題へ戻れる。
5. 全単元に概念図があり、発展・創造が新しい定義（CLAUDE.md「段階の定義」）の形になっている。
6. 旧版がすべて削除されている（`publish/legacy.yaml` の全項目が deleted）。
7. 個人の記録が KSLP の形（概念別・関係別の理解状態）で記録でき、ChatGPT で1回運用して確かめてある。

## 教材の側に置くデータ

概念・関係の原本は教材の側（このリポジトリ）に置く。データの型は知識ネットワークの側で決め、build がその型で検査して JSON を書き出す。

| データ | 中身 |
| --- | --- |
| 概念 | 用語を広げたもの。定義・原理・式・成立条件・具体例・反例・関連する単元と問題。ID は今の `TERM-…`（教材の中で一意。ネットワークでは `stats2:TERM-…`） |
| 関係 | 起点・終点・種類・説明・成立条件・根拠。別の教材の概念も指せる |
| 導出 | 複数の前提から結論が出るときの導出そのもの（独立した点） |
| 問題→概念 | 各問題が確かめる概念・関係 |

同じデータから、教材の中の用語リンク・比較のページ・単元の発展の「つながり」・概念図の説明を作る（同じことを2か所に書かない）。

## 軸の整理

- 6段階：学ぶ順番（いつ）
- 3つの力（式を読む・計算する・言葉にする）：問題で使う技能（どう）
- 5つの能力（理解・再現・識別・転移・統合）：概念・関係ごとの理解の状態（何が分かっているか）。個人の記録の側で持つ。未評価を0点として扱わない

## 横展開

単元のまとまりごとに、概念・関係のデータ、問題→概念、概念図、発展・創造の作り直し、用語リンクの切り替えを一度に行う（同じ単元を2回触らない）。

| 段階 | 単元 | 主な考え方の枠組み |
| --- | --- | --- |
| 準備（済） | 旧版の後始末・新しいホーム・削除の管理表・040 を応用へ | — |
| W0a | U13〜U16 の5〜8概念を、型の下書きで書いて build で検査する | 数理モデル |
| W0b（済） | 知識ネットワークの画面の最初の版（knowledge-net の PR #1） | — |

## 旧版の削除の条件

`publish/legacy.yaml` に、項目ごとの置き換え先と条件を書いてある。build が毎回状態を出し、削除済みの ID が戻ると止める。Notion の「旧版（削除予定）」ページも、この表から生成する。

| 旧版 | 削除の条件 | 時期 |
| --- | --- | --- |
| 確認問題（47問＋外に出した6ページ） | `REF-Q-…` の参照が0 | 準備（単元ページを公開し直してから削除） |
| 本番形式問題（15問） | 原本の問題に取り込み、`REF-PQ-DB` の参照が0 | W0 の後 |
| 混同しやすい概念（比較13組） | 13組すべてが関係「対比」になり、`REF-CONFUSION` の参照が0 | 遅くとも W5 |
| 統計用語辞典（114行） | 114語すべてに定義があり、旧版の用語ページへの対応が0 | W5 の終わり |
| 公式・用語リファレンス | 単元の「忘れたら」をネットワークに切り替え、`legacy_reference` が0 | W5 の終わり |
