# 型 v2 の設計書（#262 M2。案）

2026-11-08。製本（docs/rules/）の意味を、型（knowledge-net の kn-schema）でどう持つかを決める。移す順は docs/rulebook-migration-plan.md（M3〜M7）、v1 の種類との対応は docs/rules/migration.md 2。

**この設計書が保証すること**：製本の各冊が「決めること」を、型の項目として書く場所が1つずつあり、build がどの製本の決まりを止められるかが分かる。**保証しないこと**：書いた中身の正しさ（各冊の確かめ方と、独立な確かめ）、画面の見せ方（knowledge-net の設計と画面の原則）。

**決まったこと（渡辺さん 2026-11-08）**：型は v2 を1回で決め、原本は分類ごとに移す（P1）。関係図の画面は v2 の読み込みのあと（P2）。主張は型に足し、分類ごとに入れる（P3）。

## 0. 全体の形

v2 の教材の JSON は、今の concepts・relations・derivations・experiments に、claims（主張）と learning（学ぶ順）を足す。

| 集まり | 何を持つか | 正本の製本 | v1 との違い |
| --- | --- | --- | --- |
| concepts | 概念（語）。名前・定義・姿・基準の定義・定義の要件 | ①②③ | 姿（forms）を足す。成立条件のうち主張の仮定は claims へ移す |
| relations | 関係（線）。⑤ の10種類 | ⑤（条件は ③、主張は ④） | 種類の一覧を替える。種類ごとの項目（固定の仕方・通す操作・参照する主張）を足す |
| claims | 主張。本文・成立条件・根拠・検証の状況・教材での扱い | ④（条件は ③） | 新しい |
| derivations | 導出（前提が2つ以上の主張の導き方） | ④ | 結論を claims の主張で指す |
| learning | 学ぶ順の足す・外す | ⑥ | 新しい（前提 learning から移す） |
| experiments | 問い・実験 | ⑦ | 反例が指す主張を claims で指せるようにする |

## 1. 関係（relations）

### 1.1 種類

`type` の一覧を ⑤ の10種類にする：定める・一種・特別な場合・移る・従う・推定する・導ける・同値・根拠・比べる。

| 種類 | 必須の項目 | 任意の項目 | build が止めること（⑤ から） |
| --- | --- | --- | --- |
| 定める | — | — | to の基準の定義（① の basis。式なら basis_formula）に from が出ない（M4 で #86 の検査）。定義の依存の輪 |
| 一種 | — | — | 親が2つ以上。同じ組に定めるを重ねる |
| 特別な場合 | `fix`（固定の仕方：母数を値に・2つを等しく・個数を決める）と、固定の文 | — | fix の値が3つの外。同じ組を逆向きに書く |
| 移る | `mode`（exact・limit・approximation） | `operation`（通す操作：概念の id か文）、`theorem`（通す定理：主張の id） | 両端の姿が違う（1.3）。limit なのに行き先が族の一般の形（⑤ の 8 の規則1 は人が見る） |
| 従う | — | `theorem` | from が確率変数でない・to が分布でない |
| 推定する | — | `theorem`、性質（不偏・一致）の主張 | 端の姿が ⑤ の表と合わない |
| 導ける | `claim`（④ の主張の id） | — | 主張がない。主張の前提に from の端の命題がない（⑤ の帰結の「導けるの前提」の機械で見られる部分） |
| 同値 | `claim` | — | 同上 |
| 根拠 | `claim` | — | from が命題の姿でない・to が手続きの姿でない |
| 比べる | `axis` | — | 両端の姿が違う |

- 同じ組に関係は1つ。重ねてよいのは、包含（一種・特別な場合）＋移る と、比べる＋ほかの種類だけ（⑤ の 7）。build が止める。
- 成立条件（③）は、移るの行にだけ書ける（掛かる先が変換）。導ける・同値・根拠の条件は主張の側に書く（掛かる先が主張）。

### 1.2 v1 の種類からの写し

migration.md 2 の対応表のとおり。機械で写せるのは、材料 → 定める、種類 → 一種、一般化 → 特別な場合（fix は空で「未移行」）、変換 → 移る、対比 → 比べる。前提・応用・導出・特殊化は機械で写さず「未移行」として数える（M4）。

### 1.3 両端の姿

概念に `forms`（姿の一覧。① の 3：数・事象・確率変数・偶然で決まる区間・関数・分布・関数・演算・性質・命題・手続き）を持たせ、build が ⑤ の表の「from の姿・to の姿」と照らす。姿は排他的でない（① の 3）ので、どれか1つの姿が合えば通す。

## 2. 主張（claims）

④ の 7（主張の単位）の最小の項目を、そのまま型にする。

| 項目 | 型 | 中身 |
| --- | --- | --- |
| `id` | CLM-… | ④ の 6 の番号は `label`（④-25 など）に残す。id は消さない・変えない（README の運用の決まり 5） |
| `statement` | 文と、任意で式の木 | 主語・条件・結論。対象と変数の範囲 |
| `conditions` | 条件の行（③。掛かる先は主張） | 区分は仮定（主張の中の対象の要件は概念の側） |
| `grounds` | 主張の id・文献・導出の id の並び | 根拠。外部の結果は文献で持つ（`external: true`） |
| `verification` | 数学の確かめ（誰が・どの版で）・外部の結果の照合（照合済み／2次資料／未照合） | ④ の §9 を原本に移したもの。確認済みかは build が数える |
| `teaching` | 結論を扱うか・証明を扱うか（範囲外・出典に任せる） | 教材での扱い。受け継がない |
| `concepts` | 主張に出る概念の id | 「主張に使う概念」（#249 ②） |

- 定理（姿が命題の概念。中心極限定理など）は、概念のまま主張を1つ以上持つ（概念の `claims`）。
- 導出（derivations）は、結論を `claim` で指す。

## 3. 概念（concepts）

| 項目 | 変えること | 正本 |
| --- | --- | --- |
| `forms` | 足す（1.3） | ① の 3 |
| `basis_formula` | 今のまま。式でない定義の基準（文の定義）も書けるようにするか（D5） | ① の 2 |
| `conditions` | 掛かる先が「概念の定義」の要件だけを残す。主張の仮定（二項分布になることを保証する独立など）は claims へ移す | ③ の 2 |
| `role` | 足さない。役割（推定量・母数など）は関係から読む | ① の 4 |

## 4. 式（formulas）

#272（docs/rules/formula-check.md）の結果から。

| 項目 | 変えること |
| --- | --- |
| `statement_kind` | 足す。② の 1 の種類を1つ（定義式・等式・近似式・極限・分布の式） |
| 契約の `kinds` | 主題（変換・確率モデル・推定・判定）だけにする。定義・恒等式・近似は statement_kind へ |
| 記号の `kind` | 事象（event）を足す |
| 確率変数の範囲 | 案 A：確率変数の記号に台（domain）を書く。案 B：値の記号に `of` で確率変数を指し、範囲は値の記号に書く（D6） |
| 範囲を書かない記号 | 実数全体の母数・和と積分の変数は書かなくてよい、と型の説明に書く（D6） |

## 5. 学ぶ順（learning）

⑥ の「候補＋足す−外す」のうち、足すと外すだけをデータにする。候補は build が関係から求める（⑥ の 3）。

| 項目 | 中身 |
| --- | --- |
| `id` | LRN-… |
| `op` | add（前提知識を足す）・remove（候補を外す） |
| `from`・`to` | 概念の id（先に学ぶもの → 後に学ぶもの） |
| `reason` | 理由の1文（必須） |

- 前提（learning）38本は、op: add で写す（M6）。候補と重なるものは M6 で外す。

## 6. 移行の期間（M3〜M7）

- 型の版は `schema: kn-v2`。v2 の型は、v1 の種類（前提・応用・統合・特殊化・材料・種類・一般化・変換・導出・対比）を `legacy_type` として読める（移していない行）。
- build は、分類が移るまで v1 の行を `legacy_type` で書き出し、未移行として数える（progress.py）。移した分類（`ready`）の行に v1 の種類が残っていれば止める。
- 画面は v2 の種類を描き、legacy_type の行は今の見せ方のまま描く（M3）。
- M7 で legacy_type を型から外す。

## 7. 決めること

| | 決めること | 案 |
| --- | --- | --- |
| D1 | 主張を別の集まり（claims）にするか、概念の中に持つか | 別の集まり。関係・導出・実験が id で指せ、確かめの状況を原本で数えられる（④ の 7） |
| D2 | 姿（forms）を概念に持たせ、端の姿を build が止めるか | 持たせる。止めるのは移した分類だけ（v1 の行は止めない） |
| D3 | 特別な場合の固定の仕方を3つの値に限るか | 限る（⑤ の 4 の3つ）。合わないときは ⑤ の 8 の規則3 のとおり、規則を足す前に概念を見直す |
| D4 | 主張の仮定を概念の conditions から claims へ移すか | 移す（③ の 2 の掛かる先）。画面は概念のページに、その概念の主張の条件として出せる |
| D5 | 基準の定義が式でない概念（性質・手続きなど）の基準をどう持つか | `basis`（文の id か式の id）。今の basis_formula は式の場合として残す |
| D6 | 確率変数の範囲（案 A・B）と、範囲を書かない記号の約束 | 案 B（値の記号から of で確率変数を指す）。今の式の書き方（値の記号に domain）を変えずに済む |
| D7 | v1 の行を読む期間の持ち方（legacy_type） | 6 のとおり |
| D8 | 実験の反例が主張を指す項目 | 足す（⑦ の 2 の「同じ主張を指す」を build で確かめられる） |

## 8. 確かめ方

- M3 の完了の条件（v1 だけの見本と v2 だけの見本の両方を画面が読める）に向けて、見本の形をこの設計書から作る。
