# 型 v2 の設計書（#262 M2。案）

2026-11-08。製本（docs/rules/）の意味を、型（knowledge-net の kn-schema）でどう持つかを決める。移す順は docs/rulebook-migration-plan.md（M3〜M7）、v1 の種類との対応は docs/rules/migration.md 2。

**この設計書が保証すること**：製本 ①〜⑥ の「決めること」と、⑦ の反例・載せるか、⑧ の仮定を確かめる手掛かりに、型の中で書く場所が1つずつあること（9 の表で照らす）。build がどの決まりを機械で止め、どれを人の確かめに残すかが分かること。**保証しないこと**：⑦ の問いの単位・体験・理解判定の型（今の experiments の型のまま。引き受け先は ⑦ と #268）、⑧ の解釈の型（本文で書く。引き受け先は ⑧ と #268）、書いた中身の正しさ（各冊の確かめ方と独立な確かめ）、画面の見せ方（knowledge-net の設計と画面の原則）。

**決まったこと（渡辺さん 2026-11-08）**：型は v2 を1回で決め、原本は分類ごとに移す（P1）。関係図の画面は v2 の読み込みのあと（P2）。主張は型に足し、分類ごとに入れる（P3）。決めること D1〜D10 は 10 の表の「決定」のとおり。

## 0. 全体の形

教材の JSON は `version: 2`（今は `version: 1`。`schema` の値は "kn-schema" のまま）。集まりは次の6つ。

| 集まり | 何を持つか | 正本の製本 | v1 との違い |
| --- | --- | --- | --- |
| concepts | 概念（語）。名前・定義・姿・同一性・基準の定義・定義の要件・手続きの条件 | ①②③ | 姿・同一性の項目を足す。主張の仮定は claims へ |
| relations | 関係（線）。⑤ の10種類 | ⑤（条件は ③、主張は ④） | 種類の一覧を替え、種類ごとの項目を足す |
| claims | 主張 | ④（条件は ③） | 新しい |
| derivations | 導き方（主張を導く手順と、どの段でどの条件を使うか） | ④ の 5 | 文（statement）を持たず、結論と前提を claims の主張で指す |
| learning | 学ぶ順の足す・外す | ⑥ | 新しい（前提 learning から移す） |
| experiments | 問い・実験 | ⑦ | 反例が主張を指す（6） |

**役の分け方**（④ の 3、⑤ の 4・6）：
- 関係の端になれるもの（点）は概念。主張の中身は claim、導き方は derivation。
- 名前のある定理（中心極限定理）と、前提の命題が2つ以上いる主張は、姿が命題の概念（定理の点）と、その中身の claim の組で持つ。定理の点は、根拠・導けるの端になれる。
- 前提が1つの主張は、関係（導ける・同値・従う・推定する・根拠）が claim を指す。点は作らない。
- 3つ以上の概念・要因の関係（交絡・シンプソンのパラドックス・平方和の分解）は、概念か定理の点にする（⑤ の 6）。

## 1. 共通：条件の行（condition）

③ の 3 の「書くもの」を1つの定義にし、concepts・relations・claims から使う。

| 項目 | 中身 |
| --- | --- |
| `text` | 条件そのものの文 |
| `kind` | 要件・仮定・目安（③ の 1） |
| `target` | 掛かる先：definition（概念の定義）・procedure（手続き）・transform（変換）・claim（主張）。書く場所から決まらない所（概念の conditions）では必須 |
| `subject` | 何についての条件か（主語の概念の id か文） |
| `range` | 範囲：すべての値で要るか、ある値で足りるか（③ の 3） |
| `outside` | 外れたときに何が言えなくなるか（掛かる先ごとの意味は ③ の 2） |
| `approx` | 目安のとき：何の近似か・数の基準・どこまでの精度か |
| `sources` | 目安のとき：文献の根拠と数の確かめを別々に（③ の 3） |
| `terms` | 文に出る概念 |
| `data_hints` | 仮定のとき：現実のデータで確かめる手掛かり（⑧ の 2。条件ではない） |

- 書く場所と掛かる先：概念の conditions には definition（要件）と、姿が手続きの概念の procedure（要件・仮定・目安）。移るの関係には transform（仮定・目安）。claims には claim（仮定）。
- build は、掛かる先ごとに書けない区分を止める（③ の 2：definition に仮定・目安、claim に要件・目安、transform に要件）。
- v1 の写し：`target`（目安の対象の近似）は `approx` へ。`claim`（何を保証する仮定か）は、その仮定を claims の主張に移す（D4）。scope: data の行（kind のない手掛かり）は、確かめる仮定の行の `data_hints` へ。確かめる仮定がまだ移っていないものは、概念に `data_hints` として残し、未移行として数える（M5）。

- 役割（推定量・母数など）は持たない。関係から読む（① の 4）。

## 3. 関係（relations）

### 3.1 種類と項目

`type` を ⑤ の10種類にする。組（from と to）は向きを問わない。同じ組に関係は1つで、重ねてよいのは 包含（一種・特別な場合）＋移る と、比べる＋ほかの種類 だけ（⑤ の 7）。

| 種類 | 必須の項目 | 任意の項目 |
| --- | --- | --- |
| 定める | — | — |
| 一種 | — | — |
| 特別な場合 | `fix`（母数を値に・2つを等しく・個数を決める）と、固定の文 | — |
| 移る | `mode`（exact・limit・approximation）。limit のときは `claim`（④ の極限の主張） | `operation`（通す操作：概念の id か文）、`theorem`（通す定理：定理の点の概念の id）、`reversible`（逆向きもたどれる）、`use_form`（使う形：近似式の式の id と目安。C2 の暫定）、`conditions`（条件の行。target は transform） |
| 従う | `claim`（何が従うか・行き先の母数・厳密か極限か） | `theorem` |
| 推定する | `properties`（不偏・一致などの性質の主張の id。1つ以上） | `theorem` |
| 導ける | `claim` | — |
| 同値 | `claim` | — |
| 根拠 | `claim` | — |
| 比べる | `axis`・`same`（同じ所）・`differ`（違う所） | — |

- 従う・推定する・導ける・同値・根拠・移る（limit）の条件は、主張の側に書く（③ の 2 の掛かる先が主張）。
- 2つ以上の姿を持つ概念が端になるときは、`from_form`・`to_form`（その関係で使う姿）を必須にする（D2）。
- 画面の項目：v1 の `gist`・`labs`・`figures`・`chart`・`question`・`focus`・`stages` は、画面の項目としてそのまま残す（段ごとの見せ方）。意味の項目（比べるの same・differ、移るの operation）とは別に持つ。

### 3.2 build が止めること・人が確かめること

止めるのは、移した分類（7 の v2_ready）の行だけ。

| 機械で止める | 人の確かめに残す |
| --- | --- |
| 端の概念に姿がない（移していない分類の相手も含む。D2） | 移るの limit で、行き先が族の一般の形になっていないか（⑤ の 8 の規則1） |
| 端の姿が ⑤ の表と合わない（姿が1つならそれで、2つ以上なら from_form・to_form で照らす） | 定めるで、basis に出ても構成要素でないもの（⑤ の定めるの「構成要素にしないもの」） |
| 一種の親が2つ以上。重ねてよくない組の重なり（向きを問わない） | 特別な場合で、固定したあと同じものになるか（D3） |
| 特別な場合の fix が3つの値の外 | 導けるで、主張の前提が from の端の命題と ③ の仮定だけで足りるか（⑤ の 4 の帰結のうち、下の機械の分を除く） |
| 導ける・同値・根拠・従う・移る（limit）で claim がない。推定するで properties がない | 比べるの軸が、ほかの関係の条件で言い尽くせないか（⑤ の 7） |
| 定めるで、from が to の basis（式の記号の概念か basis_terms）に出ない | — |
| 導けるで、from が claim の premises にない。to が claim の conclusion にない。premises に from 以外の概念がある（前提が2つなら定理の点。役の分け方） | — |
| 定義の依存の輪。前提知識の重ねと輪（⑥ の 2） | — |
| 掛かる先ごとに書けない区分（1） | — |

### 3.3 v1 の行からの写し

- 機械で写すのは**型の名前だけ**：材料 → 定める、種類 → 一種、一般化 → 特別な場合（fix は空）、変換 → 移る、対比 → 比べる。意味が ⑤ に合うかは、M5 の分類ごとの作業で振り分け直す。機械の写しは M5 の作業の入力で、M4 の書き出しは legacy_type のまま（7）。
- 写した名前が ⑤ に合わないと分かっている行（確率分布の分類。どれも M5 の見本で直す）：
  - 一般化：REL-estimator-statistic（⑤ では一種）、REL-mean-expect（① の 2 の文脈の見出しで、関係にならない）
  - 変換：REL-binom-normal（⑤ では極限で、行き先は標準正規分布）、REL-t-normal（⑤ の 8 の規則1）、REL-binom-sampleprop（分布 → 確率変数で姿が違う）
- 前提（mathematical 107・learning 38）・応用 8・導出 4・特殊化・統合は機械で写さず、未移行として数える（M4）。
- v1 の `premise` は、learning なら learning（5）へ（M6）、mathematical なら定める・条件・主張へ振り分ける（M5）。関係の `derivation`（導出の点への参照）は、claim の grounds の導き方へ写す。

## 4. 主張（claims）

④ の 7 の最小の項目と、④ の 2〜4 の構造を持つ。

| 項目 | 中身 | 正本 |
| --- | --- | --- |
| `id` | CLM-番号（④-番号と同じ番号。D9） | README の運用の決まり 5・④ の 7 |
| `kind` | 主張の種類（等しい・従う・極限・ならば・同値・手続きの保証・推定量の性質・重なり） | ④ の 2 |
| `statement` | 1文（主語・条件・結論）と、任意で式の木。対象と変数の範囲 | ④ の 1 |
| `premises`・`conclusion` | 主張に出る概念を役ごとに（前提・結論） | ④ の 3、⑤ の 6、⑥ の 3 |
| `conditions` | 条件の行（1）。target は claim（区分は仮定。主張の中の対象の要件は概念の側） | ③ の 2 |
| `grounds` | 根拠：主張の id・文献（`external: true`）・導き方の id | ④ の 1・5 |
| `converse`・`counterexamples` | 逆の主張の id、反例の主張の id。逆が成り立つ条件は、逆の主張の conditions に書く（1か所） | ③ の 4、④ の 4 |
| `verification` | 数学の確かめ（どう確かめたか：独立な確かめ・数の確かめ・出典との照合、誰が、日付、版）と、外部の結果の照合（照合済み・2次資料・未照合）、中身の指紋 | ④ の 7・§9 |
| `teaching` | 結論を扱うか・証明を扱うか（範囲外・出典に任せる）。受け継がない | ④ の 7 |
| `version` | 1から。意味が変わる書き直しで1つ上げる（概念・関係・導出と同じ。CLAUDE.md） | — |

- **識別子の書き方**（D9）：④-番号の数字と枝をそのまま使う。④-25 → CLM-25、④-28b → CLM-28b、④-5a → CLM-5a、13の反例 → CLM-13-counter、13の逆 → CLM-13-converse。
- **確認済み**は build が数える（④ の §9 の数え方）。指紋は statement・conditions・grounds・premises・conclusion から作り、確かめたあとに変われば確認済みに数えない（README の運用の決まり 6）。運用の決まり 6 の例外（転記・表記の統一）と指紋の関係は #277 で決める。

## 6. 実験（experiments）

型は kn-experiment（芯とは別の改訂番号。CLAUDE.md の knowledge-net 1）。v2 の芯に合わせて、任意の項目を足す改訂にする（必須を変えない）。

| 項目 | 中身 |
| --- | --- |
| 反例の `claim` | 崩す主張の id（D8） |
| 反例の `breaks` | 崩す部分：向き（逆の主張か）・条件（どの条件の行か）。条件の行は、主張の conditions の何番目かで指す |
| 反例の `kind` | ⑦ の 2 の3種類：条件を外す実験（`condition_off`。元の主張の反例ではなく、その条件の行が要ることを示す）・誤解を正す例（`misconception`）・指標の限界を示す比較（`limit`） |
| 文章・実験の仕組み・比べる理論・検証の `claim` | 4つそれぞれに主張の id を持たせ、同じかを build が止める（整合の検査）。反例として本当に成り立つかは、数学・数の確かめで支える（機械では保証しない） |

- 比べるを学ぶ人に載せるか（⑦ の 4）は、この型に置く（D11）：概念のページの比べるの一覧の設定に `shown` と理由（取り違えやすい組か）を書く。⑤ の関係には置かない。

## 7. 移行の期間（M3〜M7）

- **画面**：v1 の JSON（`version: 1`）と v2 の JSON（`version: 2`）の両方を読む（M3）。
- **v2 の中の未移行の行**：v2 の型は、移していない行を `legacy_type`（v1 の種類の名前）で持てる。画面は legacy_type の行を今の見せ方で描く。
- **移した分類**：v2 用に `v2_ready`（分類の一覧）を新しく置く（D12）。今の `relation_map_ready`（v1 の関係図の決まりで移した分類。["確率分布"]）とは別。v2_ready の分類の行に legacy_type が残れば止める。
- **build**（M4）：v2_ready でない分類は、v1 の行を legacy_type で書き出す。M4 の完了の条件「今と同じ」は、legacy_type を v1 の type に戻し、v2 で足した項目を除いたときに、今の公開の JSON と一致すること、で比べる。未移行の行（前提 mathematical 107 を含む）を progress.py で数える。
- **終わり**（M7）：legacy_type・premise・basis_formula の書き出しを型から外す（D7。日数ではなく完了の条件で終える）。

## 8. 決めていない食い違い（C2）

④ の §6 の 5b（二項分布の正規近似。目安 np≧5）と 28b（適合度。目安 期待度数が5以上）は、主張の中に適用の目安を書いている。③ の 2 では、主張に書けるのは仮定だけで、目安の掛かる先は変換と手続き。② の未決2 の暫定（近似式は ④ の主張の中に「使う形」として持つ）とも合わない。

- **暫定**（決まるまで）：目安は、変換（移るの関係の conditions。5b は二項分布 → 標準正規分布の移る、limit）か手続き（28b は適合度検定の概念の conditions、target: procedure）に書く。使う形の近似式は、移るの `use_form` に書く。
- 決めるのは #278（③④② の食い違い）。

## 10. 決めること

**決まったこと（渡辺さん 2026-11-08）**：D1〜D10 は下の表の「決定」のとおり。D2・D3・D5・D6・D8・D9 には渡辺さんの補足を入れた。D11〜D13 は案のまま暫定（本文から指す所も暫定）。D9・D10 は製本の運用の決まり（README の 5・6、④ の 7）を変えるので、変更の入口の issue（#277）を通す。

| | 決めること | 案 |
| --- | --- | --- |
| D1 | 主張を別の集まり（claims）にするか | 決定：別の集まり。概念・関係・導出・実験から参照する。1つの概念に条件も根拠も違う複数の主張がある（標本平均の不偏と一致は別々に確かめる）ので、確認済みの範囲を主張ごとに持てる（④ の 7） |
| D2 | 姿（forms）を、129語の全部に必須にするか、移した分類だけか | 決定：移した分類だけ必須。ただし、移した分類の関係が、まだ移していない分類の概念を端にするときは、その相手にも検査に要る姿を書く（姿がなければ止める）。複数の姿を持つ概念が端になるときは、その関係で使う姿を `from_form`・`to_form` で確定する。全部を先に書かない理由：未整理の定義に合わせた仮の分類を後で直すことになる |
| D3 | 特別な場合の固定の仕方を3つの値に限るか | 決定：限る（母数を値に・2つを等しく・個数を決める。⑤ の 4）。固定の内容の文も必須。3つの値に入ったことだけで正しいとは判定せず、固定したあと同じものになるかは人が確かめる |
| D4 | 主張の仮定を概念の conditions から claims へ移すか | 決定：その主張を保証する仮定だけを移す（二項分布の「各回が独立」は、確率関数の定義の要件ではなく、成功回数が二項分布に従うという主張の仮定。③ の 2）。定義の要件・変換の条件・手続きの条件は、それぞれの場所に残す |
| D5 | 基準の定義を basis 1つにするか | 決定：basis に1つ（式の id か、定義の文）。文の定義では、直接使う概念への参照（`basis_terms`）も持つ。基準の定義と、学ぶ人向けの導入の文は分ける |
| D6 | 確率変数の範囲と、範囲を書かない記号 | 決定：式の中の確率変数の記号（X）に台（とりうる値の範囲。二項分布なら 0〜n の整数）を書く。値の記号（k・x）は X を指し、範囲を重ねて書かない。範囲は式ごとの文脈で持つ。範囲を書かない約束は明文化したものに限る。省略と書き忘れを区別して数える |
| D7 | 移行の期間の持ち方 | 決定：日数ではなく移行の完了の条件で終える。M3〜M6 は v1 の読み込みを残し、M7 で外す。v2 の中の未移行の行は legacy_type で区別し、移した分類に残れば build が止める |
| D8 | 実験の反例が主張を指す項目 | 決定：反例は、対象の主張と崩す部分を書く（「無相関なら独立」の反例は「独立なら無相関」を否定しない）。4つが同じ主張を指すかは build が止める（整合の検査）。反例が本当に成り立つかは、別に数学・数の確かめで支える。条件を外して結論が崩れた実験は、元の主張への反例と区別して記録する |
| D9 | 主張の識別子 | 決定：CLM-番号（④-番号と同じ番号。TERM-…・REL-… と表記をそろえる）。④-番号との対応を残す。採ったあとは id を変えない・使い回さない |
| D10 | 確かめの記録の正本 | 決定：移した主張は原本（claims.verification）が正本。中身が変われば古い確認を無効にする（指紋）。§9 に残すのは、移していない主張の記録と、製本の本文の確かめ |
| D11 | 比べるを学ぶ人に載せるかの項目（⑦ の 4） | 暫定：experiments の比べるの一覧の設定に置く（6）。⑤ の関係には置かない |
| D12 | 移した分類の印 | 暫定：v2 用に v2_ready を新しく置く。確率分布は M5 の見本で移すまで v2_ready に入れない（今の relation_map_ready はそのまま） |
| D13 | v1 の stages・premise・derivation の行き先 | 暫定：stages は画面の項目として残す（3.1）。premise と derivation は 3.3 のとおり |
