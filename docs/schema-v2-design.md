# 型 v2 の設計書（#262 M2。案）

2026-11-08。製本（docs/rules/）の意味を、型（knowledge-net の kn-schema）でどう持つかを決める。移す順は docs/rulebook-migration-plan.md（M3〜M7）、v1 の種類との対応は docs/rules/migration.md 2。

**この設計書が保証すること**：製本の各冊が「決めること」とする項目に、型の中で書く場所が1つずつあること（8 の表で照らす）と、build がどの決まりを機械で止め、どれを人の確かめに残すかが分かること。**保証しないこと**：書いた中身の正しさ（各冊の確かめ方と独立な確かめ）、画面の見せ方（knowledge-net の設計と画面の原則）。

**決まったこと（渡辺さん 2026-11-08）**：型は v2 を1回で決め、原本は分類ごとに移す（P1）。関係図の画面は v2 の読み込みのあと（P2）。主張は型に足し、分類ごとに入れる（P3）。

## 0. 全体の形

教材の JSON は `version: 2`（今は `version: 1`。`schema` の値は "kn-schema" のまま）。集まりは次の6つ。

| 集まり | 何を持つか | 正本の製本 | v1 との違い |
| --- | --- | --- | --- |
| concepts | 概念（語）。名前・定義・姿・同一性・基準の定義・定義の要件・手続きの条件 | ①②③ | 姿・同一性の項目を足す。主張の仮定は claims へ |
| relations | 関係（線）。⑤ の10種類 | ⑤（条件は ③、主張は ④） | 種類の一覧を替え、種類ごとの項目を足す |
| claims | 主張 | ④（条件は ③） | 新しい |
| derivations | 導き方（主張を導く手順と、どの段でどの条件を使うか） | ④ の 5 | 結論と前提を claims の主張で指す |
| learning | 学ぶ順の足す・外す | ⑥ | 新しい（前提 learning から移す） |
| experiments | 問い・実験 | ⑦ | 反例が主張を指す |

**役の分け方**：関係の端になれるもの（点）は概念、その中身の主張は claim、導き方は derivation。名前のある定理（中心極限定理）は、姿が命題の概念として点になり、中身を claim に持つ。名前のない、前提が2つ以上の主張（④ の 3）は claim だけで持ち、点にはしない（関係の端にならない。導出から指す）。

## 1. 共通：条件の行（condition）

③ の 3 の「書くもの」を1つの定義にし、concepts・relations・claims から使う。

| 項目 | 中身 |
| --- | --- |
| `text` | 条件そのものの文 |
| `kind` | 要件・仮定・目安（③ の 1） |
| `subject` | 何についての条件か（主語の概念の id か文） |
| `outside` | 外れたときに何が言えなくなるか（掛かる先ごとの意味は ③ の 2） |
| `range` | 目安のとき：何の近似か・数の基準・どこまでの精度か |
| `sources` | 目安のとき：文献の根拠と数の確かめを別々に（③ の 3） |
| `terms` | 文に出る概念 |
| `data_hints` | 仮定のとき：現実のデータで確かめる手掛かり（⑧ の 2。条件ではない） |

- **掛かる先**は、条件の行を書く場所で決まる：概念の定義の要件は concepts、手続きの条件は手続きの姿の概念、変換の条件は移るの関係、主張の仮定は claims。v1 の `target`（目安の対象の近似）は `range` に、`claim`（何を保証する仮定か）は書く場所（claims）に置き換わる。
- build は、掛かる先ごとに書けない区分を止める（③ の 2 の表：概念の定義に仮定・目安、主張に要件・目安、変換に要件）。

## 2. 概念（concepts）

| 項目 | 中身 | 正本 |
| --- | --- | --- |
| `forms` | 姿の一覧（① の 3 の10の中から1つ以上。名前と型の値は下の注） | ① の 3 |
| `basis` | 基準にする定義（1つ）：式の id か、定義の文 | ① の 2 |
| `aliases` | 別名（同じ意味の別の名前） | ① の 2 |
| `cases` | 対で初めて意味を持つ場合（片側・両側など） | ① の 2 |
| `heading_of` | 文脈の見出しのとき：共有する概念の id・対象の違い・文脈の違い（自分の定義を持たない） | ① の 2 |
| `alt_definitions` | 同じものを別の式で言う別の定義（式の id） | ① の 2 |
| `conditions` | 条件の行（1）。概念の定義の要件と、姿が手続きのときの手続きの条件だけ | ③ の 2 |
| `claims` | この概念が点になる主張（命題の姿の概念） | ④ |

注：① の 3 の姿は「数」「事象・集合」「確率変数」「偶然で決まる区間・関数」「分布」「関数」「演算」「性質」「命題」「手続き」の10。型では値を `number`・`event`・`rv`・`random_set`・`distribution`・`function`・`operation`・`property`・`proposition`・`procedure` にする。

- `basis_formula`（v1）は、`basis` が式を指す場合として写し、v1 の項目は M7 で外す。
- 役割（推定量・母数など）は持たない。関係から読む（① の 4）。

## 3. 関係（relations）

### 3.1 種類と項目

`type` を ⑤ の10種類にする。組（from と to）は向きを問わない。同じ組に関係は1つで、重ねてよいのは 包含（一種・特別な場合）＋移る と、比べる＋ほかの種類 だけ（⑤ の 7）。

| 種類 | 必須の項目 | 任意の項目 |
| --- | --- | --- |
| 定める | — | — |
| 一種 | — | — |
| 特別な場合 | `fix`（母数を値に・2つを等しく・個数を決める）と、固定の文 | — |
| 移る | `mode`（exact・limit・approximation） | `operation`（通す操作：概念の id か文）、`theorem`（通す定理の主張）、`reversible`（逆向きもたどれる）、`conditions`（条件の行。掛かる先は変換） |
| 従う | `claim`（何が従うか・行き先の母数・厳密か極限かを持つ主張） | `theorem` |
| 推定する | `claim`（推定の主張） | `properties`（不偏・一致などの性質の主張の id） |
| 導ける | `claim` | — |
| 同値 | `claim` | — |
| 根拠 | `claim` | — |
| 比べる | `axis` | `same`（同じ所）・`differ`（違う所） |

- 従う・推定する・導ける・同値・根拠の条件は、主張の側に書く（③ の 2 の掛かる先が主張）。
- 2つの姿を持つ端には、任意で `from_form`・`to_form`（どの姿として端に置くか）を書ける。
- v1 の `gist`（つまり）・`labs`・`figures`・`chart`・`question`・`focus` は、どの種類にも残す（画面の項目）。`stages` は、比べるの `same`・`differ` と、移るの元・操作・行き先に写す（3.3）。

### 3.2 build が止めること・人が確かめること

| 機械で止める | 人の確かめに残す |
| --- | --- |
| 端の姿が ⑤ の表と合わない（from_form・to_form があればそれで、なければどれか1つの姿で照らす） | 移るの limit で、行き先が族の一般の形になっていないか（⑤ の 8 の規則1） |
| 一種の親が2つ以上。重ねてよくない組の重なり（向きを問わない） | 定めるで、名前が定義に出ても構成要素でないもの（⑤ の定める。名前が出ることだけは機械で見る） |
| 特別な場合の fix が3つの値の外 | 導けるで、主張の前提が from の端の命題だけで足りるか（⑤ の 4 の帰結） |
| 導ける・同値・根拠・従う・推定するで、claim がない | 比べるを学ぶ人に載せるか（⑦ の 4） |
| 導けるで、from が claim の premises にない | — |
| 定義の依存の輪。前提知識の重ねと輪（⑥ の 2） | — |
| 掛かる先ごとに書けない区分（1） | — |

止めるのは、移した分類（6）の行だけ。

### 3.3 v1 の行からの写し

- 機械で写すのは**型の名前だけ**：材料 → 定める、種類 → 一種、一般化 → 特別な場合（fix は空）、変換 → 移る、対比 → 比べる。意味が ⑤ に合うかは、M5 の分類ごとの作業で振り分け直す。機械の写しは M5 の作業の入力で、M4 の書き出しは legacy_type のまま（6）。
- 写した名前が ⑤ に合わないと分かっている行（確率分布の分類。どれも M5 の見本で直す）：
  - 一般化：REL-estimator-statistic（⑤ では一種）、REL-mean-expect（① の 2 の文脈の見出しで、関係にならない）
  - 変換：REL-binom-normal（⑤ では極限で、行き先は標準正規分布）、REL-t-normal（⑤ の 8 の規則1）、REL-binom-sampleprop（分布 → 確率変数で姿が違う）
- 前提（mathematical 107・learning 38）・応用 8・導出 4・特殊化・統合は機械で写さず、未移行として数える（M4）。

## 4. 主張（claims）

④ の 7 の最小の項目と、④ の 2〜4 の構造を持つ。

| 項目 | 中身 | 正本 |
| --- | --- | --- |
| `id` | 識別子（D9） | README の運用の決まり 5 |
| `kind` | 主張の種類（等しい・従う・極限・ならば・同値・手続きの保証・推定量の性質） | ④ の 2 |
| `statement` | 1文（主語・条件・結論）と、任意で式の木。対象と変数の範囲 | ④ の 1 |
| `premises`・`conclusion` | 主張に出る概念を役ごとに（前提・結論） | ④ の 3、⑤ の 6、⑥ の 3 |
| `conditions` | 条件の行（1）。区分は仮定（主張の中の対象の要件は概念の側） | ③ の 2 |
| `grounds` | 根拠：主張の id・文献（`external: true`）・導き方の id | ④ の 1・5 |
| `converse`・`converse_conditions`・`counterexamples` | 逆の主張の id、逆が成り立つ条件（③ の 4 の4つ）、反例の主張の id | ③ の 4、④ の 4 |
| `verification` | 数学の確かめ（どう確かめたか：独立な確かめ・数の確かめ・出典との照合、誰が、日付、版）と、外部の結果の照合（照合済み・2次資料・未照合） | ④ の 7・§9 |
| `teaching` | 結論を扱うか・証明を扱うか（範囲外・出典に任せる）。受け継がない | ④ の 7 |

- 確認済みかは build が数える（④ の §9 の数え方）。主張の中身（statement・conditions・grounds）の指紋を verification に入れ、確かめたあとに変われば確認済みに数えない（README の運用の決まり 6。式のレビューの fingerprint と同じ仕組み）。

## 7. 移行の期間（M3〜M7）

- **画面**：v1 の JSON（`version: 1`）と v2 の JSON（`version: 2`）の両方を読む（M3）。
- **v2 の中の未移行の行**：v2 の型は、移していない行を `legacy_type`（v1 の種類の名前）で持てる。画面は legacy_type の行を今の見せ方で描く。
- **移した分類**：v2 用に `v2_ready`（分類の一覧）を新しく置く（D12）。今の `relation_map_ready`（v1 の関係図の決まりで移した分類。["確率分布"]）とは別。v2_ready の分類の行に legacy_type が残れば止める。
- **build**（M4）：v2_ready でない分類は、v1 の行を legacy_type で書き出し、build の結果（公開の JSON の中身）を今と同じに保つ。未移行の行（前提 mathematical 107 を含む）を progress.py で数える。
- **終わり**（M7）：legacy_type・premise・basis_formula を型から外す。
