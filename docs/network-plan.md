# 知識構造のネットワーク化：計画

KSLP 企画・基本設計書 Ver.1.0（2026-10-28）の第1〜2段階を、今のリポジトリの中で進める計画。2026-10-29 に合意。
進み具合は、各段階の PR と `publish/legacy.yaml`（旧版の削除の管理表）で追う。

## 最終ゴール（完成の条件）

どれも build・テストで確かめられる形にする。

1. 用語114語すべてに概念データ（定義・成立条件・具体例・反例）がある。
2. どの概念も関係でつながり、孤立した概念がない。
3. 全問題に、確かめる概念か関係が書いてある。
4. ネットワークの画面から全単元・全問題へ移動でき、教材の用語のリンクがすべてネットワークを指す。
5. 全単元に概念図があり、発展・創造が新しい定義（CLAUDE.md「段階の定義」）の形になっている。
6. 旧版がすべて削除されている（`publish/legacy.yaml` の全項目が deleted）。
7. 個人の記録が KSLP の形（概念別・関係別の理解状態）で記録でき、ChatGPT で1回運用して確かめてある。

## 原本に足すデータ

| データ | 中身 |
| --- | --- |
| 概念 | 用語を広げたもの。定義・原理・式・成立条件・具体例・反例・関連する単元と問題。ID は今の `TERM-…` を使う |
| 関係 | 起点・終点・種類（前提・導出・一般化・特殊化・変換・対比・統合・応用）・説明・成立条件・根拠 |
| 導出 | 複数の前提から結論が出るときの導出そのもの（独立した点として扱う） |
| 問題→概念 | 各問題が確かめる概念・関係 |

同じデータから、ネットワークの画面・用語と比較のページ・単元の発展の「つながり」・概念図の説明を作る（同じことを2か所に書かない）。

## 軸の整理

- 6段階：学ぶ順番（いつ）
- 3つの力（式を読む・計算する・言葉にする）：問題で使う技能（どう）
- 5つの能力（理解・再現・識別・転移・統合）：概念・関係ごとの理解の状態（何が分かっているか）。個人の記録の側で持つ。未評価を0点として扱わない

## 技術

| 用途 | 採用 | 理由 |
| --- | --- | --- |
| 画面 | React＋TypeScript＋Vite | KSLP の残りの画面（概念比較・再構築演習）まで同じ土台で作れる |
| ネットワーク | Cytoscape.js | 点と線の配置、拡大・移動、前提をさかのぼる表示 |
| 数式 | KaTeX | 概念の式の表示 |
| データの検査 | 原本側は build、画面側は Zod | 原本の参照の誤り・関係の種類は build が止める |
| テスト | Vitest＋Playwright | Playwright は今のラボのテストと同じ |
| 公開 | 公開サイト（stats2-labs）の `net/` | ラボと同じ流れで公開し、Notion に埋め込む |

- 画面のコードは stats2-course の `app/` に置く（データと画面を1つの PR で直せる）。stats2-labs は公開専用のまま。
- 後回し：Tailwind・shadcn/ui（見た目は今のラボの書き方に揃える）、Plotly・math.js（数理ラボの段階で必要になってから）。

単元のまとまりごとに、概念・関係のデータ、問題→概念、概念図、発展・創造の作り直し、用語リンクの切り替えを一度に行う（同じ単元を2回触らない）。

| 段階 | 単元 | 主な考え方の枠組み |
| --- | --- | --- |
| 準備 | 旧版の後始末・新しいホーム・削除の管理表・040 を応用へ | — |
| W0（MVP） | U13〜U16 確率変数・分布（5〜8概念）＋画面の最初の版 | 数理モデル |
| W1 | U09〜U12 数え上げ・確率 | 数理モデル |
| W2 | U01〜U08・U05T 記述統計 | 可視化学 |
| W3 | U17〜U23 標本分布・推定 | 解釈学（取り方）＋数理モデル |
| W4 | U24〜U27 検定 | 解釈学 |
| W5 | U28〜U32 相関・回帰・調査・実験 | 解釈学＋可視化学 |

W0 の後に、本番形式問題（15問）を原本の問題に取り込む小さなブランチを挟む。

## 旧版の削除の条件

`publish/legacy.yaml` に、項目ごとの置き換え先と条件を書いてある。build が毎回状態を出し、削除済みの ID が戻ると止める。

| 旧版 | 削除の条件 | 時期 |
| --- | --- | --- |
| 確認問題（47問＋外に出した6ページ） | `REF-Q-…` の参照が0 | 準備のブランチ（公開後に削除） |
| 本番形式問題（15問） | 原本の問題に取り込み、`REF-PQ-DB` の参照が0 | W0 の後 |
| 混同しやすい概念（比較13組） | 13組すべてが関係「対比」になり、`REF-CONFUSION` の参照が0 | 遅くとも W5 |
| 統計用語辞典（114行） | 114語すべてに定義があり、旧版の用語ページへの対応が0 | W5 の終わり |
| 公式・用語リファレンス | 単元の「忘れたら」をネットワークに切り替え、`legacy_reference` が0 | W5 の終わり |

## 040 の問題の扱い（2026-10-29）

2級の範囲表にある内容の問題は応用（S3）に移した（24問、U28 は先に移してある）。説明は「なぜその形か」なので発展に残し、「問題は応用に置いた」と書き添えた。
範囲表にない8問（U05 スタージェス・U05T 指数平滑・U06 トリム平均・U21 c₄・U22 ウィルソン・U30 交互作用・U31 総合誤差・U32 効果の平均）は発展に残す。予想→照合の形は、その単元の段階（W）で「説明する」形に直す。

## リポジトリの分け方

- 今は2つのまま：stats2-course（非公開。原本・build・ラボと画面のソース・テスト）と stats2-labs（公開。生成物だけ）。予想の答えや原本は外に出ない。
- 統計以外の分野を始めるとき（KSLP 14.1）に、分野に依らない「土台」（build の仕組み・labkit・画面・データの型）と、分野ごとの「中身」に分ける。
- その時に分けやすくするため、今から守る：画面は原本（content/）を直接読まず build が作る JSON だけを読む。概念・関係のデータの型は1か所にまとめる。
