# 品質基準（単元ごとに全部満たしてから公開する）

旧版を「移す」のではなく、この基準まで「引き上げる」。旧版の作り込み（例題・誤解・言い直し・仕事の場面）は全て残し、足りないものを足す。

段階の定義は CLAUDE.md「段階の定義」が元（ここはそれを満たしたかを見る一覧）。**移行が済んだことと、この基準を満たしたことは別**。満たしたかは `python3 build/progress.py`（Notion の「進み具合」）で原本から数え、横展開の各段階（#45〜#49 など）で引き上げる。

## 0. 共通

- [ ] ゴールは1文で、**できたかどうかを判定できる行動**で書く（「理解する」ではなく「〜を見分けて言える」）
- [ ] 冒頭は「ナビ＋ゴール＋タブ」だけ
- [ ] 表は2〜3列。スマホ幅で横にはみ出さない
- [ ] **全段階に図かラボが1つ以上**ある（段階ごとに使い方の指示が違う）
- [ ] 本文と問題の数値は全て `checks` で検算され、build が通る
- [ ] 旧版との突き合わせ（`build/audit.py`）で、落とした項目は全て理由付きで記録
- [ ] 用語は ID でリンク。単元は `{{unit:}}` で参照（番号を直書きしない）
- [ ] 定義・主張は教科書的に正確。条件付きで成り立つことは条件を書く（「必ず」「常に」を安易に使わない）
- [ ] 問題は難度順。易は1ステップ、中は2ステップ、やや難は条件判断か説明を含む
- [ ] 単元の用語に概念の説明があり、関係・導出につながっている（知識ネットワーク。CLAUDE.md「概念・関係・導出」）
- [ ] 各問題に、確かめる概念・関係（concepts:）がある

## 1. 初学（知る・理解する）

- [ ] 0｜入口の問い：実務の場面で、まだ解けない問い
- [ ] 1｜前提チェック：3問以内、答えと戻り先付き
- [ ] 2｜意味：判断の質問（❓）と図。図には「何を読み取るか」を添える
- [ ] 単元の中心を1枚で見せる概念図（2｜意味か3｜式の構造）。復習「図を再現する」の手本になる
- [ ] 3｜式の構造：記号・意味・この例の値の対応表。式を言葉で読む1文
- [ ] 4｜例題：全部解説 → 穴埋め → 自力 の3段
- [ ] 5｜実験：予想→操作→観察→説明→ラボなしで解く。答えは開閉
- [ ] 6｜自力確認：易・中・やや難の3問以上。力の印付き
- [ ] 7｜振り返り＋まとめ3行

## 2. 復習（定着させる）

- [ ] 翌日：思い出す3項目（答え付き）と図の再現（手本＝初学の概念図を示し、描いてから照らし合わせる）
- [ ] 言葉にする練習：説明の型・お手本（条件／対象と結論／根拠／成り立たない場合）・言い直し練習・取り違えやすい言葉・自己チェック
- [ ] 約1週間後：問い方を変えた別問と計算練習
- [ ] 約1か月後：他の単元と混ぜた問題
- [ ] 早見表、ラボで確かめる課題、さらに解く（本番形式への入口）

## 3. 応用（条件に合わせて使う）

- [ ] 判断の手順（毎回書く3点）
- [ ] 公式名を伏せた問題 5問以上（条件変更・少なくとも／含む・逆向きの問い・確率や推定への接続）
- [ ] 本番形式の5択 1問以上。**全ての誤答選択肢に「どう誤解したか」**
- [ ] 該当する章ではソフトの出力や図表の読み取り問題
- [ ] 使えない例と比べる（旧版の「よくある誤解」は全てここか復習に残す）
- [ ] 2級の範囲表にある内容の問題は、難しくても応用に置く（発展に置かない）
- [ ] 条件を変えて決まりを見つけ、式で説明する課題（ラボの steps と law）が、向いている単元にある

## 4. 転用（別の領域へ広げる）

- [ ] 同じ構造の場面の表 5場面以上（小売2つ以上、他の領域3つ以上）
- [ ] 図かラボで構造を見る課題
- [ ] 転用の問題 3問（うち仕事の場面1問）
- [ ] 転用チェック（3項目）

## 5. 発展（統計を理解する力）

統計検定の枠を外した段階。手前の延長（難しい計算・1級の知識）ではなく、考え方を変える。

- [ ] 「なぜその形か」（式・手順がその形になる理由）を1つ以上
- [ ] 「1つの数で何が消えるか」「前提が崩れると何が揺れるか」を1つ以上
- [ ] 他の単元・他の概念とのつながり（関係データ「前提・導出・対比」などと一致させる）
- [ ] `{{shared:complex_pattern}}` で説明させる場所がある
- [ ] 予想→照合（predict）の問いを置かない。問題は「説明する」形で、答えは「1つの考え方の例」
- [ ] 節に入口の型（なぜ？・本当に？・ほかでは？）を付ける（創造は「自分なら？」。docs/design.md D4）
- [ ] 単元に合う考え方の枠組み（データ解釈学・データ可視化学・数理モデル思考）を選んで使う
- [ ] 1級・大学数学の話題は、つながりとして短く触れる程度にとどめる

## 6. 創造（統計で考え、統計の外と切り分ける力）

- [ ] 要因の混ざったデータ（LAB-explore など）で、自分で問いを立てて動かす探究がある
- [ ] 統計で言えること（前提のもとの要約・推定・検定と誤差の幅）と、解釈（文脈・現場の知識・因果の見立て・価値判断）を分けて書かせる
- [ ] 「1つの考え方の例」は統計の結果と解釈を分け、筋の通った解釈を2つ以上並べる。解釈に正解を書かない
- [ ] 「成り立たない場合」を境目として扱い、そのとき何で判断するか（取り方を変える・現場の知識・費用や価値判断）まで考えさせる
- [ ] 課題 3つ以上、検証に使うラボ、ChatGPT への批評依頼文
- [ ] 振り返りの観点（任意。到達の基準にしない）に「切り分け」と「解釈」がある

## 7. ラボ（シミュレーター）

- [ ] 旧版のラボの機能を下回らない
- [ ] 共通部品（tools/labkit）を使い、`src` から build で場面ごとの版を作る
- [ ] モードを分け、段階ごとに場面の版（presets）がある：最初のモード・数値・課題カード
- [ ] 予想してから表示できる：予想が要る場面は `predict` で、予想するまで結果（.res）を隠す。予想とのずれを返す
- [ ] 間違えたときは「どこで取り違えたか」を返す（誤答ごとの説明）
- [ ] 結果の下に「式で計算」を並べる（乱数を使うものは、理論値と押すたびに揺れる値を並べる）
- [ ] 計算問題の答えに「ラボで確かめる」（問題の `lab`）があり、問題の数値が入った状態で開く
- [ ] スライダーには −／＋ ボタン。押す場所は 44px 以上
- [ ] 380px 幅・ライト／ダークで崩れない。エラーが出ない。`expect` とラボの値が一致する（tools/test_labs.js）
- [ ] 本文に書いたラボの数値は、ラボごとの check.js で検算する
