# 発見の環境への計画（2026-10-30 決定）

在り方（CLAUDE.md）：**統計を発見するための環境**。予測する・実験する・観察する・考える。中心は公開サイト（ラボと知識ネットワーク）、Notion は読む・記録する入口の1つ。
この計画は「何ができていて、何ができていないか → 今後要るもの → やること・やめること → どうデザインするか → 実装の順」を決める。決まったら #55 と各 issue をこれに合わせる。

## 2. できていないこと

1. **既存ラボの実験体験の拡充**。計画当初は、ラボの多くが「パラメータを変えて理論のグラフを見る」形だった。2026-11-01 に P6（#144）が完了し、乱数を使う14本・15か所は共通の種つき乱数へ移行済み。同じ種で結果を再現できることと、結果を積み重ねて分布を観察する学習体験の拡充は分けて扱う。
2. **発見の流れがない**。予想は1回で照合して終わる。実験→観察→考える（気づきを書く）→式で確かめる、が1つの流れになっていない。
3. **入口がない**。公開サイトのトップはラボの一覧だけ。問い・地図から入れない。
4. **ラボと地図がつながっていない**。ネットワークからラボは開けるが、ラボから「いまの発見はどの概念・関係か」へ戻れない。
5. **概念が足りない**。用語115のうち概念は17（関係26）。問題→概念は U13〜U16 だけ。115語はすべて単元に割り当て済み（45語は2単元以上）だが、地図の上には17しかなく、全体の骨格が見えない。
6. **数理の土台（math-lab）が空**。式の木（#72）・実験エンジンの置き場がない。
7. 個人記録・試用（#54・#57）は未着手（後でよい）。

## 4. やること・やめること

**やめる**
- Notion を中心にした判断。ラボの体験を埋め込み（360×320）の大きさに合わせて削らない（入口として「問いと開く」までは収める）。
- Notion への公開を段階の完了の条件にしない（完了は公開サイトとネットワークで使えること。Notion はまとめて更新）。
- 理論のグラフを見るだけの新しいラボを足すこと。新しく作るのは実験か発見の形。
- #66 の構想（React＋ECharts で数理ラボを作り直す）をそのまま進めること。先に実験エンジン（画面を持たない）を作り、画面は今の labkit と知識ネットワークの部品で作る。図は自前の SVG で足りている。
- 既存のラボを一度に作り直すこと。部品として入れ、版ごとに結果が変わらないことを確かめながら移す。

**続ける**
- 原本→build→検査の仕組み、ID 不変、検算、テストで照合する決まり。
- 概念・関係・導出を増やす作業（W1〜W5）。
- 予想（predict）・法則を見つける（steps）・解説付き再生（tour）。実験と組み合わせて使う。

**変える**
- 段階（W1〜W5）の完了の条件に「各単元に発見の問いが1つ以上（実験室で動く）」を足す。
- 完成の条件に8つ目を足す：**各単元に、自分で実験して決まりに気づく体験がある**（build で数える）。
- math-lab の順番：土台（#73）→ 式の木（#72。先でよい：渡辺さん 2026-10-30）→ 実験エンジン。式の木は骨格の概念の式（記号→概念）にも使える。

## 5. 概念の骨格（129）を先に作る（渡辺さん 2026-10-30：骨格の作成が先）

棚卸し（#105、渡辺さん 2026-10-31）：115語に、事後確率（「事前確率・事後確率」から分けた）と、単元の題にあるのに用語がなかった13語（平均・確率・加法定理・乗法定理・全確率の公式・ベルヌーイ分布・標本平均・標本比率・区間推定・仮説検定・分位点・範囲・単回帰）を足して129語。重なって見える語はまとめず関係でつなぐ。判断の原則は CLAUDE.md（概念・関係・導出）。

17から始めるが、計画としては129すべてを概念にする。先に**骨格**（全体の地図）を作り、肉付けは W1〜W5 で行う。骨格があれば、どの実験室がどの概念・関係の発見かを最初から置ける。

**骨格の段（概念の状態）**
| 状態 | 持つもの | 地図での見え方 |
| --- | --- | --- |
| 骨格（新しく足す） | 名前・英語名・単元・**定義1文**・分類（分布・統計量・手法・性質など） | 点線の枠。押すと定義1文と「まだ骨格」 |
| 説明あり（今の filled） | 原理・条件（数学／データ）・例・反例・式・誤解・出典 | 実線 |

型（knowledge-net）に状態「骨格」を足す（任意の値を足すので v1 のまま改訂を上げる）。いまの stub（関係から指されるだけ）は骨格に置き換える。

**骨格の関係**
- 前提（learning）：129語の学ぶ順をすべてつなぐ（孤立0。build が止める）。
- 構造の関係（一般化・特殊化・変換・対比・導出・統合）：主なものを骨格の段で置く。変換・対比・導出・一般化は今の決まりどおり「つまり」1文を必ず書く。図・解説・確かめるラボは肉付けの段で。
- 115語の棚卸しを先に（済み：129語）：重なる語・粒度の違う語（例：用語と手法の名前）を、まとめるか分けるかを決める（ID は変えない。まとめた語は別名で指す）。

**骨格の完了の条件（build で数える）**
1. 129語すべてが骨格か説明あり（定義1文がない語0）
2. どの概念も前提でつながる（孤立0）。全体図で W1〜W5 の単元のまとまりが見える
3. 主な構造の関係に「つまり」がある
4. 進み具合（progress.py）に「骨格」の列が増え、全単元 ✓

**大きさ**：大（129語の定義1文と分類、関係はおよそ150〜250本の見込み）。原本のデータ作り＋型の改訂（小）＋地図の見え方（小〜中）。

## 6. どうデザインするか

**発見のループ**（1つの実験室の中の流れ）

| 段 | 学習者がすること | 画面 |
| --- | --- | --- |
| 問う | 何を調べるかを知る | 上に問いを1行 |
| 予想する | 結果を先に決める（理論の値・形・向き） | 予想のカード。決めるまで結果を隠す |
| 実験する | 1回ずつ／まとめて起こす | 下に2つのボタン。動きは1つの操作に1つ |
| 観察する | 結果が積み重なるのを見る、理論と重ねる | 中央に実験の主役（並び・積み上がる分布） |
| 考える | ずれ・決まりを1文で書く | 発見メモ。「メモを送る」で記録用の文を作り ChatGPT に渡し、ChatGPT が Notion の学習記録へ書く（公開サイトは個人の記録を持たない。#102） |
| 確かめる | 式で説明する。記号を押して実験の値と照らす | 式の木（記号→意味・いまの値・概念、1段ずつ展開）。解説はシートで開く（tour・law） |
| つなぐ | いまの発見が地図のどこかを見る | 概念・関係のシートから知識ネットワークへ |

**式の木が体験の芯になる**（渡辺さん 2026-10-30：式の木は UI や体験にとても影響する）
式は「覚えるもの」ではなく「触って確かめるもの」として出す。式の木（#72）で次をできるようにし、実験室・地図・解説の画面はこれを前提に作る。
- 記号を押すと、その意味と**いまの実験の値**が出る（p＝0.3、n＝10 …）。実験の条件を変えると式の中の値も動く
- 1段ずつ展開する（E(X)＝np → 10×0.3 → 3）。どの段で何を使ったかが見える
- 記号から概念へ開く（p → 成功確率、Σ → 期待値の定義）。地図の骨格とつながる
- 実験の結果（積み上がった平均）と式の値を並べ、ずれを見る
このため式の木は実験エンジンより先に作り、実験室 v0 は最初から式の木を使う。

**段階ごとの実験の形**（CLAUDE.md の段階の定義と合わせる）
- 初学：1つの問いで 予想→実験→理論と重ねる（予想1回）。
- 応用：条件を変えて実験し、決まりを見つける（steps と law を実験で）。
- 発展：前提を崩す実験（独立でない・偏った取り方・外れ値）で、何が揺れるかを見る。予想の照合はしない。
- 創造：自分で問いと条件を決めて実験を組み、統計で言えることと解釈を分ける。

**3つの考え方との対応**
- 数理モデル思考：仮定（p・n・独立）を変えて実験し、式の予言と比べる。
- データ解釈学：取り方（標本の選び方・欠け）を変えて実験し、偏りが生まれるのを見る。
- データ可視化学：同じ実験の結果を指標と図を変えて見せ、何が見え何が消えるかを見る。

**守ること**：確率の計算と動きを分ける。種で再現できる。テストは種で照合し、回数を増やすと理論に近づくことも確かめる。手触りは tokens の決まり（押す・滑る・一度だけ光る・動きを減らす設定で止める）。

**構想と、そこへ向かう骨格**（渡辺さん 2026-10-31：構想があればそれに向かう骨格が決まる。順番に作る。#115）

構想：
- 実験室は「こういう時に使う」をテーマ（来店客の購入・検品の不良品・フリースロー・さいころ・4択・コイン）で選べ、計算は同じでも場面で覚える。
- 「この計算が使えない場面」を同じ画面で見せる（戻さずに取る→超幾何、独立でない）。統計で言えることの境目。
- 知識ネットワークの線（関係・導出）＝1つの実験。複数の概念を組み合わせる実験（ベルヌーイ＋独立→二項、二項→ポアソン・正規、標本平均＋中心極限定理→信頼区間）。
- 複数の手法を組み合わせる実験（集める→要約→推定→検定→前提を崩す）。

この構想のため、P3・P4 で最初から次の骨格で作る（中身は少なくてよい。形を後で変えない）：
1. **実験はデータで書く**：実験室の定義（問い・テーマ・条件と範囲・予想の形・観察する量・つなぐ概念と関係の id）を原本に書き、画面は定義を読むだけ。新しいテーマ・実験は定義を足すだけで増える。
2. **実験の記録は型を決める**：種・条件・1回ごとの値・集計（math-lab の engine の record）。次の手法（推定・検定）や次の概念の実験の入力にそのまま渡せる。
3. **モデルを差し替えられる**：同じ画面で「理論のモデル」と「起きている仕組み」を分ける（二項の理論 × 戻さずに取る仕組み、など）。ずれが「使えない場面」になる。
4. **実験は線につく**：実験の定義は、概念（点）か関係・導出（線）を指す。地図の線から実験室へ、実験室から線の両端の概念へ行き来できる。

## 7. 技術スタック（2026-10-30 決定・#107）

- **math-lab を土台の束にする**：計算（種つき乱数・実験エンジン・式の木。TypeScript の純粋関数、Vitest＋fast-check）と部品（手触りの値・シート・切り替え・式の木の表示・積み上がる分布。React）。
- **サイトは1つ**：knowledge-net が math-lab を使い、入口・地図・実験室を出す。新しい実験室は React。
- **そのまま**：原本と build（YAML・Markdown・Python）、図（自前の SVG）、既存のラボ33本（今の URL のまま。P6 から順に移す）。
- 式は KaTeX のまま式の木から作り、記号に押せる印を埋め込む。発見メモは ChatGPT 経由で学習記録へ（公開サイトに保存しない）。動きは CSS が基本、積み上がる動きに Motion を検討。
