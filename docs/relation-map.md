# 関係図の定義書

2026-11-06 に渡辺さんが決めた関係図の骨格（最小版。#228）の定義。**書き方・画面・移し方の現行の仕様はこの文書と、設計書（docs/relation-map-design.md）・計画書（docs/relation-map-plan.md）だけ（意味の判断は製本。下）。** 型（v2）・教材の原本・画面は、この3つを土台に作る。

- この定義書：何を表し、何を書き、何を書かないか（型 v1 での書き方）
- 設計書：それをどの型・データ・画面で持つか
- 計画書：どの順で作り、何を先に決めるか

**2026-11-08 から、関係の意味・成立条件の区分・学ぶ順の判断の正本は製本（docs/rules/ の ③⑤⑥）。** この定義書の 3〜5 は、型 v1 で書くときの書き方だけを持ち、意味の判断は製本を指す（#261 で寄せた）。v1 の種類へは docs/rules/migration.md の対応表で写す。

設計文書「関係図の骨格：設計案の比較と評価」と、#228 の 11-05 の案は、検討の履歴として残している。そこに出てくる「全体ともの」「所有」「穴」「種類の木を中心にした骨格」は取り下げたので、実装では参照しない。

## 1. 何のためのものか

関係図は、概念どうしの関係を見せる地図。答える問いは次の4つ。

| 問い | 答えるもの |
| --- | --- |
| 何の仲間か | まとまり（はっきりしていれば種類も） |
| 何でできているか | 定義に使う概念（型の名前は材料） |
| いつ成り立つか | 成立条件（要件・仮定・目安。線にしない） |
| 何とどう違うか、どう移るか | 対比・変換・一般化・導出の線（意味は製本 ⑤） |

次のものは説明しない。

- 前提知識（学ぶ順）。製本 ⑥ で別に作る（#259 の M6）。
- 計算の手順。作業台と問題集で扱う。
- 統計の外の解釈。創造の問いで扱う。
- 実験の操作。実験室で扱う。
- その概念に関わることの全部。概念のページで扱う。

関係図は辞書を作るためのものではない。

## 2. 概念が持つもの

| 欄 | 中身 | 必須か |
| --- | --- | --- |
| 名前・定義1文 | 今の `name`・`short`（説明ありの概念は `definition` も） | 必須 |
| 分類 | 今の `category`（12種） | 必須 |
| まとまり | 分類の中の、教材が宣言した一覧から1つ | 必須 |
| 成立条件 | 今の `conditions`。行ごとに要件・仮定・目安（5 の後の「成立条件」） | あれば |

概念の型（全体ともの、性質・現象など）・所有・穴・分類ごとの軸は持たない。

### まとまり

- **意味：** 同じ分類の中で、いっしょに見ると分かりやすい概念の組。何の仲間かに答える。
- **書き方：** 分類ごとに教材がまとまりの一覧（名前と1文）を宣言し、概念はそのどれか1つに属する。
- **書かないこと：** まとまりは関係ではない。同じまとまりにいても、一方が他方の一種や部品になるわけではない。
- **目安：** 1つのまとまりに、2〜6個。

## 3. 関係（型 v1 での書き方）

**関係の意味・端・判定の順の正本は製本 ⑤（docs/rules/relations.md）。** ここには、⑤ で決めた関係を型 v1 の種類で書くときの書き方だけを置く。v1 の種類と ⑤ の種類の対応、移すまでの暫定の運用は docs/rules/migration.md 2 の対応表。どの関係を学ぶ人に見せるか（取り違えやすい組か、など）は製本 ⑦ 4。

| v1 の種類 | 読み方（□ に from、■ に to） | 書くもの |
| --- | --- | --- |
| 種類 | □ は ■ の一種 | 親は1つまで（⑤ の一種） |
| 材料 | □ は ■ の定義に使われる（画面の呼び名は「定義に使う概念」） | 直接の構成要素だけ（⑤ の定める）。材料の材料は画面がたどる |
| 対比 | □ と ■ を比べる | `axis`（比べる軸）と違いの1文（⑤ の比べる） |
| 一般化 | □ を一般化すると ■ | ⑤ の特別な場合。固定の仕方は `gist` に書く |
| 変換 | □ を変換すると ■ | ⑤ の移る。`mode`（厳密・近似・極限）と成立条件。通す操作は `gist` に書く |
| 導出 | □ から ■ が導ける | ⑤ の導ける（4 の帰結の「導けるの前提」を満たすものだけ） |
| 応用 | □ を ■ に使う | 新しく書かない（⑤ で廃止。migration.md 2） |

- 線の向きと画面の呼び名（材料は「使われる概念 → それを使う概念」、見出しは「定義に使う概念」「これを定義に使う概念」。#249 ④）は、画面の決まりとして knowledge-net の docs/decisions.md（関係のタブの見出し）に置く。型の種類の名前（材料）は v2 まで変えない。
- 基準にする定義（確率分布は確率関数・確率密度の式。`basis_formula`）は製本 ①、定義の依存の輪は build が止める。

## 4. 前提知識と成立条件（型 v1 での書き方）

- **前提知識**：学ぶ順の判断の正本は製本 ⑥。関係図の線にしない。移すまで（#259 の M6）は、教材の原本に今の「前提（learning）」として書く（理由の1文を添える）。直接の1段だけを書き、たどれば着く前提知識を重ねて書くと build が止める（#249 ③）。
- **成立条件**：区分（要件・仮定・目安）の意味と掛かる先の判断の正本は製本 ③。線にせず、概念・関係の `conditions` に添え、行ごとに区分と外れたときの説明を書く（書き方は docs/authoring.md）。文に出る概念は、画面が文の下に押せる札で並べる。現実のデータで確かめる手掛かり（`conditions.data` の区分のない行）は「データで確かめる手掛かり」として別に出す（判断は製本 ⑧ の 2）。
- **主張に使う概念**（#249 ②）は、製本 ④ の主張の単位に置き換わった。型に足すのは #262（M2）。

## 5. 規則

関係を書くときの規則の正本は製本 ⑤ の 8（関係の相手が教材にないときは書かない・関係のために概念を足さない・例外の規則を足さない）と、⑤ の定める（名前が定義に出ることは必要条件で十分条件ではない）。

## 6. 概念を足すとき・分けるとき

判断の基準の正本は製本 ①（同一性）と ⑤ の 8 の規則2。ここには、関係図を作るときに決めたことを記録として残す。

| 概念 | 決定 | 理由 |
| --- | --- | --- |
| 分散 | 「確率変数の分散」と「データの分散」に分ける | 対象が違う（確率分布／観測したデータ）。今の定義は確率変数の分散だが、REL-dev-var の説明「偏差の2乗の平均」はデータの分散を指していて、食い違っている。標本分散と不偏分散にさらに分けるかは別に決める |
| 回帰式 | 足す | 最小二乗法・回帰係数・残差・決定係数・外挿の5個が、定義の中で回帰式を名前で使っている。材料になるかは概念ごとに製本 ⑤ の定めるで分ける |
| 離散分布・連続分布・カイ二乗検定 | 足さない | 階層を整えるためだけの概念になる |

## 7. 画面が作るもの（データに書かない）

- **木：** 柱 → 分類 → まとまり →（あれば種類）の順で出す。データの形は木でなくてよい。
- **共通の印：** まとまりの全部の概念に共通する材料・成立条件の概念は、まとまりの見出しに1つだけ印で出し、概念からは外す。表示の要約で、まとまりの材料・条件としてデータに書かない（まとまりは概念ではない）。
- **たたむ：** 使う概念がみな同じまとまりにある材料は、そのまとまりの中にたたむ（期待度数など）。
  - これは表示だけの決まりで、データに所有の関係を作らない。
  - 画面には「このまとまりの中で使われる概念」として収める。ほかの概念と一体のものや、その部品には見せない。
- **受け継ぎ：** 種類の親の材料を、子にも出す。
- **掘り下げ：** 材料の材料を、その場で1段ずつたどる。
- **線の強さ：** 確率のような基礎の概念へ多くの線が集まるときは、その線を薄くする。

## 8. 関係図の外で担うもの

仮説検定の構成（帰無仮説・検定統計量・有意水準がそれぞれ何の役をするか）は、関係図のデータでは示さない。部品の概念はまとまりの中に並ぶので、仲間としては見える。役割は、実験室と作業台が体験の中で説明する。
