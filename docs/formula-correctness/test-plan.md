# テスト計画：代表の式とわざと入れた誤り（#118）

README の 0「テストの有効性と最小十分性」に従う。各テストに **検証対象・想定する故障・検出方法・既存テストとの差分・リスク（起きやすさ×影響）** を書き、既存のテストで見つかる故障には新しく足さない（「既存で足りる」）。
リスクは 高・中・低 の組（起きやすさ×影響）。影響の「高」は、学習者に誤った数・誤った意味を見せること。
既存のテストの名前は math-lab packages/engine/test/ のファイル名と `it` の名前（inventory.md の 1）。

## 4. 既存のテストの統合・削除の候補（消すのは統合の段で決める）

同じ故障を見つけるテストが重なっているもの。今は消さない。

| 候補 | 重なる相手 | 理由 | 案 |
| --- | --- | --- | --- |
| open.test.ts「教材の35式で、概念を指す記号のうち開けるものはすべて開け、TeX にできる」 | correctness.test.ts「教材の式で開けるものをすべて開き…」 | どちらも教材の式の開ける組を全部開いて toTex を通す。後者は所属も見る | 統合（後者に TeX の確かめを残し、前者を消す）。名前の「35式」も今は38式 |
| parts.test.ts「分布：k を 0〜n で動かした値の和は1」 | correctness.test.ts「二項分布：Σ P(X＝k)＝1…」 | 同じ式の正規化。前者は `distribution` 経由だが、故障（式の誤り）は同じ | `distribution` の端（lo・hi）の扱いだけを確かめる形に置き換える |
| formula.test.ts「代表の式の形」（7式の TeX を手書きの文字列と比べる） | C2（tree と tex の一致）・C3 | #72 で原本の tex を木から作るようになると、手書きの文字列との比べは表示の好み（\dfrac など）の固定だけになる | #72 のあとに置き換え（表示の決まりのテストとして数を絞る） |
| viewer.spec.ts「V(aX+b) を開くと中の μ は E(aX+b) になり…」 | open.test.ts「引数が式のとき…」 | 数学の中身は engine のテストで見ている。e2e は画面が engine の結果を出すかだけを見ればよい | e2e は1つの開く操作の表示に絞る（中身の確かめは engine に任せる） |

## 5. 見本（オラクル）の流れ

1. 統合の 3 で、research/oracle/ の試作を build の一部（例 build/oracle.py）に移し、out/ に見本を書き出す。
2. math-lab の test/fixtures/ に写す（C5 の hash 付き）。math-lab のテストは見本を読むだけで、計算は engine で行い、見本の誤差の決まり（exact・derived・sum）で照らす。
3. 2026-10-31 の時点で、試作の見本 85 個（二項の確率・平均・分散、値の表の平均、z）を engine の今の値と照らし、最大の差 4.4×10⁻¹⁶ で一致することを使い捨ての調べで確かめた（コミットしていない）。
